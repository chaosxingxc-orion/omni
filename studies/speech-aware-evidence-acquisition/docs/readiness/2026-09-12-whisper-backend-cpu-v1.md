# Local Whisper CPU backend readiness

Status: implementation and fake-only tests complete; no CPU speech forward or runtime tool contact has been made.

`LocalWhisperBackend` now accepts `device: "cpu"` only when `fp16: false`. Existing `cuda` and explicit `cuda:<index>` protocols retain their prior validation, checkpoint loading, tensor movement and decoding behavior. Construction still validates configuration and creates the bounded audio-prefetch object only. It does not import Whisper, load the checkpoint, read audio or execute a forward. The first decode remains the point at which `_ensure_stack` loads the exact local checkpoint.

The runtime inventory is device-neutral. `verify_whisper_inventory` validates the existing `saea-local-whisper-runtime-inventory-v1` checkpoint, official source files and package versions, then projects the same `saea-local-whisper-backend-inventory-v1` fields for either device. Do not rewrite a historical CUDA inventory. A future CPU tool registration must pin a new protocol and ExecutionPlan whose decoding object retains the existing schema and fixed English transcription settings while setting `device` to `cpu` and `fp16` to false. Its protocol hash, contact and audio ceilings, attempt identity and exposure row must be new. The checkpoint and repaired official-source inventory may be reused by exact hash.

For one model-selected full-utterance action, resolve and verify only that sample source after the action has passed the shared action and lineage checks. Then call `backend.prepare_sources([source])`, followed by `backend(source)`, and finally `backend.close()`. The source mapping remains the existing exact contract: `media_path`, `audio_sha256`, `verified_fingerprint`, `source_frames`, `source_sample_rate_hz`, `start_frame` and `end_frame`. Backend v1 requires `start_frame == 0`, `end_frame == source_frames` and at most 30 seconds. This sequence performs no roster prefetch and makes audio preparation occur after model selection. The live tool custodian must debit the separately registered speech-tool contact and duration before this sequence; that action-loop accounting is outside this backend change.

A long-lived provider cannot repeatedly call the current `prepare_sources` method one row at a time because `BoundedAudioPrefetch` owns one iterator and thread pool per preparation call. Root must choose the action-loop lifecycle or a later bounded queue design. This change does not introduce either provider design.

Focused validation uses fake Whisper, tensors, audio and prefetch only. It proves CPU rejection with `fp16: true` occurs before prefetch construction, CPU checkpoint/device and tensor routing use `cpu`, decoding receives `fp16: false`, construction remains free of model/audio work, and both historical CUDA spellings remain accepted. A separately registered real CPU forward with the host-memory guard is still required before operational readiness can be claimed.
