# Optional process memory diagnostics (2026-10-07)

This diagnostic extension is offline engineering preparation. It neither authorizes a retry nor changes the original natural4 resource-stop disposition. The frozen natural4 worker remains at `3f3c30af26ad70086970876656ac5a36e1268cc4`.

Opt in through the existing batch queue key `process_memory_diagnostics: true`, forwarded as `--memory-diagnostics` to the existing process guard. Existing queues without that key retain their command and receipt fields. No experiment configuration, runtime policy, model request, Windows observer, process ownership, sampling interval or floor is changed.

The collector reads only ten named `/proc/meminfo` categories, and RSS/PSS/Swap from the owned worker and registered resident server's `smaps_rollup`. PID and `/proc/stat` starttime bind each observed process; a second identity check surrounds the memory read. Missing, malformed, oversized, disappeared or reused process records report an error or null field, never a zero memory reading. Each read is capped at 64 KiB, or 4 KiB for process identity; one daemon collector can remain pending. The guard never waits for diagnostics. Scheduling and snapshot errors are recorded separately and cannot decide admission or stopping. Timing, pending and age fields distinguish older diagnostic samples. No credentials, process command lines, task content, subprocess or GPU queries enter collection. Use wall-clock timestamps to join the existing serving telemetry.
