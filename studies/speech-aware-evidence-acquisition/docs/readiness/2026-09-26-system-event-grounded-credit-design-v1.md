# Event-grounded whole-system semantic credit: prospective design

## Question and named deficit

Determine whether mechanically verified system events help a frozen semantic
learner derive faithful conditional guidance from the same complete trajectories
and official terminal feedback. The first batch showed fabricated tool credit,
loss of initial-versus-revised answer order, and confusion between entity counts
and intent accuracy. These are learning-input deficits; operation JSON validity
is a separate interface question.

This document records a design, not an ExecutionPlan or model-contact authority.
Complete the registered bounded synthesis baseline first. Keep its raw proposals
and candidate or rejection unchanged. Do not reopen closed candidate/delta,
VAR-2, F10 or evidence-path flights.

## Minimal matched intervention

Reuse all four actors per source input, the existing generated summaries, the
same numeric terminal feedback, eligibility rule, frozen model and decoding.
Do not resample actors or regenerate summaries to improve the comparator.
The comparison source gets one explicit, versioned event-evidence option.

Alongside each unchanged summary, supply a deterministic view derived from its
verified original episode:

- Ordered model contacts: role, visit, interruption state, exact response text.
- Tool schemas actually advertised on each original request, and actual tool
  events/results in their recorded order. A role's tool claim remains model text.
  Zero events is an explicit fact, not an inferred failed validation.
- Recorded Planner routes, terminal disposition, delivery transformation and
  delivered answer, with their original bindings.
- Explicit metric definitions: entity TP/FP/FN describe the delivered answer's
  official word/character comparison; intent_exact and format_ok are separate
  terminal channels. They do not grade an intermediate response or a tool.

Use chronological source events rather than root-authored interpretations.
Retain every contact and actual tool result; do not select only a bad revision.
Keep full requests addressable in sealed actors. The event view is a deliberate
projection, not a claim to preserve every knowledge/prompt byte in model context.
Do not include reference task answers, transcripts, intermediate gold judgments,
new performance labels or desired corrective lessons.

Version source schema and implementation custody. The legacy source reconstructs
exactly its old semantic document. The new source must bind the added evidence
to the same episode hashes and original candidate labels before preparation.
An unknown mode, altered event, missing actor or crossed option binding fails
before contact. Real fit measures the actual combined comparison request.

## Interpretation and downstream sequence

1. Measure comparison fidelity on the complete registered source population.
   Inspect whether emitted lessons cite nonexistent events, reverse decision
   chronology, confuse feedback channels, or claim isolated causal effects.
   Preserve all raw responses. Four inputs and one informative group are only
   a construction diagnostic, not an effectiveness or generalization sample.
2. Use the same source-bound operation contract and bounded batch synthesis for
   both branches. No root repair, hand-selected lesson deletion, or silent
   candidate truncation. Record empty and invalid update dispositions.
3. Attest each provisional frozen candidate through the shared memory path.
   Correct actor tool/prompt capability consistently in learned and empty-memory
   policies. This common engineering repair is never counted as an RL gain.
4. Reexecute complete episodes on the next disjoint TRAIN construction batch.
   Freeze memory/prefix per batch; apply feedback-driven updates only after
   all trajectories and official complete-manifest scores have finalized.
5. Evaluate complete terminal task outcomes on the registered B1080 roster,
   with matched empty-memory/fixed-policy controls and same-roster replication.
   Require official pooled SLU-F1 and intent protection, natural/equal-stratum
   views, error decomposition, actual acquisition, repairs/harms and costs.

Faithful credit is necessary but not sufficient for useful learning. A plausible
summary or valid memory cannot replace complete-system reexecution. A branch
that only improves a local artifact has not established an RL benefit.

## Resource and method boundaries

Retain four construction inputs, four whole-system trajectories per input and
two actor slots. Semantic stages reuse one 49152-token decoder-only slot.
Use precomputed speech features and no-mmproj; no extra ASR/encoder is needed.
Reserve the full declared output allowance and at least 3072 remaining tokens.
Keep Windows/GPU guard thresholds and independent background execution.

Keep the frozen-F0 utility and separate intent/format feedback unchanged.
Do not reinterpret terminal entity utility as a calibrated success probability
or a total ordering of intent quality. Any alternative reward or admission
tradeoff requires its own prospective comparison.

The implementation is a versioned adaptation of the pinned TF-GRPO learning
chain. Event-grounded credit is an experimental optimization candidate, not a
claim of a novel algorithm, a complete upstream reproduction or stable task gain.
