## Decision responsibilities

| Node | Responsibility | Model-selected analytical actions | Output authority |
|---|---|---|---|
| Perception / candidate source | Consume scoped intent knowledge and lawful speech to represent plausible labels and evidence gaps | None | Hypotheses and gaps only |
| Reviewer | Identify a concrete inconsistency, uncertain span, missing evidence or unsupported inference; perform bounded permitted checks | Allowed within an explicit analytical tool allowlist and allocated budget | Assessment, flags and evidence only |
| Planner | Choose continuation, knowledge views, requested speech checks, and the next bounded node | Allowed; coordinate shared action execution and budget | Plan and action requests only |
| Solver / joint decision | Consume the candidate set, appropriate intent/slot knowledge and acquired evidence, then jointly select label and slots | None in this role-bound design | Final task answer |

Every node is executed through the same frozen core boundary and shared controller/OpenJiuwen path. Role names do not imply separate answering models. Reviewer cannot overwrite a final answer; Planner cannot submit its plan as the task answer.

An analytical action acquires or evaluates additional evidence, such as ASR, selected-span re-listening, alignment, or a schema check. Loading a previously prepared, source-bound knowledge view is information supply, not permission to execute any external tool. Perception and Solver may report which knowledge or evidence is missing; Planner may route that request. Do not force every sample through every analytical tool.

Reviewer may directly use a narrow, pre-authorized read-only check within the Planner's episode budget; an expensive or different-scope action returns to Planner. The common dispatcher enforces this allocation so the same proposed check is not executed by both roles. This is a control rule, not a new claim that current model confidence is calibrated.

## Construction and consumption

Build persistent intent and slot knowledge from separately registered construction material. Intent values explain activation, exclusion and neighboring-label distinctions. Slot values explain semantic role, extraction/boundary, presence, normalization, and intent binding. Both retain source support and limitations; absent TRAIN support is not prohibition, and frequent fields are not mandatory.

Keep long-term construction separate from runtime perception. Current hypotheses, spans, checks and revisions belong to per-episode state. Promote a stable rule from experience only through an explicitly validated successor knowledge release; do not write evaluation answers or raw trajectories directly into either store.

## Engineering consequence

Current named-store routing supports distinct released sources, but the legacy native controller has no typed actor role and can treat any non-tool nonfinal response as final. A role word in a prompt therefore cannot establish the new authority boundary.

Add opt-in typed phase roles to the shared phase program. Preserve unannotated program serialization and behavior. In annotated programs, expose and dispatch analytical tools only for Reviewer/Planner, keep other nodes tool-free, carry nonterminal assessment/plan text forward, and reserve final delivery for the final Solver phase. Permit explicit per-phase tool/store allowlists and use the same request builder for actual execution and capacity accounting. Test actual shared execution, not only parsed declarations.

The pending matched candidate-commitment component adds no analytical-tool mechanism: it compares hard-first versus later joint selection from one derived source. Close that comparison before a separately registered native role-bound knowledge/tool experiment. Preserve the distinction between component evidence and complete-system performance.
