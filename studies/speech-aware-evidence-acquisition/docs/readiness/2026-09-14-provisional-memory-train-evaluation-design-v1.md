# Provisional memory evaluation on disjoint TRAIN: root design

Status: implement the missing shared evaluation boundary; do not admit a GPU
flight, select a scientific incumbent or claim optimization. The active SLURP
pair remains frozen. Root makes the pack, role and comparison decisions after
the current system analysis. Do not expand the task into a second framework.

## Evaluation object and boundaries

Evaluate a frozen, explicitly selected ordered pack of provisional procedural
guidance through the existing native episode and corrective-memory tool.
The source is the verified TRAIN proposal/materialization chain. Construction
and evaluation rosters must be distinct, sample-disjoint SLURP TRAIN cohorts.
Membership disjointness is not a claim of speaker disjointness.

Keep ExperienceMemoryCatalog admitted-only. Use an evaluation-specific provider
that shares Applicability matching, structural condition projection and
ExperienceMemorySelection. Do not change record status, fabricate admission,
implement semantic relevance implicitly, or truncate by record-ID order.
The protocol chooses a compact ordered pack; source verification proves the
choice exists in the artifact, not that the choice is good.

The compact pack cannot exceed the existing maximum runtime record bound.
Return all applicable pack records in the declared pack order. Refuse an
oversized pack rather than drop rules. An explicitly empty pack is representable
and supplies no guidance; it does not force a memory call. Actual tool use
remains chosen by Reviewer or Planner. Perception and Solver do not gain
analytical-tool authority.

## Model-free source attestation

Reuse prepare_artifact and the source-bound provisional materializer in an
offline preparation function. Reconstruct the materialization authority from
its pinned configuration and require the resulting artifact identity to match
the requested candidate artifact. Produce an immutable source attestation
binding the candidate file/output hashes, materialization config, construction
roster and record correspondences with implementation identity.

Runtime reads only the pinned provisional artifact, compact source attestation,
construction/evaluation roster metadata and evaluation decision. It must never
reopen archived task responses, TRAIN rewards or official score files. Do not
invoke materialization or feedback reconstruction inside the answering runtime.
Preserve all original proposal, materialization and score bytes.

## Explicit runtime declaration

Add candidate_experience_memory as an opt-in shared runtime binding. It is
mutually exclusive with experience_memory and pins:

- The provisional artifact and its independently prepared source attestation.
- The construction roster and exact disjoint TRAIN evaluation roster.
- The explicitly selected ordered record hashes.
- Task/component scope and allowed analytical-tool roles.
- An evaluation-only decision that binds those identities plus the actual
  intended run and attempt.

Avoid a self-hash cycle: the evaluation decision need not contain the composed
runtime protocol hash of a configuration that itself includes that decision.
The later ExecutionPlan/protocol registration binds the complete composed
configuration. Validate actual plan profile, split, carrier, run/attempt and
roster membership once they are available and before any model or tool contact.
Require bounded-discovery-probe, discovery split role, task answers and a native
role episode. Reject DEV/test/confirmatory IDs, source/evaluation overlap,
partial or foreign active rosters and any artifact/admitted-memory ambiguity.

Every bound record must parse through ExperienceRecord, stay provisional, use
canonical reward-link references and belong to the pinned construction cohort.
Validate all pins and actual source correspondence from the source attestation.
A correctly rehashed unrelated artifact or decision must still be refused.

The existing realized-contact request fit must see exactly the tool-result

## Post-seal evidence and later admission

Before real candidate evaluation, add a model-free evaluation-source verifier
over the verified complete bundle, pinned evaluation binding and roster.
Verify native call authority, provisional artifact/record lineage and the
declared selection. Distinguish tool availability, actual call, applicable
selection and subsequent model exposure; none alone proves beneficial use.
This source receipt is not a score or admission verdict.

Official scoring runs once on the complete manifest. A separate registered
comparison/decision must bind the source receipt and full score evidence.
Only a favorable actual decision may create new admitted records, source proof,
manifest and admission receipt. Do not mutate the provisional artifact or
reuse proposal-provenance validation as evaluation evidence.

## Required proof before contact

Use synthetic sources and in-process native transports to demonstrate:
a real source attestation and loader, exact disjoint TRAIN plan binding,
Reviewer/Planner tool call with all selected structural matches in pack order,
identical fit/send history, source lineage in the sealed trace, absent-binding
legacy parity, and rejection before contact for changed/overlapping/partial
sources or unauthorized roles. The admitted catalog must continue rejecting the

Implement the provider, source attestation, runtime wiring and focused proof
first. The post-seal source verifier and admission writer are subsequent shared
pieces, and remain mandatory before those respective stages may run. This
increment is not a complete training-free RL cycle.


## Root post-seal reuse and behavior distinction

The source review located an existing whole-episode join:
analysis.native_episode_diagnostics.analyze_verified_native_episode_statistics
already verifies phase/receipt/request/response/USE correspondence and Solver
terminal delivery. Reuse it for the candidate evaluator rather than rebuilding
those joins. The remaining common increment is native tool-result exposure
analysis; the candidate-specific increment verifies the actual artifact,
attestation, decision, selected records and exact registered source configuration.

Bind every result to its source request and tool-call ID. Check actual source
authority against verified trace custody, and compare a later request's returned
document to that same result. Keep retries distinct. Reject a false or altered
history claim, wrong role/source, and a future result claimed by an earlier
contact. Report only source identities and counts in the compact source receipt.

Do not make tool use a prerequisite for source integrity. A finalized episode
may legitimately have no memory call, an empty selection or no observed exposure.
These are behavioral outcomes, including possible negative efficacy evidence.
A successful selection without later exposure is not automatically an invalid
evaluation. Admission and quality analysis must not relabel availability,
invocation, exposure or lexical overlap as beneficial causal use.

Native local and inherited histories differ. The local framework validator
proves the executing role's exact ReAct assistant/tool sequence. Later roles can
carry the same result through the existing inherited native-history renderer.
Verify that route through the same pure projection if it is included in the
reported exposure counts. Otherwise label local exposure as a lower bound and
inherited exposure as unverified; never equate unverified with absent.
Do not instantiate a fake live model transport during offline verification.

The next shared analyzer is being implemented separately from the candidate
provider. It adds no model contact, changes no active flight, and cannot by
itself admit a memory pack. Compact pack construction, complete source/scoring
comparison, admission writing and a real frozen evaluation remain open.
