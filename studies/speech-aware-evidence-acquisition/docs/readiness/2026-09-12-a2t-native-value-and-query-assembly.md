reference extracted parameters rather than enforcing the public registry as

## Couple key construction and value consumption

Use one positive content key per exact registered tool. Build its English text
from the humanized tool name, supported choose semantics, public role guidance
and native role guidance. Preserve all 152 tools, including schema-only tools.

Keep avoid semantics out of the positive dense key: matching text that says
not to use a tool is not positive support for that tool. Supply these distinctions
in the associated value alongside the full public/native parameter guidance,
applicability limits, constraints and source scope. A dense positive key does
not reproduce the historical BM25 router's separately negative Avoid channel.

Freeze shared KnowledgeSnapshot, KeyFacet and ValueBundle artifacts. Match the
historical Nemotron passage prompt for keys with its query prompt plus speech
for queries. Keep both sides in the pinned 2,048-dimensional normalized vector
space. Precomputed speech segments preserve the entire source, including long
recordings; max-over-segment recall does not identify which instruction remains
chronologically active. Current-turn interpretation still belongs to the
shared observation/state/controller path and the frozen answering core.
