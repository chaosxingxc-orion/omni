# Guarded complete-family campaign with existing CPU score overlap

The existing process guard now accepts `--mode campaign --campaign-plan <committed-repo-plan>` through the existing strict `load_campaign_plan` parser. It refuses a simultaneous experiment or external worker token, outside-root plans, unready or mode-ineligible cells and dirty source. Its receipt binds the plan raw hash, ordered experiment/cell/run/attempt identities, frozen Git head and registered service session. Existing Windows sampling, freshness, floors, intervals, diagnostics, owned descendant teardown and leased-worker/node-panel paths are unchanged.

The batch driver forwards an ordinary registered campaign plan to one guarded campaign and refuses a separate smoke. Its final inspection uses the existing sealed inspector for every configured member, not an outer representative. Each member gets its configured row count, native contact ceiling and active role tool authority; a globally stricter no-tool constraint remains enforced. Actual frozen N100 ceilings are 13/13/2/3 contacts per row and no-tool flags 0/0/1/0, derived from policy rather than labels. A later member failure is propagated after all members are inspected.

No new scheduling implementation is introduced. Existing `run_campaign` and `FlightQueue` generate one member at a time, with queue depth four within that member and one CPU score pool overlapping the next generation. After refreshing score futures, a completed failed official score blocks admission of another pending member. An already admitted generation settles; completed/sealed evidence and owned scoring work are preserved. No scorer-thread abort, automatic retry or policy update is introduced.

Validation uses fake transports and operational boundaries only: 50 batch/inspector/campaign-plan cases passed in 55.83 seconds; affected guard CLI cases passed 9 in 5.32 seconds and leased-worker/node-panel cases passed 16 in 5.12 seconds. The complete affected queue suite passed 13 in 5.74 seconds; strengthened single-scorer overlap plus immediate/delayed failure cases passed 3 in 5.36 seconds. Final all-member authority/global-no-tool inspection cases passed 5 in 4.69 seconds. New guard and driver cases failed on the missing forwarding paths before implementation; immediate and delayed score-failure cases failed on the prior admission gap before the fix.

The patch changes `process_guard.py`, `queue.py`, `batch_driver.sh` and `batch_inspect.py`. It changes none of the five phase-supply fingerprint files: `core/flight/runtime.py`, `rails/kb_policy.py`, `rails/knowledge_provider.py`, `rails/knowledge_stores.py`, `rails/phase_supply.py`. No role/policy, input, output, request, scorer definition or measurement profile is changed. Root can freeze capacity first and integrate this patch for the later generation worker, with exact current-source/config/registration checks retained.

Root launch inputs remain prospective: use the actual finalized repository campaign plan, 4 GiB startup/running floors, the registered resident session and root-authored queue. Optional diagnostics are forwarded unchanged. No process guard or batch driver was invoked operationally during this preparation, and no service, STOP, lease, cache, queue or scientific output was changed.
