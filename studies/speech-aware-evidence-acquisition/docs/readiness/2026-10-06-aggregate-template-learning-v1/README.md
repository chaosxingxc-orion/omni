# Aggregate template learning records

Apply the [owner instruction](../../receipts/owner/2026-10-06-aggregate-template-learning-records.json) prospectively.
A learning record represents one complete template system evaluated in one registered round.
Derive K from the immutable candidate order. Keep exactly K records per observed population;
retain N times K records for N complete populations in the validated lineage. Retain rejected
and unchanged candidates. Keep original evaluated-iteration labels; never manufacture missing
history. The present lineage contains evaluated rounds 2 and 3, not an invented round 1.

Each record carries the full editable node templates and assembly, policy/cohort/roster identity,
official business quality and reliable completion, aggregate terminal counts and utility,
node structural/cost statistics, and aggregate support/review/revision/postprocessing statistics.
Do not export anonymous per-input episodes or node visits. Do not export task text, knowledge,
source lists, answers or per-case summaries. Aggregate deterministically without model calls.

Keep control/A/A statistics once in shared comparison metadata and reference them from candidate
records. Controls do not create extra candidate learning records. Never pool cohorts or compare
standardized relative returns across them. Preserve rejected-population selection statistics.
Node means and standard deviations describe dependent visits; they are not causal credit or
independent quality estimates. Process rates retain numerator, denominator, eligible/unknown,
Wilson interval and missingness bounds. Null process data means unavailable historical measurement.
The overall process summary enters learning; the full stratum tables, paired observations and
source custody remain in the root audit. Historical private evidence and cumulative exposure
are not deleted by reducing the learning view.
