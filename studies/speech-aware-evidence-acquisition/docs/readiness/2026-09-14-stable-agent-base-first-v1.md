## What the base must demonstrate

### Complete agent behavior

Use the existing shared controller and OpenJiuwen executor for both direct and
system arms. The system must complete actual Perception, Solver, Reviewer and
Planner behavior within registered bounds. Reviewer/Planner tool use remains
on demand. Solver owns the answer. Precomputed speech packets remain an input
optimization; auxiliary ASR remains a selected tool action, not fixed preprocessing.

Verify that requested evidence is returned, associated with its source and made
available to the intended subsequent node. Distinguish availability from semantic
use or benefit. Preserve rejected actions, failure feedback, finite exhaustion,
abstentions and all incurred contacts in full-cohort results.

### Reproducible task benefit

Use full, matched direct-versus-system comparisons and the inherited same-roster
replication rule. A single favorable DEV comparison or a different-policy TRAIN
trajectory is insufficient to establish stable benefit. Reuse the already
registered roster and serving configuration where scientifically compatible;
do not draw new samples to replace an unfavorable result.

Report the native full-task metric, natural-mixture and equal-stratum results,
paired uncertainty and the inherited protection outcomes. Keep the system
version and the complete experimental identity explicit in every comparison.
A new tool-enhanced system must not inherit an older system's benefit verdict.

Root will choose the minimum necessary base comparison only after the current
complete source and its sole full score release. If an already sealed compatible
replication exists, verify and reuse it. If it is only a plan or a different
system, record that gap and prepare the needed matched comparison. Do not run
a component grid merely to establish the base.

### Observable room for improvement

Provide a traceable workspace in which the system can acquire knowledge, request
an analytical speech tool, revise candidates, request Solver revision and stop,
where those actions are actually exposed by the configured graph. Record the
legal scope, triggering context, result visibility and delivered-answer outcome.

Use complete released traces to identify where errors remain and whether actions
are exercised. For SLURP, retain the separate questions of candidate coverage,
selection conditional on coverage, and slot grounding. The existing TRAIN anchor
has 143 gold-missing cases, 95 covered-but-wrong intent cases, 525 correct-intent
cases with nonexact slots and 317 fully correct cases out of 1080. These are
baseline diagnostics, not an attribution of tool effects or a learned policy.

Do not require every tool or component to improve independently before accepting
a useful base. A trace showing both helpful and harmful transitions can identify
a later optimization opportunity; it does not itself define a causal advantage
or validate an algorithm. Do not add capabilities merely to enlarge an action list.
