# System-text search operator runbook

Use the existing shared flight lifecycle. These commands do not launch models,
score, clear STOP, retry, grant result access or release held work. Run them from
the serially integrated, frozen source version in Ubuntu-24.04 with the pinned
speechrl environment. Keep large policies, responses and trajectories under the
data root; never commit them to Git.

## Initial feedback and each update

Import the prepared seed with `import-seed --bundle <data-root seed-policy.json>`
and an archive outside Git. For the current CONTROL-V2 seed, import the original
seed first and the corrected seed second: the importer verifies its recorded
parent chain and refuses dropped cumulative exposure. Use the corrected seed ID
from `protocol-control-v2.json`, not an older seed or a scientific winner.
See [runtime views and seed ancestry](runtime-views-v1.md) for the exact files.

Register the complete family and exact member-to-run bindings before generation.
A family specification has exactly `family_id`, `expected_members`, `bindings`,
`initial_reference_member`, `reference_family` and `read_registration`. The last
field is a repository-relative `{relpath, sha256}` pin to that family's analysis
recipe. Its exact READ row must be uniquely registered and root countersigned
before any score or earlier feedback source is opened. Initial feedback references
the initial seed; later feedback points to that original family rather than
re-estimating F_ref. Use the shared reward-source binding schema for each member.
The reader revalidates every attempt, seal and unique complete official score
before opening outcomes. Countersign the family-specific READ record first.
The initial recipe's `initial_members` must match the complete run mapping;
future recipes declare `family_id` and `expected_members`. The CLI reuses the
standard flight-registration ledger parser and signature predicate. It records
the recipe pin and READ-row hash in feedback and refuses an authority change
during export. This check never creates a countersignature or substitutes for
finalization, verified seals and exactly one successful complete official score.

Use `feedback --family <spec> --output <new-feedback-file>` only after that read
gate. It retains every registered row, terminal disposition, official counts,
costs and trace pins. Cached feedback JSON alone is not read authority.

Use `proposal-input` with branch, round, slot, seed/parent identities, pinned
protocol, model version and a fresh session identity. L additionally supplies
the complete preceding family and its explicit learning-member list. Its view
is projected after whole-family qualification and relative returns are
recomputed without B. Earlier L inputs, failed responses and dispositions have
hash-bound indexes. B rejects feedback/complementary arguments before opening
them, and its parent must always be the original seed.

Invoke the isolated proposer once for that allocation. The external transport
must expose only the packet and exact allowed indexed files. Import its receipt
with `import-response`. Required receipt fields are `raw_response`, `session_id`,
`model_version`, `input_sha256`, `input_tokens` and `output_tokens`; preserve null
for genuinely unavailable token counts. Invalid, over-budget, wrong-session,
duplicate and no-change responses remain recorded and consume their allocation.
Never call again to obtain a more convenient proposal.

Before invocation, `proposal-capsule` packages the exact saved input with its
registered knowledge and evidence. L requires the family specification and
learning-member list again, so saved feedback cannot bypass the complete-family
reader. B refuses those arguments before opening them. The command writes
`capsules/<branch>-<round>-<slot>.json` outside Git and adds no contacts. Packaging
alone does not admit a transport; the real provider path must preserve and attest
every request, enforce the complete conversation budget and expose only the
artifact broker. The current host audit deliberately uses a synthetic endpoint.

Capsules now use lossless, hash-verified chunk storage under
`capsule-material/<branch>/<allocation>/` in that external archive. Large traces
are never clipped to the former in-memory artifact limit. Keep the complete
cache with its capsule; pages verify their stored bytes at access time. See
[the volume and cost-reader correction](complete-feedback-streaming-v1.md).

The [bounded Responses transport](responses-transport-v1.md) now supplies an
actual HTTP/SSE and artifact-continuation implementation, proved on loopback.
It retains the hard output bound and requires a model-free input meter plus a
pre-contact registration callback. No compatible live provider is yet admitted.
The subscription profile's lack of a server output cap is an explicit pending
owner question; do not omit the cap or call a paid endpoint as a workaround.

Use `compile-candidate` with the same protocol, seed configuration, parent
archive, exact next-round evaluation roster, data root, isolated staging
directory and required `--cohort-binding`. Use the matching pinned
`cohort-bindings/update-N-v1.json`. This replaces the seed's old R01C input
bindings while preserving the compiled policy; it refuses missing query rows
and wrong vote pools, and removes inherited supply/FIT identities. See
[the exact input contract](cohort-input-binding-v1.md).
Compilation also refuses cumulative source overlap and undeclared edits. A change
to construction instructions or values requires a separately registered actual
construction generation and a verified release link. The construction reader
joins each output to its own request instruction and sample, applies the existing
semantic edit contract and verifies the prepared release. No construction call
may borrow a task-generation allocation.

Prepare and register each candidate's own supply, FIT, generation and scoring
identity through the existing flight machinery. `compile-candidate` now records
its proposal/bundle/configuration custody. Use `freeze-update` to account for
all four spent proposal opportunities and freeze the actual update family
before any prospective run has artifacts. Both parent/A/A pairs remain;
only objectively invalid imports may be excluded. Copy the registration and
its evaluation map into the prospective READ recipe. Failure after admission
never permits a partial-family update. See [update-stage custody](update-stage-custody-v1.md).
The executable candidate flight registrations and coordinator admissions have
not yet been materialized. The exact TRAIN dataset fragments for all three
updates and common selection are now prepared and verified with the existing
native loader; their [receipt](runtime-views-v1.json) is metadata evidence only.
Bind each actual member's own TRAIN supplies and FIT before admission.
Common-selection membership has its own offline freeze described below.

protocol, stage, branch and ordered `--selected-id` values. Bind every bundle,
run and runtime configuration in the prospective READ recipe's
`system_search_evaluation` map. This entry derives measurements from verified
feedback; the legacy hand-entered `SystemSearchArchive.retain` record cannot
authorize a later parent. Apply the preregistered tie-break and own-A/A intent
protection before recording the choice. Root's statistical report remains
required; the custody command computes no verdict. Do not mix point estimates
from different rounds or expose evaluator selections to the blind proposer.
See [selection custody](selection-custody-v1.md) for the map, fallback and
transitive exposure rules.

Use `freeze-selection` with all three freshly gated update families and root's
explicit historical nominee bindings before the common selection cohort. It
admits one or two retained versions per branch plus seed/A/A, binds unused
second slots before contact, and preserves all nomination exposure. It does not
compare different cohorts' scores or automatically nominate the last round.
See [common-selection registration](common-selection-registration-v1.md).
Reevaluate the frozen nominees on that common cohort. Record both branches and
use `freeze-finalists` to bind their exact L/B versions before DEV. Prepare the
later registration against its create-only `finalists.json`, then run seed/A/A and both finalists on the registered
1,000 rows. Root reads the entire completed family and reports L-B primarily,
L-seed secondarily, uncertainty, strata, reliability and actual costs. No
automatic extra samples, adoption, new allowance or recursive-improvement claim
follows from point estimates.
