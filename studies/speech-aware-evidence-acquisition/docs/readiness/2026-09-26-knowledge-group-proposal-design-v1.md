## Source and view contract

and prepared-text paths. Source v2 explicitly declares
complete-system-events-per-input-v1 and a 200,000-byte limit per context.
Reject an oversized context; never drop a group, attempt or later event to fit.
The original v1 context and all actors/scores remain immutable.

The declared event view retains:

- Every role contact, response record, interruption and raw response choice.
- Every actual tool attempt/result, arguments and unknown extra fields.
- All supplied intent, slot and exemplar knowledge bodies, tool schemas and decoding.
- Prior role-state content, decoded control messages and decoded tool-state results.
- Ordered source record references, planner routes, terminal disposition and delivery.
- Every attempt's official terminal counts, intent/format status and utility.

Known duplicate custody metadata and wire timing/identity fields are explicitly
omitted from decoded views. Every omission lists its field names and source hash.
Unknown fields and malformed, duplicate-key or nonfinite JSON remain literal.
No role statement is reinterpreted as an executed tool. No speech is replayed, and
no reference transcript or gold answer is introduced.

The editable cards retain all semantic fields, including intent-role bindings.
Only the long TRAIN source-support ID lists become hash-addressed custody references
in the model-facing view. Compilation and ancestry still use the complete canonical
source and all eight cumulative construction inputs. These are explanatory slot
value proposals; intent knowledge, retrieval keys and bindings are unchanged.

Every context uses the same local evidence alias, observed-group, and the same
edit contract/output grammar. The source group ID and input hash disambiguate it.
This keeps the common instruction/schema prefix stable. A proposal may cite only
its observed group; do not interpret the alias as evidence from other contexts.
