# Native Audio2Tool candidate-to-parameter supply

This change connects the existing native role episode to released Audio2Tool
parameter explanations through the shared knowledge provider, named-store
router and FlightRuntime. It adds no experiment launcher or independent
answering path. Real model capacity and task effectiveness remain unmeasured
for this new configuration.

## Shared execution and source authority

TaskAdapter.candidate_inventory exposes immutable ordered legal names with
their source hash and authority. Its default delegates to the existing
candidate-contract provider, preserving SLURP behavior. Audio2Tool derives
its inventory from one public tool-registry byte read. Knowledge values never
define tool legality; no task row, gold call or reference transcript is needed.

The provider now shares deterministic selection, ranking, fusion and
materialization. The SLURP derivation retains its parser, three-candidate
bound and same-ID authored facets. The Audio2Tool derivation preserves ordered
action occurrences, alternatives and repetitions in raw state and the audit,
deduplicating only evidence delivery. Both follow actual value-to-facet links,
including when adding new values after a later source state.

The registered provider is audio2tool-candidate-semantic-v1. Its route requires
a parameter-meaning store, an explicit source phase, max_actions,
max_candidates_per_action, per-candidate value and total value limits.
It refuses SLURP projection and implicit Top-3 fields. Candidates guide
knowledge delivery; Solver retains the complete legal tool answer space.

The shared pure compiled-snapshot validator checks the compiler receipt,
source metadata, value view and exact tool -> value ID -> content-facet
relationship. It rejects rehashed target, facet or value-ID swaps.
Preparation owns source reads, rehashing and publication. Runtime checks
released source/snapshot pins, matches the public registry hash and complete
legal target set, then indexes existing values without recompiling data.
Selection receipts bind raw Perception content, source response, inventory,
snapshot and qualified selected values.

## Real configuration and native request proof

Use the distinct registered program
phase-audio2tool-native-candidates-review-revise-v1. It declares
audio2tool-perception-state-v1 for Perception while preserving the existing
bounded four-role semantics. Historical programs are unchanged.

The synthetic native integration uses this real program, the public
phase-material loader, registered response-format resolver, static instruction
renderer and material builder. It uses the actual Audio2Tool runtime adapter,
FlightRuntime resolver, continuous runner and OpenJiuwen executor. Speech
packets, responses and contact admission are synthetic.

The proof covers five ordered occurrences and repeated alternatives, exact
selected parameter content in the Solver request, absence of those later
parameter cards in Perception, and the full legal task contract throughout.
Solver may return a legal tool outside the supplied candidates, and only its
completion becomes the accepted answer. No answering model, encoder, ASR,
scorer or task-gold loader is invoked.

An empty Perception action list means no intermediate hypotheses were emitted.
It supplies no parameter cards; it does not authorize an empty final answer
or remove the original task.

## Remaining experiment admission work

Public task sources establish multi-tool capability but no numeric maximum
for action occurrences or alternatives. Register operational bounds explicitly.
Do not infer them from old SELECT/FILL limits, a retrieval K or synthetic
fixtures: retrieval breadth and alternatives per action are different knobs.

Prepare the full four-role baseline using the two released knowledge stores,
current 4000-row roster, prepared speech and pinned query/facet vectors.
Keep the old official task input/output contract for the matched direct arm.
The old snapshot-bound recall and two-stage policy are not the new method.

Measure complete real requests and configured output headroom before
admission. Preserve multi-action diagnostics alongside the registered standard
scorer. Public singular call-string wording and multi-action task representation
remain a known contract ambiguity; do not silently change the benchmark.

The active SLURP replication remains on its separately frozen execution source.
This engineering change neither edits that source nor admits another GPU flight.
