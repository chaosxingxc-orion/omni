# Prepared-text complete-system summary stage

## Scientific purpose

The whole agentic episode remains the optimization unit: all recorded role,
tool, revision and delivery events reach the summary. A summary must not gain
an undeclared second hearing or extra task ontology. The previous
system-trajectory-summary-v1 baseline remains an explicit multimodal adaptation.
The new system-trajectory-summary-text-v1 baseline removes those fresh inputs.

This is a model-facing execution connection, not a completed TF-GRPO cycle,
a bit-for-bit reproduction of upstream prompts, or evidence of task improvement.
No research model, tokenizer or scorer endpoint was contacted by this work.
The execution-closed candidate comparison stays closed and unread.

## Shared execution and authority

Use the new D2 arm prepared-context-text, the existing direct-only controller,
OpenJiuwen executor, verified prepared_training_feedback loader, scoreless TRAIN
artifact contract and actual live request fitting. The source loader rechecks
the complete sealed source and exact construction roster. The new arm adds no
construction_targets field and grants no new gold visibility.

The arm accepts one verified prepared state followed by one phase-control
instruction. It refuses fresh evidence, audio, feature packets, tools, native
episodes, observation transitions, task-answer scoring and injected task
instructions. The phase prompt remains configurable and source-pinned. The
fixed system instruction defines this input contract, rather than reproducing
the original task-answer prompt. The original adapter prompt and ontology
builder are not called when assembling this text stage.

The common QueryState retains the original speech identity with speech_audio
as its source provenance. That source field is not a claim of observed audio.
The shared client's text_only_sample_id branch keeps the real carrier, roster
and recording binding but sends no media. It does not fabricate a feature
packet or relax the original speech-query rule for task-answer arms.

The boundary has a distinct prepared_text=saea-prepared-text-v1 marker and no
speech_feature_parts, raw_speech_query, construction_targets or evidence fields.
Transport renders the verified state and current control once, using the same
renderer for capacity and generation. It supports the existing resident
speech-query-prefix-v2 prompt order without changing the model fragment or
starting another model service. Prepared source hashes and exact rendered-body
hashes are preserved. Existing arms retain their field sets and behavior.

## Fitting and accounting

A text-only phase uses one properties endpoint call plus two calls per row:
apply-template and tokenize. A single-media phase retains its historical
one-plus-three-per-row count. The common endpoint calculator now takes an
explicit media_count; the new arm selects zero. Whole-roster, exact-body,
one-shot fit journals, service identity, generation lease and refusal on an
over-capacity request remain in force. No truncation is introduced.

The fit receipt records zero speech tokens and zero media parts. The prepared
custody receipt records zero fresh audio observations and no fresh task
knowledge. The anchor's positive source duration remains in boundary metadata
and conservative legacy audio-budget accounting. Report this charged duration
separately from actual new audio exposure; do not describe the former as an
additional model hearing or silently alter historical metering.
