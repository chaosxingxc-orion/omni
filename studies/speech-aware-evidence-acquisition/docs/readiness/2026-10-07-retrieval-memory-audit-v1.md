# Retrieval memory audit (2026-10-07)

Audit only: no production source, scientific configuration, scores, retrieval parameters or frozen worker bytes were changed. The synthetic proof invokes the current matrix cache on generated vectors only.

## Findings and priority

The existing exact path already caches immutable key norms and float64 matrices. It computes a query norm once per dimension, copies only that query into NumPy, and divides score arrays rather than normalizing every key anew per query. The matrix is built once per tuple-object set. Existing BLAS preselection only selects candidates for the unchanged scalar exact rescoring; this audit changes neither arithmetic nor its boundary rules.

The highest-priority cache concern is object lifetime. `_KeyMatrixCache.get` compares each vector tuple by object identity; entries retain both the complete tuples and matrix. Four entries are retained by count, without a byte budget. Calling the uncached `load_sealed_vectors` again on identical pinned bytes creates fresh tuple identities and therefore another matrix entry. `phase_supply` loads phase query/facet tables before provider construction. Rebuilding `KbFacetProvider` per decision reuses that loaded table, so provider reconstruction alone does not duplicate it. Separate phase/source construction or repeated route binding can parse it again; the code makes this reachable, but this audit has not established the number of duplicate entries in the failed natural4 process.

A single synthetic proof (original tool chunk 1837d1, exit zero) used 256 x 64 generated vectors. Reusing the same tuple objects reused one entry. Five equal-content fresh parses increased entries to four, evicted the original on the fourth fresh parse, and kept four full vector sets after external references were dropped. Matrix bytes rose from one 131,072-byte entry to 524,288 bytes; cached tuple rows remained 1,024. Every matrix byte and exact norm matched the original. This demonstrates retention behavior, not the failed worker's measured memory or a scientific result.

At 11,514 x 2,048, a float64 matrix is 188,645,376 bytes (179.91 MiB). Distinct ordinary CPython float objects plus tuple slots cost approximately 754,581,504 bytes (719.62 MiB), before row headers, dictionaries and input JSON. Four independently parsed copies can therefore retain roughly 3.51 GiB of these two payloads together. This is an upper scenario formula; actual entry widths and tuple sharing must be observed. It does not explain or claim the roughly 20 GiB host growth. Matrix construction also temporarily allocates a finite-value Boolean array. Query-time dot/approx/partition arrays scale with row count, not rows times width.

The full per-dimension score list and keyed full sort can allocate extra O(N) references and sort keys. A separate synthetic selection microproof matched exact score/facet-ID ordering in 60 tie and size cases; at N=11,514/K=5 its selection-only peak was about 1.02 MiB for full sort versus 296 bytes for bounded selection. This excludes the existing score list and all resident vectors. Root explicitly deferred that small optimization. The all-dimension union, complete `RankResult`, thresholds and fusion must remain intact: `KbFacetProvider.fuse` consumes the complete stored rank result even when its external `Ranking` view is sliced to K.

Knowledge hydration already has a selected rendering boundary. The frozen snapshot is loaded/adopted before ranking; fusion traverses its value metadata, while `_render_kb_supply_packet` renders only values visible in the query state. Replacing it with a new lazy hydration scheme is not justified by this audit.

## Safe prospective cache design

Prioritize loader streaming first (separate Sol2 ownership). For a subsequent reviewed change, scope immutable parsed-vector reuse to a route/flight identity containing the verified file SHA-256, declared dimensions, resolved confined source path and validated schema. Reuse the same tuples within that scope; never share mutable unvalidated dictionaries across callers. Keep hash/tamper checks and exact norm/scoring arithmetic. Scope release must remove retired entries without affecting active concurrent routes. Add a byte budget to the existing matrix cache in addition to its entry bound; evict cache references only, and compute the same exact fallback if an entry exceeds budget. Do not infer pin identity from equal floating-point data, add ANN, quantize, renormalize or change BLAS/scalar arithmetic.

Before implementing, review duplicate-source construction with the current streaming patch, then prove identical score/order/recall/fusion/request bytes, tamper refusal, concurrent route safety, and released cache ownership using synthetic sources. No retry, contact, admission, cache clear or live collection is authorized by this note.
