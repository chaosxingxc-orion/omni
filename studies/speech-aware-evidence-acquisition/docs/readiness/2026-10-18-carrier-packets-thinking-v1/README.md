## Why a separate package, and why packets come first

The Thinking mmproj audio tower differs from the Instruct one (748 of 860 tensors), so no Instruct packet is valid input to the Thinking decoder. The carrier baselines (`docs/readiness/2026-10-18-carrier-base-thinking-v1`) pin the SHA-256 of their Thinking packet artifact, which exists only after this chain runs; the P3.3 package is therefore derived (`--require-receipts`), registered and flipped AFTER it. All Thinking packets live in ONE root, `/home/chao/feat-cache/slurp-q4km-packets-thinking-gpu-afdaeff6`, extended ADDITIVELY under their own receipt per roster (the Fold B / DEV / test-sample precedent); a packet id is the recording id (A2T) or the audio digest (windows), so the root needs no carrier directory.

## A2T (`carrier_think_packets.py a2t`)

The SLURP-Thinking packet pass applied to the 400 rows of `docs/checks/speech-aware-evidence-acquisition/2026-09-27-a2t-paired-400-roster/flight-roster-receipt.json`: the encoder server (Thinking decoder + its bf16 mmproj on the GPU, `-np 1`) starts inside a serving-swap window, the four-row smoke stage encodes the first four rows into the legacy cache only and measures rows per minute, the full stage encodes the remaining rows, the server stops normally, and all 400 are promoted into the packet root under `A2T-PAIRED-400-THINKING-promotion.json` (create-only). Wrapper: `scripts/flights/carriers/carrier_think_packets_gpu.sh a2t`.

## Earnings windows (`carrier_think_packets.py windows`)

An exact-window inventory binds the encoder identity, so the registered Instruct inventories are RE-KEYED to the Thinking identity model-free (`carrier_think_windows.py`; the transform reproduces all four registered Instruct inventory hashes byte for byte, `selfcheck`) with NO new slice cut: the requests point at the registered Instruct slices (4.3 GB / 1.2 GB are not duplicated). The pins are in `carrier_think_window_pins_v1.json`; the encode experiments are registered against them now. Per carrier the chain then runs the four-window SMOKE pass (encode under a root lease, audit, provenance, formal packets) and, only if it passes, the FULL pass. The 4 smoke windows are re-encoded in the full pass into its own cache (4 extra contacts, inside the plan); their packets are promoted twice, and the second promotion is accepted only when the chunks are identical (harness item E40: `shared`); a conflicting packet id is never overwritten and stops the chain.

## Order

1. `bash scripts/flights/batch/package_launch.sh scripts/flights/carriers/carrier_think_packets_launch_spec.json --root-countersign --until commit` (derive, write, countersign the seven rows, commit).
2. `bash scripts/flights/carriers/batch_chain_carrier_packets.sh all` (the Windows task SAEA-Chain-CARRIERPACKETS; A2T -> E21 -> E22): per carrier one swap window (stop the resident session, encode, promote, start the Thinking session) with a rate gate between the smoke and the full stage.
3. Then the P3.3 package (`carrier_think_base_launch_spec.json`), which refuses unless every packet pin exists.

## Honest limits

* The A2T stage follows the proven SLURP-Thinking and A2T-G1 drivers primitive for primitive; the Earnings window stage (lease, `prepare-window-features`, audit, provenance, packets) follows the library contracts and the registered E21 DR encoding, but has never been exercised on the Thinking core: the four-window smoke pass IS its rehearsal, and the chain stops after the smoke unless the rate gate and every receipt check pass.
* Window inventories are new data-root files (about 5 MB each); nothing else on the data root is written by the model-free stage.
