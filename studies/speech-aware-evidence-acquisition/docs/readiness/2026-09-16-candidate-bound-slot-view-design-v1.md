# Candidate-bound slot views: one selected successor design

Date: 2026-09-16. Root prospective design; NOT an ExecutionPlan or launch authorization.

## Decision and hypothesis

Select a single information-consumption extension for SLURP: preserve the released
candidate-to-slot semantic relation through to a source-bound request view. Use the
older qualified dual-store agent as the fixed base. Keep candidate generation, K8
intent retrieval, candidate width, selected card IDs/order/caps, role prompts, permitted
tools, revision bound and frozen core fixed for the first comparison.

This is distinct from retrying the closed typed-context package. Do not reactivate its
replica, read its partial quality, splice its outputs or relabel a third recovery.
The latest reference-dedup implementation remains a separately verified engineering
capability; do not bundle unrelated new role/review/tool changes into this comparison.

Hypothesis: the same original slot facts, associated with currently relevant intents,
can be consumed more accurately than complete multi-intent cards. Expected signatures
are better slot interpretation or fewer harmful revisions, with global omission and
ambiguity constraints preserved. A smaller context with no task gain does not establish
this hypothesis. Candidate inclusion is expected to remain unchanged within a paired
episode if the Perception path is held identical; independently generated arms can
still vary and must be reported as generated.

## Representation and scope

1. Build a pinned structured relation catalog from the already released authored source.
   Rebuild the original snapshot exactly. Retain source/value identity and field addresses,
   all binding rows, and every global field. This is a prepared derivative, not a new
   knowledge authoring or an inference of relations from prose.
2. Select binding rows at the actual consumer request boundary, not at initial acquisition.
   Multiple candidates can share a value; preserve every applicable binding, not merely
   the first candidate whose turn selected the card.
3. Initial Solver scope is the complete normalized current candidate set. For Reviewer
   and revision, include the latest valid Solver intent even if outside that set.
   If explicit target lookup is ever enabled in a later admitted design, preserve its
   actual per-call targets too. Do not freeze the scope to the first Perception output.
4. Keep all global extraction cues, admissible formats, missing/ambiguity behavior,
   limitations and source links verbatim. Keep every selected card in original order.
   If no source binding applies, retain the complete card and record why; absence is
   not evidence that a field is forbidden or mandatory.
5. Distinguish the derived view from the original value. Preserve original canonical
   knowledge, QueryState, dispatcher results and native assistant/tool groups. Do not
   mutate full content under a source hash that identifies different bytes.
6. Validate source custody before deriving the wire view. Route base evidence and any
   native knowledge return through the same registered view mechanism, with explicit
   derivation identity and original-source references. FIT and dispatch must use the
   same final builder. The existing native reference projection cannot reference a
   shortened view while claiming that the complete original body is visible.
7. Record role, current candidate/draft/call source hashes, selected/excluded binding
   addresses, fallback reason, original/full-view hashes and final request hash.
   Preserve raw model responses. A deterministic view must not decide the answer.

The existing rendering callback is a useful seam but lacks scope/structured-relation
inputs. Extend the shared knowledge/context abstraction deliberately; do not put a
SLURP prose-slicing function in a private experiment script or weaken source checks.
The required structure exists in the pinned authored rows, not in QueryState alone.

## Verification and scientific comparison

First prove synthetic multi-candidate, outside-candidate draft, no-applicable-binding,
malformed-draft fallback, exact global preservation, explicit target scope, raw/feature
request equivalence and default identity. Use the existing framework/executor.

Then register a distinct bounded engineering proof with exact source/config, row IDs,
service identity, actual FIT contacts and maximum generation/tool counts. It must
exercise the changed path. Four rows can establish this engineering evidence only.
Do not bypass a request-fit failure by silently truncating or accepting an unreviewed
answer. Keep the failed source frozen.

After that proof, register one complete same-roster system comparison on TRAIN A.
Compare the fixed useful agent and the one-change candidate-bound view. Keep a compatible
direct-model anchor for the full-system question; if no released source/service-matched
anchor is eligible, explicitly include a fresh direct arm in the proposal rather than
reading the closed pair's held score by convenience. Present exact costs/caps only after
the final bounded role program and service are verified.

Primary reporting remains complete-cohort official pooled SLU with paired speaker
cluster uncertainty and all scenario strata. Report natural and equal-scenario summaries,
intent correctness, exact task outcomes, common-correct-intent slot diagnostics, omissions,
false additions, surface/type errors, draft-to-final saves/harms and actual input/contact
counts. Outcome-conditioned subsets are diagnostic, not substitutes for the primary.

Freeze the actual advancement and replica rule before contact. A positive system-versus-
direct comparison does not isolate the view's contribution; the fixed-agent comparison
does. Do not promote the new view merely because it is smaller, or keep sweeping scopes
after failure. Preserve the older useful agent if the tested extension does not qualify.

## Expectations and later branches

The source-only enumeration shows about 42.5% ideal card-body reduction for all ordered
three-candidate sets. This is not an estimate of actual model tokens or task gain.
A modest positive change is plausible, but shared-model error and correct-intent misses
can dominate. The view may be neutral or harmful.

Do not concurrently add candidate refresh, Whisper, new knowledge content, a new Reviewer
prompt or training-free policy updates. The candidate-coverage line remains a separate
prepared successor. Once one agent base is stable and has exercised meaningful decisions,
define actual grouped trajectories, rewards and automatic policy/experience updates.
Root-designed view engineering remains engineering evidence.
