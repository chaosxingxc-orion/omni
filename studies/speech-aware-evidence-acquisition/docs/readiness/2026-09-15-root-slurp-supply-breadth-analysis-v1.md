# Root interpretation: SLURP supply breadth and the next agent workspace

This is a root-authored analysis of the released TRAIN fold-A1080 audit. It does not authorize a new model contact or reopen a closed flight. The complete shared retrieval replay matched the existing breadth8 supply for all1080 samples. Selection was sealed before the reference join. All findings are discovery diagnostics, not causal gains.

## Evidence and population

The replicated SLURP package remains the exploratory base: NEW500 official micro-F1 improved from35.8906% to50.6876%, delta14.7970pp, speaker-cluster CI90[11.5245,18.0112]. Its equal-scenario delta was12.1257pp. This is a complete-package result on historically exposed discovery; individual components and training-free RL are not established by it. Recommendation and takeaway strata declined in that replication, so aggregate improvement does not imply every task type improved.

The separate TRAIN fold-A1080 source generated candidates containing the gold intent on937 rows(86.76%). It ended with correct intent on842 rows, of which525 still had nonexact entities. Keep these populations and definitions separate from the DEV1000 replication diagnostics.

The breadth32 supply covers1040 own-intent cards(96.30%), but this does not demonstrate95% generated-candidate coverage. It newly supplies the own card on79 of the143 old candidate misses. Reaching95% requires at least1026 covered candidates, an improvement of89 over937. If the only changes were perfect correction of those79 newly supplied misses and no losses, coverage would be1016/1080(94.07%). At least10 further improvements would need another route. This is conditional bookkeeping, not a ceiling or a prediction: added cards may also affect other rows and cause losses.

At breadth8,33 candidate misses already received the own card;110 did not. At breadth32,31 old misses still lack that card. Availability and consumption are separate intervention targets. A retrieved value needs a usable semantic distinction; its presence is insufficient. Full breadth32 values also cost3.98 times the current knowledge bytes, before actual token fitting.

## Root-selected design direction

Keep the replicated base frozen. Prepare a successor that separates a broad discriminative intent workspace from candidate-associated explanatory slot material. Use existing shared knowledge/provider/controller interfaces and explicit configuration; do not create another experiment runner.

1. Retrieve broadly enough to expose competing intent hypotheses. Prepare a compact, source-bound view containing activation meaning, distinguishing evidence, confusable alternatives and exclusion conditions. Preserve all60 legal intents in the task contract. Treat breadth32 as a preparation candidate supported by this audit, not an automatic winner or a claim of95% coverage. Freeze exact value transformation and byte counts before generation.
2. Let Perception form candidates using speech and the supplied intent view. Keep generated candidate count explicit and report gold membership, actual distinct count and missing-support strata. Do not infer confidence from a short candidate list. A change in the candidate-count contract requires prospective registration.
3. Let Solver compare competing intents while loading the associated slot explanations: semantic role, extractable evidence, valid representation, omission/negation rules and constraints. Candidate hypotheses remain evidence, with the full legal answer space retained. Report final-intent accuracy conditional on gold-candidate inclusion and entity quality conditional on correct intent.
4. Let Reviewer and Planner request evidence for named uncertainties. Acoustic ambiguity calls for a governed speech observation such as local ASR or bounded relistening. Taxonomy ambiguity calls for discriminative knowledge. Parameter inconsistency calls for a task/slot contract check. Solver retains answer authority. Tool availability is not a successful intervention unless the actual trace shows use and its final benefit or harm.
5. Build corrective memory only from released construction/discovery permissions and reusable validated failure patterns. Keep raw TRAIN rows out of a memory masquerading as distilled rules. Keep references and protected-fold annotations outside every runtime request.

Use complete final-task quality to decide whether a successor advances; candidate95% remains a priority diagnostic target alongside system optimization. Compare the system to direct frozen-core use and the retained useful incumbent as needed for the decision. Report rescues, harms, saturation, invalid output, tool/revision use and per-stratum results. Do not launch a sequence of tiny quality screens or repeat until a threshold happens to pass.

## Boundary with future training-free RL

These changes make an explicit workspace that a later algorithm can optimize: candidate/knowledge views, evidence-query choices, bounded observation scope, revision decisions and stopping actions. Engineering design is not RL. Algorithm work starts from a locked useful base, with registered trajectory sampling, task rewards, group-relative credit, update targets and a separate evaluation split. Root owns that design after the remaining transfer evidence is read.
