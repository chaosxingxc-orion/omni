# Shared fresh-parent window binding

Use the existing FlightRuntime and OpenJiuwen direct and repair policies in two offline stages. The new core.predecessor_builder verifies the declared run, attempt, config, protocol, discovery split, complete call roster and every window boundary before recovering terminal responses with the existing stitch proof. It verifies prompt/completion totals and saturation against that same newly sealed manifest instead of historical constants. Both generated stages count toward system cost.

The parent contract is frozen before direct generation. Its configuration and protocol hashes name that prospective direct arm; only the resulting manifest and response hashes are materialized after sealing. No outcome-dependent selection is allowed. A derivative is written once below the data root, and its content-free receipt under docs/receipts pins the source and the full window/text chain. The old entry verifies its existing historical artifact; fresh parents use the common builder through scripts/flights/bind_window_predecessor.py.

This change neither starts a service nor authorizes an experiment. New parent and repair fit/generation exposures remain separate. Full actual repair capacity must be checked with the newly produced draft before repair generation. Historical raw-audio comparisons and the current prepared-packet provenance remain explicit.
