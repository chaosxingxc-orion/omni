## What already works

The shared native role graph is the correct control plane. The registered phase-native-candidates-review-revise-v1 controller runs Perception, Solver, Reviewer, and Planner through the shared OpenJiuwen executor and FlightRuntime. native_episode_config permits analytical tools only on Reviewer or Planner, binds each tool set to its source role, and enforces the configured iteration and revision ceiling. Native tool authority is reconstructed from the actual metered completion, ordered request schemas, structured function call, and request/response hashes. Tool results enter the role history as source-bound state. native_episode_receipt then permits delivery only from the exact latest Solver visit, whether Planner accepts it or the bounded revision limit delivers it. Perception, Reviewer, and Planner cannot become answer authorities.

The tool registry already contains saea-tool-live-speech-observation-v1. Its native schema lets an authorized role choose the current speech observation on demand with exactly span=full-utterance, representation=asr-transcript, and a bounded distinction naming the ambiguity to resolve. The shared dispatcher validates the structured call, counts the internal action, and invokes LiveSpeechObservationProvider. The model cannot choose a filesystem path, audio hash, or unrelated sample: FlightRuntime derives the roster's packet/audio binding, and the provider rejects stale sample or packet identities.

The cold path is real and governed. Before reading the selected audio or constructing Whisper, FlightRuntime debits a separately registered speech-tool ExecutionPlan through the required contact callback. The provider verifies the bound source hash and duration, lazily constructs LocalWhisperBackend, decodes only that selection, and stores a content-addressed artifact. The result separates visible transcript/status/evidence identity from internal source, inventory, protocol, attempt, response, and artifact lineage. Repeated identical requests use the verified artifact without another neural forward; failures retain their charge and durable start marker. Runtime seal/abort closes the provider and writes a create-only receipt.

The September 12 four-row recovery established the actual framework call -> local Whisper result -> successor request -> Solver answer wire, including exact per-sample packet, source, response, ASR artifact, and call identities. It is engineering evidence only and supplies no effectiveness or autonomous-trigger conclusion.

The local backend is pinned rather than inferred from the scoring normalizer. The repository records the official Whisper large-v3 checkpoint and 20250625 source, tokenizer/source hashes, exact decode protocol, dependency identities, and local receipts. The prospective DEV1000 source inventory and CPU protocol already exist under prepared/SAEA-SLURP-NATIVE-SYSTEM-LIVE-SPEECH-PREPARE-V1. The v2 verifier resolves Whisper's version from a hash-bound literal source file because distribution metadata is absent, while retaining exact installed-version checks for dependencies. That inventory passed model-free verification; it does not prove a decode or task benefit.

## What is still missing

The current direct/native dual-store configuration has no speech tool or live_speech_observations binding; Reviewer can call only the task-contract tool. The held slurp-native-system-live-speech-dev1000-v1 fragment correctly exposes task-contract and live speech only to Reviewer and keeps Solver tool-free, but it is prospective. Its prospective_live_speech_observation block is documentation metadata, not the runtime interface. Activation still lacks a root-owned live-ASR ExecutionPlan, an unconsumed exposure-ledger row, exact contact/audio ceilings, an attempt-namespaced output_relpath, the actual live_speech_observations binding, final fit/model/scoring registrations, and pinned CPU library thread limits.

The implemented speech action is full-utterance only. No native action currently expresses a source-bound time crop, and LiveSpeechObservationProvider rejects every span other than full-utterance. core/span_surgery.py and core/model/slices.py already provide deterministic, hash-chained cutting and slice verification, and local FFmpeg/ffprobe receipts cover crop mapping and inspection, but those primitives are not an allowed phase action and are not composed with the live-ASR provider. saea-tool-slice-encode-v1 is an encoding primitive, not a Reviewer/Planner-selected crop -> ASR evidence operation. MMS forced alignment is locally pinned/loadable, but no registered live alignment action converts a legal hypothesis to trustworthy seconds; Reviewer word indices are not timestamps. Therefore scoped crop decoding, original-to-crop time mapping, crop-specific cache/contact accounting, and a typed crop-ASR result remain interface work. Planner currently emits only ACCEPT, REVISE, or ACQUIRE; it carries no structured tool/span choice. The held candidate instead lets Reviewer both diagnose and call full-utterance ASR.
