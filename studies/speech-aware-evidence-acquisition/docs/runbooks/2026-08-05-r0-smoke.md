# R0 smoke runbook (SAEA-E-001) — NOT EXECUTED BY THE R0 DELIVERY PLAN

Purpose: first model touch — wiring and measurement-integrity smoke of the
bare-core arm on the dev subset10. Bounded-discovery-probe; no superiority
claim. Executing this runbook is an owner-visible action: it appends an
exposure ledger row before any result is read.

**2026-08-07 operator-path repair note:** an independent rereview
(`wiki/audit/speech-aware-evidence-acquisition-r0-review/independent-rereview-2026-08-07/`)
found that the commands below, as previously written, could not complete a
real smoke: `python -m ...core.driver` could not dispatch at all (no
`__main__.py`), the plan fields omitted `attempt_id`, `driver run` requires
`--session-receipt` with no documented way to create one, and `driver
finalize` was never shown passing `--tracking-uri` (so it silently skipped
the MLflow upload). All four are fixed: a real module/console entry point
now exists, and a new `saea-driver smoke` subcommand collapses plan
generation, session start, run, and finalize into ONE command that derives
`attempt_id`/`split_role`/`split_identity_hash`/`protocol_hash` itself
instead of asking the operator to hand-assemble them. The manual, step-by-step
form is kept below as an **appendix** for anyone who needs to run (or debug)
one stage in isolation.

## Preconditions (all machine-checked at the gate)

1. Clean study tree at the delivered R0 commit; receipts intact
   (`pytest tests/contract/test_real_receipts.py`).
2. `docs/receipts/splits.json` frozen (`smoke` reads the `dev` hash itself,
   via the same verified `core.driver.load_split` path the run-time gate
   re-checks — an operator never copies it out of the file by hand).
3. WSL Ubuntu-24.04; `source ~/.venvs/speechrl/bin/activate`;
   `SPEECHRL_DATA_DIR=/mnt/e/chao_workspace/exploring-l4-intelligence/speechrl-data`.
4. Bytecode discipline: the gate refuses (M-1 hardening) if
   `src/speech_aware_evidence_acquisition/scoring/__pycache__` contains any
   entry — a stray or planted `.pyc` co-located with frozen scoring sources
   no longer needs a manual purge to be caught. That on-disk check alone is
   NOT a complete guarantee: `PYTHONPYCACHEPREFIX` relocates every `.pyc`
   the interpreter would read or write into a mirrored tree outside
   `scoring/`, which that walk never visits, and `PYTHONDONTWRITEBYTECODE=1`
   only stops a NEW `.pyc` from being written — it does nothing to stop an
   ALREADY-planted one from being read and executed. The gate additionally
   refuses outright if `PYTHONPYCACHEPREFIX` (or `sys.pycache_prefix`) is
   set for the checking process, and refuses if any already-imported scoring
   submodule loaded from this checked tree came from a non-`.py` file or
   carries a cache location outside it
   (`FrozenCoreGate._assert_no_relocated_bytecode_cache`) — so this
   precondition, unlike the loose wording this runbook previously carried,
   IS machine-checked at the gate. Operator hygiene is still required: leave
   `PYTHONPYCACHEPREFIX` unset and `export PYTHONDONTWRITEBYTECODE=1` before
   importing, so a `.pyc` is never written in the first place; if the gate
   refuses on this, remove the directory (or unset the relocated prefix) and
   retry. `pytest` itself also enforces the on-disk half of this for its own
   session (`tests/conftest.py` purges `scoring/__pycache__` and sets
   `sys.dont_write_bytecode = True` before any test — including step 1's
   `test_real_receipts.py`, which points the real gate at this checkout's
   actual `scoring/` — is even collected), so a stray `.pyc` left by an
   earlier, unrelated interpreter can no longer make step 1 nondeterministic.
5. llama-server from the receipt-pinned build (`/home/chao/llama.cpp`, commit
   `fdbd6abee20e408de21e90ca77a24cd50a6ea073`) serving the lock-pinned GGUF;
   `llama-server --version` must report `(fdbd6ab)` before starting is
   **not required for `smoke`**: `smoke` (with no `--dry-run`) calls
   `core.session.start_session` itself, which spawns the receipt-pinned
   binary directly — the binary must exist at the pinned path and re-hash
   correctly, but nothing needs to be started ahead of time. `--runtime-root`
   is the directory *containing* the pinned checkout (receipt paths resolve
   relative to it, e.g. `/home/chao`, not `/home/chao/llama.cpp`).
6. Every model touch requires a validated `contracts.ExecutionPlan`
   (`smoke` builds and validates one itself) and a pre-registered exposure
   ledger row — step 1 below, unchanged, still manual and still first.

## Sequence

1. **Append the exposure ledger row** (consumed=no, budgets as planned) —
   BEFORE any request. This step is unchanged and stays manual: it is the
   owner-visible pre-registration record, not something `smoke` should ever
   write on an operator's behalf.

   Plan values this row must match (`smoke` recomputes the last three
   itself; only the first three are still an operator's own planning
   decision — see step 2's `--planned-*` flags):
   - `run_id`: `SAEA-E-001-r0-smoke`
   - `execution_profile`: `bounded-discovery-probe`
   - `carrier_lock_key`: `earnings22-original` (from
     `configs/dataset/earnings22-dev-subset10.json`)
   - `planned_model_calls`: `12` (10 samples + 2 retries)
   - `planned_gpu_hours`: `2.0`
   - `planned_speech_audio_seconds`: sum of subset10 `audio_seconds` from
     `load_earnings22` filtered to `earnings22_subset10_ids`, plus retry
     headroom of 2 × the longest sample's seconds, rounded up

2. **Run the ONE smoke command** — plan generation (with a FRESH
   `attempt_id`), session start + persisted receipt, run, and finalize (with
   an explicit MLflow tracking URI), all in one:

   ```bash
   python -m speech_aware_evidence_acquisition.core.driver smoke \
     --model qwen3-omni-llamacpp \
     --dataset earnings22-dev-subset10 \
     --baseline bare-core \
     --experiment r0-smoke \
     --run-id SAEA-E-001-r0-smoke \
     --planned-model-calls 12 \
     --planned-gpu-hours 2.0 \
     --planned-speech-audio-seconds <value computed in step 1> \
     --run-dir "$SPEECHRL_DATA_DIR/runs/SAEA-E-001-r0-smoke" \
     --runtime-root /home/chao \
     --tracking-uri "$HOME/mlruns" \
     --ledger-cells /path/to/human-ledger-cells.json
   ```

   `--run-dir` is a **stable parent directory** an operator points at once —
   `smoke` creates a fresh `<attempt_id>/` subdirectory under it on every
   invocation (see the operator note below), so this same command is safe to
   re-run verbatim after a failure. `--tracking-uri` must be an **ext4
   (WSL-native) path** per program policy (`CLAUDE.md`: "Only local MLflow
   `mlruns` stays on ext4") — never a path under `$SPEECHRL_DATA_DIR`.
   `--ledger-cells` is a JSON file with the human-supplied ledger columns
   `finalize`/`smoke` cannot derive from the bundle alone: `experiment_id`,
   `speech task/carrier`, `changed axes`, `shared code revision`,
   `model rev`, `dataset rev`, `effectiveness`, `reasonableness`,
   `efficiency`, `deviations`, `decision`.

   `smoke` prints one JSON object on success: `run_id`, `attempt_id`, and
   the on-disk locations of the plan, session receipt, run manifest, scores,
   ledger markdown/JSON rows, and the MLflow run id. Nothing here bypasses or
   re-implements a gate — `smoke` is a thin sequencer over exactly the same
   `run_experiment_bundled`/`finalize_bundle` calls `driver run`/`driver
   finalize` already make (see `core/driver/smoke.py`'s module docstring),
   so it fails closed exactly as those do: a genuine failure exits non-zero
   with the underlying error, and (per I7) still leaves a durable ABORTED
   manifest to inspect.

3. **Register the umbrella experiment-index row** with `core.tracking.ledger_row`
   (the `ledger_markdown`/`ledger_json` paths `smoke` just printed); register
   it in the umbrella wiki (separate umbrella commit).
4. **Write the wiring-integrity memo**: traces complete (OBS/USE per sample;
   ORG/SUPPLY absent for bare-core), budgets respected, hashes recorded —
   the R0 exit criterion is measurement integrity, not a result claim.

**Operator note — a failed attempt always gets a fresh attempt_id and a
fresh run directory, automatically:** `smoke` generates a new `attempt_id`
(and therefore a new `<run-dir>/<attempt_id>/` subdirectory) on every
invocation — there is no flag to reuse a prior attempt_id, and none should
ever be added (`core.attempts`: `(run_id, attempt_id)` is a non-reusable
primary key, I6). After ANY failure (a refused gate check, a transport
error, a finalize refusal), simply re-run the exact same `smoke` command
from step 2 verbatim — it will never collide with the failed attempt's
files, and the exposure ledger row from step 1 does not need editing unless
the failure changed what was actually consumed (annotate/extend it if so,
rather than reusing it silently, per the pre-existing exposure-ledger
discipline).

## Appendix — manual, stage-by-stage form

Only needed to debug or re-run a single stage in isolation; `smoke` (above)
is the sanctioned path for a real attempt. Every command below is the exact
same underlying call `smoke` makes.

1. Compute the plan fields by hand (`smoke` does this for you): `run_id`,
   `execution_profile`, `carrier_lock_key` (from the dataset config
   fragment), `split_role`/`split_identity_hash` (read via
   `core.driver.load_split(REPO_ROOT, "dev", lock, root)` — never copy the
   hash out of `docs/receipts/splits.json` by hand; the loader both reads
   and live-verifies it), `planned_model_calls`/`planned_gpu_hours`/
   `planned_speech_audio_seconds` (still a genuine planning decision), a
   FRESH `attempt_id` (any string matching `[A-Za-z0-9][A-Za-z0-9._-]*`, not
   reused across attempts), and `protocol_hash`:
   ```python
   protocol_hash(compose(REPO_ROOT, "qwen3-omni-llamacpp",
       "earnings22-dev-subset10", "bare-core", "r0-smoke").config_hash,
       "bare-core", <dev split hash>)
   ```
   Write the result to `$SPEECHRL_DATA_DIR/runs/SAEA-E-001-r0-smoke/<attempt_id>/SAEA-E-001-r0-smoke.plan.json`.
2. Start the session and persist its receipt — there is no separate
   `driver session` subcommand; call `core.session.start_session` directly:
   ```bash
   python -c "
   from pathlib import Path
   from speech_aware_evidence_acquisition.core.session import start_session, load_runtime_receipt
   from speech_aware_evidence_acquisition.e0.artifacts import REPO_ROOT
   from speech_aware_evidence_acquisition.data.lock import data_root
   receipt = start_session(
       runtime_root=Path('/home/chao'),
       data_root=data_root(),
       runtime_receipt=load_runtime_receipt(REPO_ROOT / 'docs' / 'receipts' / 'runtime.json'),
       host='127.0.0.1', port=8090, session_id='SAEA-E-001-r0-smoke-<attempt_id>',
       receipt_path=Path('$SPEECHRL_DATA_DIR/runs/SAEA-E-001-r0-smoke/<attempt_id>/SAEA-E-001-r0-smoke.session-receipt.json'),
   )
   print(receipt.pid, receipt.port)
   "
   ```
3. Run through the ONE driver path:
   `python -m speech_aware_evidence_acquisition.core.driver run
   --model qwen3-omni-llamacpp --dataset earnings22-dev-subset10
   --baseline bare-core --experiment r0-smoke
   --plan <plan.json from step 1>
   --run-dir $SPEECHRL_DATA_DIR/runs/SAEA-E-001-r0-smoke/<attempt_id>
   --runtime-root /home/chao
   --session-receipt <session-receipt.json from step 2>`
4. Score: `bash scripts/evaluate.sh --manifest
   $SPEECHRL_DATA_DIR/runs/SAEA-E-001-r0-smoke/<attempt_id>/SAEA-E-001-r0-smoke.run-manifest.json`
   -- the AUTHORITATIVE, I7-verified path (re-verifies split/trace/hash
   binding, the D3 scoring-source freeze, and this study's speech-only
   carrier scope before scoring anything). The legacy positional/`--outputs`
   forms bypass all of that and print a loud "NOT an audit record" warning;
   never use them here. Finalize (score + upload + machine-derived ledger
   row) via `python -m speech_aware_evidence_acquisition.core.driver finalize
   --manifest <same manifest path> --tracking-uri "$HOME/mlruns"
   --ledger-cells /path/to/human-ledger-cells.json` (`core.tracking.log_bundle`;
   **`--tracking-uri` must be passed explicitly** — omitting it silently
   skips the MLflow upload and leaves `mlflow_run_id` as `None`, per
   `core.bundle.finalize.finalize_bundle`'s own contract).

An aborted or partially failed run restarts adapter metering in a new
process — before any re-run, annotate/extend the exposure ledger row rather
than reusing it silently. Each attempt must also use a FRESH attempt
directory, e.g. `$SPEECHRL_DATA_DIR/runs/SAEA-E-001-r0-smoke/<new-attempt_id>/`:
`TraceSink` and the driver's outputs file both fail closed (refuse to
construct/open) when the prior attempt's `<run_id>.trace.jsonl`,
`<run_id>.trace-manifest.json`, or `<run_id>.outputs.jsonl` already exists in
`--run-dir`, so re-running against the same directory raises rather than
silently appending to or truncating the prior attempt's record.
