## 2. The task abstraction

### 2.1 The five-tuple

Every speech task this program runs is an instance of

> **T = (U, C, K, A, S)** — speech observation **units** `U`, a task **contract** `C`, a
> **knowledge space** `K`, an **answer space** `A`, and a **scorer** `S`.

The abstraction is not invented here. It is the shape `rails.task_adapter.TaskAdapter` already
declares, and the mapping is one to one:

| Element | Meaning | `TaskAdapter` surface | Runtime seam |
| --- | --- | --- | --- |
| **U** — observation units | The addressable pieces of speech a node may observe: a whole utterance, a fixed window of a call, a speaker turn, a re-cut span. Each unit carries an identity (`AudioRef` path + sha256) and a span list | `load_split(split_id) -> Sequence[TaskSample]`; `rails.obs.ObsPacket` (`audio_ref`, `spans`, `first_pass`); `preprocess_plan()` | `rails/adapters/runtime_view.py::load_runtime_view` — label-free, hash-verified, media fields only |
| **C** — task contract | The stable schema/ontology text that says what a correct answer is. **Never the query**: the query is the speech (`TaskAdapter.build_task_contract` docstring) | `build_task_contract(sample, obs) -> str`; `instruction(sample) -> str` | `task_instruction_template` + `task_instruction_fill`; the `saea-tool-task-contract-v1` replay |
| **K** — knowledge space | Every frozen, TRAIN-only store the control plane may draw typed content from, plus its retrieval keys | `candidate_contract_provider()`, `candidate_inventory()`; `rails.knowledge_provider.KnowledgeProvider` (`build` / `candidates` / `fuse` / `materialize`) | `knowledge_stores.<id>.{phase_supply, candidate_supply}`; `evidence_source` |
| **A** — answer space | What the Solver may emit and the Delivery node may deliver | `score_response(gold, response)`'s expected shape; the phase `response_format_id` | `core.base.RESPONSE_FORMATS`; `core.base.DELIVERY_NORMALISERS` |
| **S** — scorer | The one paper-facing number, run once per complete manifest | `score(sample, response)`; `gold(sample)` | `core.base.SCORERS` + `core.scoring_batch` |

Two facts make the abstraction load-bearing rather than descriptive. **Gold enters only through
`gold()` / `score_response()`**, reachable only from `score()`, strictly post hoc (`task_adapter.py`,
"gold discipline (D2)"); `assemble_prompt` and `build_task_contract` can never see it, and both runtime
adapters **raise** from those hooks (*"gold never enters an Audio2Tool runtime flight"*). And **a
carrier adds one descriptor, one adapter, one scorer registration and config fragments** — nothing else
(`core/carriers.py::_register_descriptor_backed_loaders` fails closed at import time if a descriptor
has no loader or a loader has no descriptor).

### 2.3 Which axis each node serves

The research object is four separately controlled axes (umbrella `wiki/Research-Objective.md`): `OBS`
speech observation and re-resolution; `ORG` knowledge organization and provenance; `SUPPLY` evidence
selection, amount, order and timing; `USE` evidence admission, verification, iteration and stopping.
The node set maps onto them as follows, identically for all three carriers.

| Node | Primary axis | Secondary axis | Why |
| --- | --- | --- | --- |
| Perception | **OBS** | ORG | It turns speech into an addressable hypothesis state; its own supply is the first ORG read |
| Solver | **USE** | — | It admits or ignores the evidence it was handed and produces the answer |
| Reviewer | **USE** | SUPPLY | It verifies, and it is one of the two seats allowed a model-callable action |
| Planner | **USE** | OBS | It is the iteration-and-stopping control, and it owns the candidate-refresh action |
| Acquisition | **SUPPLY** | OBS | It brings new evidence, or a new observation, into the trajectory |
| Delivery | **USE** | — | It is the admission decision on the answer's surface form |
| (knowledge plane, not a node) | **ORG** | SUPPLY | `build` / `candidates` / `fuse` / `materialize`, offline and pre-contact |

The axis map is what makes the lock a research object rather than an engineering diagram: a Stage-3
optimiser moving a knob is moving a named axis, and the evaluation contract is read per axis.

## 3. Node responsibilities

### 3.1 The division at a glance

Six node kinds. Four are model-contact roles admitted by `load_native_episode_config` (exactly
`perception`, `solver`, `reviewer`, `planner` — no other key validates). Acquisition is defined in the
graph (`NativeEpisodeNodes.acquisition`) and reachable from no config. Delivery is not a role at all:
it makes no contact, registers no agent state and routes no step.

| # | Node | Responsibility, stated once | It **OWNS** (the only node allowed to decide this) | Cost unit |
| --- | --- | --- | --- | --- |
| N1 | **Perception** | Turn this row's speech into a bounded, typed hypothesis state the rest of the episode may choose among | **Which candidates exist for this row** | `perception.max_iterations` contacts per row, plus `max_candidate_refreshes` more |
| N2 | **Solver** | Produce the task answer under the contract | **The answer.** Only a Solver completion may become delivered text | `solver.max_iterations x solver.samples` contacts per revision |
| N3 | **Reviewer** | Verify the draft against the contract and report criticism | **The findings.** The only node whose output is admitted as criticism | `reviewer.max_iterations` contacts per revision |
| N4 | **Planner** | Choose the episode's next transition inside the declared budget | **The transition** (accept / revise / acquire / refresh) | `planner.max_iterations` contacts per revision |
| N5 | **Acquisition** | Bring new evidence, or a new observation, into the trajectory on demand | **New evidence admitted mid-episode** — **BUILT by E18** (owner decisions 43–44): IMPLEMENTED for SLURP kind (a) `knowledge-requery`, PARTIAL for kind (b) `speech-reobserve`, STUB for kind (c) `tool-acquire`; no cell registered, nothing admitted | 0 contacts for kinds (a)/(c), 1 per visit for kind (b); `max_acquisitions_per_row` visits |
| N6 | **Delivery** | Turn the accepted answer into the delivered bytes | **The delivered text** | zero contacts, zero request bytes |

The responsibility statement is one sentence per node; everything below is derived from it, and any
behaviour that cannot be derived from it is a finding (section 3.8).

### 3.9 What no node may read, on any carrier

The research boundary, machine-enforced where possible; part of what Tier A freezes.

- **No gold of an evaluated row**, at any node, at any level: gold enters only `gold()` /
  `score_response()`, reachable only from `score()`, and both runtime adapters raise from those hooks.
- **No transcript and no ASR state as a retrieval key**: queries carry speech or speech+state, never
  text (owner ruling 2026-09-06, enforced as the first token of `embedded_signal`).
- **No future turn**, no reference transcript, no other evaluated row's content.
- **No second answering model**: an L2 cleaning contact may only select, label and compress what L1
  handed it, and `validate_cleaning_document` refuses any content token absent from that material.
- **The Reviewer seat is criticism-only** (owner decision 11-C), enforced by the verdict type.
- **The node-context policy touches only `agent_state` entries** — never the speech packet, the system
  message or `supplied_evidence`.
- **Derived media stays inside its carrier root** (`DERIVED_MEDIA_PREFIX`; the confinement gate).

## 4. The cooperative link edges

### 4.1 What an edge is, and where it is realised

An **edge** is a directed pair `(producer, consumer)` plus the **semantic class** of what crosses it.
The axis is the consumer's reading, not the producer's contact, because the same output means different
things to different consumers — exactly the key `rails.node_context_policy` already uses.

A node request has exactly four content slots, and every edge lands in one of them
(`reproduction/ojw/native_request.py::MeteredNativeSpeechRequest.prepare`, rendered by
`core/model/transport.py` with `core/model/native_history.py`):

| Slot | What lands there | Per node? |
| --- | --- | --- |
| `task_instruction` (system message) | the task contract `C` | **no** — byte-identical for every role |
| `supplied_evidence` (`[evidence <id>] <content>`) | the knowledge-plane edges E2, E4, E6 | yes, per phase |
| agent-state text parts (`[agent state <id> kind=<kind>] <content>`) | every model-output edge: E3, E5, E7, E8, E9, E14, E15, E16 | yes, by accumulation |
| the role query (last user text part) | the node's own instruction plus the `Native episode limits` JSON | yes |

Framework replays (the Reviewer's tool-calling assistant turn plus its `tool` message) are a fifth
channel carried by `project_native_framework_history`; they realise the tool-observation edges E10–E13.

**Levels.** Each model-output edge can be handled at **L0 `raw`** (pass-through under one fixed prefix
— today's behaviour everywhere), **L1 `structured`** (deterministic parse, declared malformed rule,
hash-pinned template, zero contacts), or **L2 `cleaned`** (L1 plus one extra metered contact,
schema-validated, falling back to L1 on any failure, one attempt, no retry). The policy object is a
pure per-state transform over the already selected history — it never adds, drops, merges or reorders a
state — which is what makes L0 byte identity checkable by construction.

**The machinery is carrier-independent; its parsers and templates are not.** The level semantics, the
parse-failure rules (`raw` / `omit` / `refuse`), the renderer-key check and the receipt schema are
generic; `SLURP_BOUNDARY_IDS`, `SLURP_BOUNDARY_TEMPLATES` and `PARSER_IDS` are SLURP-bound, and the
policy id is literally `typed-slurp-node-context-v1`. No other carrier has a boundary map (F-13).

1. **Exactly one model-output edge in the whole program is parsed** — E4, and by the knowledge-supply
   path, not by any context policy. Every other (E3, E5, E7, E8, E9, E14, E15, E16) is a verbatim byte

   outside the episode graph. The loop this base advertises — observe, narrow, draft, judge, acquire,
   revise, commit — is, as flown, observe → draft → judge → route → (rarely) revise → commit, with

   policy may not touch — the strongest argument for making SUPPLY, not context level, the first
   Stage-3 action set (OQ-5).

## 5. Node primitives (owner decision 39)

### 5.1 What a primitive is

A **primitive** is an operation a node may perform on its inputs, stated over the task abstraction
`T = (U, C, K, A, S)` rather than over a carrier. Its signature is fixed by this lock:
`name(inputs: typed content classes) -> outputs`, plus **side effects**, **receipts**, a **cost unit**
and the **knobs** it exposes. The Stage-3 action space is the union of the exposed knobs (section 6); a
primitive with no exposed knob is a structural commitment, not an action. **Twenty-seven primitives**
across six nodes plus the knowledge plane; the status triple is **SLURP / contextual ASR / Audio2Tool**,
where `IMPL` = armed and flown, `PART` = config-reachable but never flown (or reachable in only one of
a carrier's two regimes), `MISS` = no code path a config can reach.

which is precisely what DE-1 is (owner directive 26, module M3).

## 6. The optimisable space

### 6.1 The rule

The optimisable space is the **union of the exposed knobs of the primitives of section 5**, partitioned
as v1 section 5.7 proposed and owner decision 39 accepted: **FREEZE** — the lock fixes the value;
**OPEN** — admissible Stage-3 action space, searchable under its own preregistration; **UNEXPLORED** —
loader-admissible, never flown, no evidence, and **not** in the action space until a cell or the owner
puts it there.

Three carrier-independent constraints apply to the whole table. **Decision 40**: the never-varied
instruction templates and the task contract are FROZEN for Stage 2 on every carrier, and the measured
warning behind that rule is the Audio2Tool ORG-1 read — re-rendering the *same* 152 registry rows
grouped by domain cost **−3.23 pp** [−4.15, −2.33] while the token-matched same-shape control cost only
+0.25 pp, so the loss was prompt structure, not volume. **Decision 38**: a contrast uses the margins of
its own configuration's request-identical replicate; where none exists B0r's own null (SLU 1.1218 /
intent 1.0051) is the fallback and the retired imported half-widths are never used again — the
contextual-ASR carrier has its own measured nulls (corpus WER 0.05793, PERSON 0.25009, numeric 0.15651).
**A knob is per carrier**: a status is a proposal for the column it sits in.

Carrier columns carry the value in that carrier's **default plan** (SLURP, contextual ASR) or its most
recent registered fragment (Audio2Tool); `—` = not applicable; `absent` = the key is not declared,
which for several keys is a meaningful OFF.

### 7.4 What changing a store costs

Re-pinning a store is a `stores`-class arm (`switch.form "repin"`), a one-factor cell on the sealed
anchor, an admission entry and a replication obligation — B4b cost two flights and about 4.6 GPU hours.
Adding a store block additionally needs a prepared-artifact rebuild over the whole roster, a new
`prepared_phase_supply` pin, a wire check, a four-row smoke, a prompt-fit receipt, and a twin when
presence alone could explain the mechanism. Changing a retrieval knob changes the prepared artifact's
identity, so it is rebuilt and re-verified by `core.flight.repin` and the cell is a new arm although no
store byte moved. Rebuilding a construction view is model-free, but the builder's `--check` must
reproduce the released bytes and a repo-committed view also moves a git blob hash. And re-rendering the
contract from an unchanged store (A2T ORG-1) moves **no store byte at all** and still cost −3.23 pp:
rendering is part of the mechanism, and a token-matched form twin is the only control that separates
shape from content.

## 9. What this draft does not do
