# 系统轨迹、verl 与 LoRA：现有资源下的可行性评估

状态：可行性分析，尚未运行训练、测得训练显存或验证精度收益。本文不改变已锁定的冻结模型基线，也不把参数学习归入 training-free RL。

## 结论与建议

**8×64GB Ascend 资源值得验证 Qwen3-Omni 的注意力 LoRA；当前不能承诺 verl 开箱即用。** 系统可承担环境交互、检索、轨迹采集和奖励计算，verl 承担策略优化与训练/推理权重同步。关键工作是两者之间的多模态轨迹适配，而非简单导出回答文本。

建议顺序：真实音频单步训练与权重回灌验证 → 筛选正确监督的 LoRA-SFT 对照 → 有组内奖励差异的在线 LoRA-GRPO。已有系统与 TF-GRPO 继续作为独立对照，先验证参数学习有没有额外收益，再讨论联合优化。SFT 是推荐的低复杂度起点，不是 GRPO 的数学前置条件。

## 资源依据与兼容性

本地模型架构为 `Qwen3OmniMoeForConditionalGeneration`。权重索引记录 31,719,205,488 参数、63,438,410,976 字节，约 **59.08 GiB BF16 权重**。A3B 表示每 token 激活量，不代表只需加载 3B 权重。

| 项目 | 已知事实与判断 |
| --- | --- |
| 硬件 | 8×64GB NPU，总名义显存512GB；主机约2TB内存 |
| 注意力 LoRA | 文本48层 q/k/v/o 投影，rank16约13,369,344参数，rank32约26,738,688参数；不含其他模块或额外保存层 |
| 显存约束 | 冻结权重仍需驻留或分片；激活、通信缓冲、反向传播、rollout KV cache及参考策略也占空间 |
| 初始配置方向 | BF16冻结基座、明确限定文本注意力模块、rank16、小训练microbatch、激活重计算、兼容的模型分片；冻结音频/视觉塔和MoE路由器 |
| 分片收益的限度 | 59.08/8仅是理想权重分片量，不能当峰值显存预测；FSDP层聚合和MoE实现会改变峰值 |
| 当前环境 | 服务容器已有torch_npu/Transformers/vLLM-Ascend，但未安装verl和PEFT；需要独立、版本固定的训练镜像 |

LoRA减少的是可训练参数、梯度与优化器状态，**不会免除穿过冻结文本网络的反向计算**。不建议初版使用 `all-linear`，以免意外覆盖128个专家以及音频/视觉模块。现有推理并发128不是训练microbatch128，更不能据此预测训练显存。

核查 verl 提交 `8df5baeed0f5ecdd7f870d83bc3d79194816e2a9`：

- Ascend支持表列出Qwen3-30B-A3B、Qwen3-VL及GRPO等组合，但未找到Qwen3-Omni对应条目；这说明组合未获该表证明，不等于一定不可实现。
- LoRA文档支持FSDP/FSDP2+PEFT，以及推理侧adapter或合并权重同步。
- Qwen3-30B-A3B MoE-LoRA示例明确面向 **NVIDIA、文本模型、Megatron**，不能作为本工程昇腾音频模型跑通的证据。
- 通用音频输入CPU测试不能证明Omni反向传播和在线RL正确；`VeOmni`是后端名称，也不等于Qwen3-Omni模型支持。

因此必须验证完整交集：**Ascend + Qwen3-Omni MoE + 原生音频 + LoRA + 训练/推理权重同步**。目前没有训练吞吐和峰值显存实测，不给出小时数承诺。

## 是否必须 rollout 出正确轨迹

| 学习方式 | 正确轨迹要求 | 现有轨迹如何使用 |
| --- | --- | --- |
| 正确轨迹筛选 + SFT | 需要可靠的正确监督；可来自成功rollout，也可来自标注答案或经核验的修正 | 筛选成功回答，保留真实输入与检索上下文；没有可靠推理监督时先训练答案，不强行学习整段思维链 |
| GRPO | 不需要预先准备全是正确答案的数据，但需要当前策略采样及可区分优劣的奖励 | 同一输入/上下文/策略采样一组，外部评分，计算相对优势；旧数据不能直接冒充当前策略采样 |
| 偏好学习，如DPO | 需要可靠的chosen/rejected相对排序，chosen不一定完全正确 | 历史候选可用于构造偏好对；具体训练后端另行确认，不假定本次verl组合已支持 |

例如二值奖励 `[0,0,1,0]` 有效地区分成功与失败；`[0,0,0,0]` 或 `[1,1,1,1]` 的组内任务优势为零，继续重复该组价值低。这里说的是任务奖励梯度；启用的KL等辅助项可能仍产生梯度。全错组应触发定向诊断、改进知识/感知或补充可靠监督；全对组降低采样优先级。

Intent正确率与槽位部分匹配可以提供分级奖励，使全错答案仍有排序信号，但它们改变了学习目标。先固定可验证的基准奖励，再把分级奖励作为独立实验；警惕通过漏报槽位、输出空答案等方式获得不合理收益。最终仍用完整名单官方SLURP评分，不把逐样本训练奖励当作官方聚合F1。

**最终答案正确不等于整段推理正确或必要。** 旧K4输出token中约98.23%属于reasoning，不能直接把它们全部当高价值监督。优先筛出与证据一致、无标签泄漏的答案；若训练简短推理，需要单独核验其内容。标注答案可以作为训练target或reward，但不能进入部署时不可获得的输入上下文。

## 轨迹采集必须补齐的内容

已有逐调用收据和断点是基础；RL适配还必须保留原始音频/处理器版本、完整prompt与chat template、检索证据及工具反馈、模型/adapter版本、采样参数、输出token IDs与生成边界、奖励分项，以及算法所需的行为策略log-prob或可核验的重算依据。

仅对模型生成token计算策略损失；音频、用户消息、检索返回和工具返回属于条件输入，不能当成模型动作学习。若一条episode含多次P/S调用，需要显式重建每次调用的输入与loss mask；不能把整个系统日志拼接成一个completion。

旧K4采用不同提示、共享P输出，是诊断/SFT/偏好候选资料，**不是现成的同策略独立全流程GRPO组**。模型更新后，旧策略数据的使用还需有界策略滞后及相应校正；不能无限重用旧rollout。训练端与vLLM的音频预处理、token化、MoE路由及log-prob一致性都需验证。

LoRA更适合尝试修复已经拿到充分证据却未正确使用、标签映射不稳或输出结构不稳的问题。若错误来自P听错或知识库根本没有相关证据，应先修复对应环节；不能假定参数更新会补出缺失的任务事实。这个分工需要按错误样本验证，不是已完成的归因结果。

最小方案优先训练S求解阶段：每个输入固定P结果、检索上下文及冻结的P策略，再对S采样。部署时也只在S加载该adapter，P继续使用原基座；若全局挂载adapter改变P，则属于另一个实验。系统辅助得到的正确答案不意味着去掉知识上下文后模型仍能答对，知识蒸馏/压缩需要独立对照。

## 数据与实验安排

现有隔离候选池只有625条，其中439条是观察到错误的候选，尚未全部统计确认难例；不是已有大规模优质训练轨迹。训练/开发成员固定一次、保留原始标签关系覆盖，防止同语句不同录音或知识来源跨界。已用于选择样本或方法的集合不应再称完全未接触的确认集。

参数训练可能需要代表性回放样本来检查或缓解遗忘；这与training-free RL只聚焦难例的约定不冲突，两者改变的对象不同。回放比例应由开发集回归决定，不预设机械比例。若扩大训练源，需明确调整知识来源划分并建立新版本，不能把知识条目或开发集直接补进训练。最终冻结后报告完整13,078条test；历史采样汇报不等于该测试集被用于调优。

1. **兼容性关卡**：小批真实训练音频，核验LoRA参数列表、非零有限梯度、单步更新、冻结参数不变、checkpoint恢复，以及新adapter在推理侧真正生效；记录峰值显存、时间与训练/rollout log-prob差异。
2. **SFT对照**：相同输入和知识配置，只改变S阶段adapter；在固定开发集报告SLU-F1、Intent、各意图/槽位表现和token/延迟，先确认有可复现的收益且无明显回归。
3. **GRPO验证**：可从每个固定上下文4次S采样起步，先测有效混合奖励组比例。按真实收益和成本调整组大小，不自动扩大到长loop；启用合适的KL/步长约束，防止小数据过拟合。
4. **资源调度**：首轮验证优先8卡按rollout/训练阶段切换，CPU持续准备和评分；先证明显存与权重交接，再比较4卡训练+4卡rollout或其他调度。8卡分配不代表持续高利用率，应以有效学习样本/秒及质量收益/卡时选择。

输入音频、确定性的处理器产物可按依赖版本缓存；冻结音频塔时可研究编码特征缓存，先验证训练接口兼容。模型权重更新后不能沿用旧文本KV cache或旧策略log-prob。数据缓存共享与策略轨迹新鲜度是不同问题。

每轮报告：唯一样本完成量/总量、rollout次数、有效混合奖励组数、总token、逐阶段耗时、卡数/实例数、峰值显存、吞吐、ETA及开发集收益。历史2.766秒/条是双阶段A0推理吞吐倒数，不能外推为LoRA训练效率。
