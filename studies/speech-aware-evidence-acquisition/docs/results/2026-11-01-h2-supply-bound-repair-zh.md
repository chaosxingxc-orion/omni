## 故障与恢复边界

模板变体声明的供应上限仅为 20，运行时传入的累计知识 ID 已超过该值（日志出现 32、39）。错误发生在 Solver 发请求之前；不能通过截断供应内容掩盖配置错误。修正后的累计保守上界为 **56 = 8 条感知边界 + 28 条候选槽位卡 + 20 条训练示例**。前序 ID 即使从文本压缩，仍在累计 receipt 中，因此不能漏算。两臂共用这个上界，检索、供给内容和提示模板不变；每个实际请求仍执行原生 FIT。

原请求、响应、成本和执行树保留。现有原生恢复要求相同 run 与协议哈希；修改上限会改变配置身份，不能把它伪装成原协议重试。选择独立 V2 运行重新登记：现有恢复不能跨协议复用，仅为复用约 10 分钟旧轮成本而扩张通用追溯/封存协议会增加工程风险和停机时间。旧 312 次 P 成本不丢弃、不当作新轮零成本；新轮仍支持同协议断点续推。V2 已完成 94 项执行树测试；独立后台流水线已完成候选绑定与配置生成，正在准备完整供给。容器首次创建因只读父目录缺少挂载点而未启动，补齐空挂载目录后同一未启动容器完成 stage；该故障没有模型调用，保留原始退出记录。尚未确认 V2 模型请求。输入仍使用原完整 H2 312 条名单，不重采样。
