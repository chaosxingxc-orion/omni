# 任务现状、决策与下一阶段计划

更新时间：2026-10-31

## 一、研究目标与已确定口径

本工程的最终比较固定为三条系统链路：Direct、初始 Agent（A0）和最佳 training-free RL（TFRL）。报告不仅比较 SLU-F1，还要同时给出 intent、scenario、action、entity/span 等诊断指标、错误结构、稳定性和实际成本。

方法冻结后，主结果必须覆盖官方 SLURP test 的全部 13,078 条录音。此前使用过的 test 子样本没有参与调优，因此不视为污染；10,068 条子集只作为补充拆分，不能替代全量主结果。

执行顺序已经固定：先完成 Direct/A0 的收益、重复性、错误结构和成本锁定，再运行 TFRL。A0 永久保留为控制组。TFRL 首轮使用 625 条 R01C construction rows，固定 313/312 分半，K=4，最多三轮；相对固定 A0 至少提升 1 个百分点且通过完整评估，才允许接受。

## 二、已经获得的证据

Direct Fold B 的 lock、aa、ab 三个完整批次都覆盖 1,080 行，官方评分状态均为 FINALIZED/PASS，SLU-F1 分别为 45.1178%、45.6633% 和 45.2940%。这些结果用于估计重复噪声，不能单独解释为 A0 收益。

旧的低宽度 Agent 已受控终止并封存，不能与后续结果混合。调度修复已通过针对性回归，修复内容是让声明的阶段并发宽度真正传给 runner，不改变研究协议和方法语义。

随后建立的 phase-width v2、v3、v4 身份均遵守一次性实验规则：失败身份不重放，历史 receipt、lease 和 reconciliation 不修改。v2 在模型接触前因容器运行参数不足退出；v3 暴露了 coordinator 将合法准备产物误判为 FIT 已消费；该校验逻辑已经修复。v4 又在模型接触前因准备命令路径错误退出，并已封存。到目前为止，没有新的完整 A0 模型结果，因此不能宣布系统收益，也不能进入 TFRL。

## 三、算力调度硬约束

NPU 不能因为等待实验准备、人工确认或下一个步骤启动而空闲。所有已经获准且前置条件满足的任务，都必须先写入 detached queue，由 queue runner 按依赖和资源条件自动衔接：当前任务运行时准备后续任务，当前任务结束后立即启动队列中的下一项。队列必须记录任务身份、提交、配置和协议哈希、日志位置、完成/失败标记、超时和失败策略，并支持断线恢复而不重复模型接触。SSH 只是控制和观察通道：连接断开时，detached worker 和 queue runner 继续运行；重连后先读取状态、进程令牌、日志和终态标记，再恢复监控。

队列调度不能绕过实验门禁：未完成 registration、mint、供给准备、paired READ 或 preflight 的任务只能排队等待，不能盲目启动；外部用户占用 NPU 时必须等待，不能抢占。监控重点是队列状态、运行/等待任务数、NPU 利用率和失败事件。SSH 中断本身不能被当成实验失败，也不能触发同一身份的自动重提；如果 worker 已有明确终态失败，必须保留证据、完成审计，再用新的实验身份运行修复后的后继任务。

## 四、当前状态

当前没有正在运行的 Agent campaign，也没有需要恢复的旧任务。常驻推理服务保持可用。下一次 A0 必须使用全新的实验身份，并同时核对注册提交、执行提交、配置哈希、协议哈希、供给哈希和服务绑定完全一致。准备阶段保持零模型接触；真正 campaign 必须 detached 运行，并记录并发、等待队列、墙钟、调用数、音频秒数、FIT、错误和实际成本。

## 五、现在需要你的决策

目前没有必须新增的决策。D1（比较三条链路）、D2（完整 test 主结果）和 D3（先锁定 Direct/A0，再运行 TFRL）已经足够支撑下一阶段工作。

## 六、下一阶段计划

1. 先建立包含 A0、A0 后评分/诊断、Fold A 诊断和 TFRL 前置检查的 detached queue；能提前准备的 CPU/model-free 工作全部并入队列。
2. 从修复后的干净工程提交派生全新 A0 身份，完成 registration、mint、model-free preparation、paired READ 和只读 preflight；前置条件未满足时保持 queued，不启动模型接触。队列提交后即使 SSH 断开，A0 仍由 detached worker 继续执行，重连只做状态恢复和监控。
3. 队列自动启动完整 1,080-row A0；任何模型接触后的失败都封存，禁止自动重试或混入旧 Agent，但后续独立的已获准任务可按失败策略继续或停止。
4. A0 完成后，队列立即衔接完整官方评分、FIT 审计、六列诊断、重复 custody、paired READ，以及 Fold A 的编码、检索、comparator、agreement 和 supply 诊断，形成 D0/A0 lock。
5. 只有 D0/A0 lock 完成后，队列才释放首轮 TFRL；每轮保存候选、奖励、拒绝原因和 lineage，未达到门槛就停止该分支。
6. Direct、A0、最佳 TFRL 与选择规则冻结后，三者各运行一次完整 13,078 条 test；test 结果不再反馈给优化。最终主表报告全量结果，10,068 子集只放补充分析。

## 七、证据边界

单测、registration、mint、准备产物、dry-run、预算上限和局部 checkpoint 都不是系统指标。旧低宽度 Agent 及 v2/v3/v4 的前置失败只用于工程审计，不能与新实验合并，也不能据此推断收益。
