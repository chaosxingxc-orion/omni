# 经验库轮次的独立供给准备

## 当前结果与作用

新增第2/3轮供给准备入口，使用共享 FlightRuntime 的离线首阶段检索与选择，每个真实313/312半组生成自己的供给文件。供给绑定脚本同步支持显式轮次，不再只接受首轮 seed 实验。公开和研究目录分别通过90项正式容器回归（15.49秒、14.76秒）。当前仍没有第2轮真实供给产物或模型调用。

准备入口要求真实经验库、前一轮对半组来源、完整625条首轮判定及真实数据名单全部通过现有校验。准备前后重验，来源、名单或经验库变化即拒绝发布完成凭证。输出保留源码版本、六项来源文件哈希、首轮判定和独立供给哈希；每个输出阶段必须精确覆盖该半组，不能用重复样本填满。

绑定前要求两组均完成且未发生generation/FIT调用，重新核验供给、全部来源、Git历史版本和首轮判定。绑定后调用共享运行时验证供给身份与种子，保持held状态，不执行准入。兼容独立研究仓和umbrella内嵌study两种Git路径。已存在输出或失败产物均保留，不因SSH断开自动重建。

## 使用与验证边界

在固定版本执行目录内，先安装经过审查的配置和sampling-plan并提交，再在正式容器调用：

```bash
python scripts/analysis/tfrl_banked_supply.py \
  --repo "$STUDY" --data "$DATA" \
  --name slurp-tfrl-current-bank-i2-h1-v1 --iteration 2 \
  --first-decision "$DECISION" --out "$PREPARATION"
```

两半组完成后，使用 `scripts/flights/nx/tfrl_current_supply_binding.py --iteration 2`，分别通过两个 `--preparation` 指向其complete.json。第3轮显式改为3。

测试覆盖实际银行加载及完整313条配置校验、准备入口写出、同一产物拒绝重建、准备失败/来源变化、绑定文件写出及真实Git历史读取；昂贵的运行时检索生产和绑定身份验证使用替身。测试不等于真实经验库、完整渲染或FIT已完成，也不构成性能结论。

## 部署绑定和评分登记补齐（21:28 UTC）

部署绑定入口 `tfrl_current_generation.py stage` 现支持显式 `--iteration 2/3 --first-decision ...`。原函数会覆盖为首轮shared-rollout标签；经验库轮次现在必须原样保留`tfrl-v2`及`context_application`，错误标签直接拒绝。仅更新选定模型/服务绑定与允许执行阶段，仍保持held。两半组均通过真实名单、经验库、首轮判定、供给文件哈希和绑定来源核验后才写配置。

评分登记 `scripts/flights/nx/tfrl_current_read_registration.py` 同样支持轮次和首轮判定参数，写入每半组七项完整官方评分配方及独立暴露记录，明确实际经验库请求审计。登记本身不评分、不启动推理。旧首轮参数默认行为保持。

顺序必须是：独立供给准备并绑定→提交→登记两半组评分配方→提交→部署绑定及执行阶段准备→提交→生成/FIT登记、共享供给重绑定、准入和完整预检。评分登记要求check-only，因此不能移到部署绑定之后。所有步骤只在新执行目录进行，当前冻结目录不改动。
