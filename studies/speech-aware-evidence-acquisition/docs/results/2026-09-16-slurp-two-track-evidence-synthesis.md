## Track A: candidate inclusion

Treat retrieval supply, generated candidate inclusion and final resolution as separate
events. The completed shared breadth replay matches K8 on every1080 row and raises own-card
availability from947/1080 atK8 to1040 atK32 and1074 atK60. That is retrieval coverage,
not generated-candidate recall. K32 uses roughly four times the knowledge bytes.

The completed K60/factored experiment is stronger evidence about task behavior than
the offline coverage curve. It adds only10 net covered candidates and does not improve
the full task. Its one-candidate responses rise from57 to255 despite broader knowledge.
The maximum-five experiment adds14 net covered candidates while some previously covered
rows lose their correct candidate. Neither creates a monotonic candidate superset.

Root inference: simple breadth is insufficient in the tested packages. The next useful
question is what distinct evidence changes a persistently missed hypothesis without
discarding a useful incumbent hypothesis. Possible factors remain unadmitted: preserving
and augmenting the candidate set, a named alternative observation, or construction-source
contrasts addressing a specific unresolved boundary. Do not choose a factor from
runtime-inaccessible gold or treat a shorter candidate list as calibrated confidence.

The completed exact-cohort numeric inventory identifies100 persistent candidate misses
across the anchor, maximum-five and broad/factored sources, plus60 persistently covered-but-wrong
intent rows and426 persistently correct-intent/nonexact-entity rows. Those intersections are
descriptive; different source runs and contextual consequences prevent component-level
causal attribution. Do not rerun the existing retrieval grid.

## Track B: intent resolution and entity extraction

Do not treat all residual errors as hearing failures. The released anchor has525
correct-intent/nonexact-entity rows:127 FN-only,134 FP-only and264 mixed. The complete
official loss decomposition attributes31.49% of FP+FN mass to residual unmatched reference,
28.82% to unmatched prediction,35.04% to same-type filler distance and4.65% to a heuristic
equal-filler type swap. These are loss shares, not disjoint sample counts or recoverable gain.

The temporal follow-up distinguishes an available-information gap from representation:
all84 rows with an unmatched reference date received the date card in both initial Solver
and Reviewer requests, and25 omitted dates also occur in candidate distinctions. The
latter remain hypotheses, not independently verified transcripts. Time errors frequently
involve representation or spans, while existing global cards do not fully specify
intent-specific annotation boundaries. Another ASR pass cannot be assumed to repair these.

The current package tests whether typed evidence/hypothesis separation and concrete review
findings make useful correction more likely. It does not test new acoustic observation or
new slot content. After its complete release, root will inspect:
- Correctness of delivered answers and all18 scenario strata.
- Candidate-missing versus covered-but-wrong intent cases.
- Slots on a common correct-intent subset, with malformed rows separately retained.
- Draft-to-final saves and harms, including full-task exactness and official partial quality.
- Supported issue versus insufficient-evidence versus malformed review, and whether the
  Planner routed an action that can resolve the declared issue.
- Actual new knowledge/evidence obtained, repeated lookup, and unavailable citations.

A validated schema, available citation or successful tool response is not verified truth
or useful information gain. Do not multiply critique count or context bytes as an objective.

## Actual current action boundary

The existing OpenJiuwen NativeEpisodeWorkflow already has bounded acquisition and candidate
refresh paths. The current frozen configuration does not enable either extension.
Planner receives ACCEPT/REVISE as its enabled action set; an acquisition action is exposed
only when an acquisition node is configured, and refresh only when explicitly registered.
Reviewer can invoke the task-contract or target-knowledge tool within its own current visit,
with a reporting turn reserved. There is at most one Solver revision.

Therefore the current experiment can test knowledge-supported correction and role context,
but cannot establish an adaptive acoustic-observation policy or recovery of missed candidates
through an executed refresh. Perception currently declares empty evidence_refs and
unresolved_fields; absence of those fields is a protocol choice, not evidence of certainty.
Semantic distinctions remain model hypotheses. The context module preserves and organizes
available state; it does not manufacture missing observations or become another answering model.

For postseal context attribution, separately check whether the necessary observation survives
the role transition. The current compiler retains the latest relevant review for Planner
and revision, and Reviewer retains its own current native tool call/result pairs. A later
Reviewer visit does not inherit earlier evaluative opinions or all old tool history.
This is an implemented selection rule, not proof that every excluded observation was
irrelevant. Inspect the sealed evidence/receipt chain before attributing a missed correction
to knowledge absence, model reasoning, or over-filtering. Do not alter the active policy
based on this static possibility.

The published historical agent base is also a useful reference for the new package.
The registered new primary is system versus its matched direct arm. Passing that primary
does not establish superiority over every earlier agent package. Preserve historical
agent comparisons as descriptive unless matched source and process conditions support
a stronger claim; explain any concrete quality/action-space tradeoff before adoption.

## Remaining scope of role-specific context engineering

The typed compiler currently selects and normalizes historical role states. It does not
filter every source of model context. The shared runner still renders accumulated
QueryState knowledge to later roles, and the current slot provider selects whole global
slot values. A selected value includes all authored intent-role bindings for that slot;
selection by current candidate does not itself project the value to that candidate.

Consequently, completion of the compiler and its tests is not completion of the owner's
entire role-specific information design. Preserve this distinction in reports. The current
experiment tests the implemented history-view package, not fully role-specific knowledge
projection or a semantically optimal filter.

Root hypothesis for later discrimination: useful stable slot guidance, current-intent role
meaning and neighboring-role contrasts may need different views. Some global context can be
useful, so dropping every unselected binding is not already justified. Inspect requested and
consumed knowledge after the current pair; use allowed construction sources for any new
view, preserve source hashes, and evaluate full task quality before adoption. Do not infer
this mechanism caused the existing errors merely because the context contains other roles.

   rewards and policy updates for training-free RL. These root-led engineering changes are
   not an algorithmic RL result.
