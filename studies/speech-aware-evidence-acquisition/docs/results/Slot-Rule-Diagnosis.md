# 错误槽位规则诊断与修复方案

本报告仅使用已保存的 TRAIN 证据，未访问 TEST 标签、未调用模型、未访问远程主机。公开报告仅保留聚合结论与机制解释。以下是静态证据分析，不是已实现或已验证有效的语义准入器。

## 结论与当前处置

**输出协议错误与错误知识是两个独立问题。** JSON 合法、引用存在，并不代表规则正确。已核验 compact v2 的三条反思直接违背各自参考答案：两条禁止 `news_topic`，一条禁止 `song_name`。这些规则不应进入可消费的知识库。已生成的历史响应、失败与费用必须保留，不能改写成成功。

目前最先应修复的是**知识构建时的证据归因和语义准入**，再验证消费端能否正确使用通过准入的条件规则。现有材料不足以把原始任务失败归因于音频感知、检索或 Solver 中的某一个环节；反思器未看到原始音频及完整供应证据。

51 组来源包含 204 条历史 rollout、138 种不同预测，严格成功为 **0/204**。零严格成功不意味着完全不能学习：可以从明确的 TP/FP/FN 提出局部纠错假设；但不能把较高部分奖励的答案当作正确示范，更不能直接晋升为全局规则。

## 已核验的问题

三条已保存的 Reflexion compact-v2 规则直接违背其 TRAIN 参考答案：两条建议禁止 news_topic，一条建议禁止 song_name。新闻样本中，意图正确可独立贡献0.5奖励；删除错误主题虽然减少FP，必要主题仍为FN。歌曲样本中，删除错误 song_name 使奖励从0.7升至0.75，但TP没有增加，必需歌曲仍缺失。这不能支持全局删槽规则。

另有一条“人物新闻优先 person”的局部建议没有被本例直接反证，但尚无跨样本支持；不能为修复错误而反向硬编码每条新闻必须有 news_topic。已有72条ADD审计中，没有逐规则机器可检验的支持关系；8项发现包括5项直接冲突、2项跨规则冲突和1项过度泛化。

## 修复顺序

1. 从评分所用的预测、reference和轨迹身份派生 IntentExact、实体TP/FP/FN及严格成功，禁止模型改写这些证据。
2. 候选声明意图范围、可观察条件、目标槽位、操作及逐条支持引用；自由文本规则先隔离，不自动发布。
3. 对可机器验证的无条件删槽/必填规则检查支持样本与同范围反例；未声明、不能验证的条件标为未验证。无反例也不等于普适正确。
4. 覆盖原始数据真实存在的槽位组合，加入有/无槽位、边界和类型对照，不做意图×槽位笛卡尔积。
5. 冻结候选后在独立开发集报告repair/break、官方指标和全部成本，再决定是否进入消费端。

## 当前实现边界

本次静态诊断只使用已保存TRAIN证据，没有读取TEST标签或新增模型调用。结构化CPU准入模块正在实现；尚未上线，尚无精度收益证据。旧提示已提醒“部分奖励不是正确证据”，因此不能把追加提示当作完整修复。全量评估运行仍冻结在已有A0知识版本，不接入探索中的规则。
