# TFRL/RSI 后续算法计划

## 开发集与学习目标

开发集从固定原始数据集无放回采样，按开发集失败率选择难例，并按数据中真实存在的 intent-slot 关系覆盖，不构造笛卡尔积，也不读取测试标签。训练集、开发集和测试集身份固定后跨实验共享。最终测试仍使用完整 13,078 条，测试集不参与调优。

当前优先优化知识消费：检索排序、提示中的证据组织、候选筛选和答案约束。知识构建只在出现可复核的缺失、冲突或覆盖不足时修改，并保留原始 provenance。每个候选改动必须同时报告总体指标、难例指标、意图/槽位分层指标和多模态回归。

## 算法路线

1. 先锁定冻结模型的首轮系统收益和真实成本；
2. 用已验证轨迹计算 outcome/step credit，过滤重复、无效和未完成轨迹；
3. 以 advantage-weighted preference 或 rejection sampling 形成 CPU 侧候选，先做离线 replay；
4. 再评估 training-free RSI 的知识构建/消费改动；
5. 若离线收益稳定，再准备 verl LoRA 分支：冻结音频塔、视觉塔和投影层，只训练主模型适配器，并保留多模态回归；不把环境准备当作训练成功。

验收要求：固定开发集提升达到预注册阈值，难例收益不能由少数意图贡献，测试集只在最终候选锁定后完整运行；所有训练或推理轨迹、token、成本和 checkpoint 都必须有唯一身份并支持断点恢复。
