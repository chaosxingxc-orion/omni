# TFRL学习信号与探索决策

## 核验结果

对固定51组、204条历史轨迹展开组内证据引用，核对rollout与反馈奖励一致性，在固定镜像内完成零模型调用审计。来源哈希与完整证据审计相同；本次不重新生成轨迹，不修改官方评分。

| 核验项 | 实测结果 | 对探索的影响 |
|---|---:|---|
| 严格成功 | 0/204 | 只用二元strict奖励没有组内学习信号 |
| 连续奖励存在组内差异 | 51/51组 | 已有数据足以开始相对反馈分析，不必先等待成功轨迹 |
| 组内唯一scored输出 | 146/204 | 58条重复结果可以压缩表示，不能删除其成本或统计权重 |
| 无权去重改变组均值 | 37/51组 | 保留multiplicity；唯一答案等权作为独立算法消融 |
| 只有一个唯一输出的组 | 0/51组 | 本池不存在因此需要整组跳过的情况 |
| reference意图不在P候选列表 | 15/51组 | 是候选召回的观察项，不是Solver信息缺失或无法答对的证明 |

连续奖励为既有开发反馈 `0.5 * IntentExact + 0.5 * ExactSlotF1`，不是最终官方综合SLU分数。所有组的非零差异说明相对排序有信号，不证明提炼出的规则正确、可泛化或能提升系统。

## 对旧外部研究的修正

旧报告估计约54条重复，本次精确核验为58条。旧报告估计约14组意图候选缺失，本次按原始完整intent_id精确匹配为15组；此计数不处理语义相近标签，也不作语义归因。完整任务说明还提供合法标签全集，供给知识与实际请求也必须一起看，不能把P shortlist当作Solver全部信息。

不采用“reference词未出现在distinction→程序判定供给错误→禁止该样本学习”的硬门禁。它将文本匹配误当语义根因，可能把知识消费问题误排除。程序负责可核验的字段、来源、结构和计数；模型分析语义机制，NPU受控对照验证可修复性。

完整证据仍有边界：`raw_speech_query`明确标记为文本学习省略音频；原生请求控制历史中的`development_canonical_json_string`是存储编码，后续输入组装应按既有编码契约还原或保留可解释表示。取回request字段不等于取回音频，也不代表本轮重新验证原生所有字节。

## 下一轮安排

1. TF-GRPO先利用现有连续相对反馈提出知识构建与消费候选；不将reference编辑得到的理想答案伪装为成功rollout，不将部分奖励描述为成功示范。
2. ACE和Reflexion收到同样完整的实际输入证据，但保持各自反思整理或记忆更新流程；不用新增归因门禁阻塞实验。
3. GEPA按实际完整输入提出多种提示干预，配对观察repair/break及官方指标。外部旧研究是一份设计报告，不能直接冒充可部署mutation bundle。
4. 轨迹去重仅先用于压缩上下文并保留原始次数、来源与奖励。改变样本权重的版本单列候选，与原权重版本比较。

这份审计解除了“strict全错，所以先补成功样本才能开始相对学习”的潜在等待；没有解除候选产物尚未交付的实际缺口。模板、外部prepare/run/collect与A lane衔接子任务多次只返回规则确认，均未验收并退回，不计入完成或队列。
