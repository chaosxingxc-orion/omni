# ACE runtime projection

A teacher response may contain one complete `json` code fence. Collection unwraps only that exact envelope; surrounding prose, multiple fences and invalid JSON remain errors. The original response, wire digest and request identity are retained and replayed.

ACE operations containing development provenance cannot enter a Solver template. A compile specification may pin `runtime_projection`, a `saea-ace-runtime-projection-v1` document binding the original proposal digest, reviewer, rationale and every operation's condition/content/exception source digest. Each field lists ordered, disjoint character spans retained verbatim. This is an explicit researcher-authored projection, not a claim that the teacher emitted the projected text. It cannot insert new text; removing text still requires semantic review.

Preview artifacts retain the complete teacher proposal, projection and projected runtime proposal. Source replay rederives all three and the deduplicated items. Published release reviews bind the resulting candidate digest. The projection does not authorize a candidate, prove generalization or implement programmatic applicability gating. Check target coverage and unrelated controls before NPU evaluation; never inject diagnosis IDs or reference answers into runtime context.
