# TFRL样本、轨迹与决策信息充分性

## 结论与证据范围

当前没有证据证明模型已经获得完成每项研究决策所需的充分信息。需要先审计实际请求，再诊断模型；上下文很长、字段完整或序列化可还原，都不等于模型容易理解、能定位证据或拥有因果证据。此前把无效知识ID笼统称为模型凭空编造不准确。

主线程核查了源样本统计、分区实现、三份真实失败请求/响应、构建材料投影及GEPA反思来源。以下区分实测、已识别缺口和下一步方案；尚未完成所有节点逐条审计。

## 信息供给与知识质量必须分开

| 问题 | 已有证据/缺口 | 应怎样处理 |
|---|---|---|
| compact材料省略关键输入 | 历史compact投影仅保留query中的sample_id/history/audio标记，省略task_instruction/supplied_evidence等；完整视图已补回 | compact不能承担完整因果诊断；保留为消融，开发默认应有足够节点材料 |
| 字典引用与可编辑知识混淆 | 真实Curator current_items={}，但证据字典有e5；模型MODIFY e5。e5确为历史检索的意图说明，不是可编辑经验ID | 明确只读背景知识、证据引用、可编辑增量库三者；提供允许操作/目标清单，以及“修基础知识”与“加消费经验”分别能做什么 |
| 压缩无损不等于易理解 | full-query将重复子树变为e0/e1等引用，系统和任务消息嵌在source_messages内，含多层JSON | 面向模型提供按节点组织的证据视图和局部展开；完整原件保留。比较同信息的不同呈现，不拿省tokens当目的 |
| 缺少听觉证据 | 构建反思为文本路径，audio_inspected=false；只有diagnostic分支明确提供TRAIN参考转写 | 分析声学错误时按需给原音频/片段及P实际产物；参考转写标为诊断真值，不能假装模型当时听到了它 |
| 缺少因果对照 | 当前知识是在历史轨迹产生后构建的，generator_item_exposure_verified=false | 不能要求反思器证明这些新知识导致旧错误；安排当前策略真实重跑、单节点干预和负例，再更新helpful/harmful证据 |
| 知识内容错误或过度泛化 | Reflexion47条规则中37条依赖运行时不可得参考；出现只要提到食物就改意图的泛化建议 | 提供原任务定义、易混意图边界、支持例和反例，验证条件—动作—例外；格式修复不解决规则真假 |
| 消费证据不足/使用失败 | GEPA已有完整文本请求、感知状态、原始与交付答案、官方反馈；反思器未直接听音频 | 逐样本查正确知识是否构建、检索、呈现、采用、交付保留；当前不能给出两类错误占比 |

## 调整后的实验设计

1. **冻结已有样本，先补信息审计。** 不反复重抽。为实际请求形成矩阵：任务定义、可用动作、音频/P产物、候选意图/槽位说明、知识内容与来源、排序、原始输出、交付变化、反馈及历史暴露。每项标已提供/缺失/仅开发可见；缺关键项时输出“证据不足”，不硬判模型原因。
2. **建立稳定覆盖表。** 在现有TRAIN池按原始标注的意图与实际槽位模式统计覆盖，不做笛卡尔积。学习锚点保持难例；选择邻近反例是验证适用边界，不是按SFT比例混入易例。确认缺口后一次性扩展版本化名单，多算法共享。
3. **增加有信息增益的轨迹。** 将现有4条作为起点；对不确定或可干预的难例先补到8条，仍有新路径时再到16条。这是下一实验建议，非已完成配置。优先新证据、不同节点干预和修复路径；原样重复只用于估计随机性，不能冒充策略探索。报告独立P次数、Solver分支数、独特决策路径和新增正确率。
4. **先比较信息供给，再比较学习方法。** 同一难例与固定模型，对照当前输入、补全必要信息、同信息改为清晰节点视图、加入成功修复及反例四类干预；每次明确改变项。检验信息补全后是否能得到正确决策，之后才判断TF-GRPO/ACE/Reflexion/GEPA的学习差异。
5. **扩大GEPA反馈覆盖。** 不再以每候选2条反馈代表整个问题。使用固定分层小批次逐步覆盖233池，按真实上下文容量组织多次反思及候选验证；保留每例关键证据。完整16条对照先定位机制，再在80条内部选择/312条开发回归检验，报告重叠与暴露。
6. **以系统主指标验收。** 首GEPA候选代理奖励略升而官方SLU下降，已经证明单一代理奖励可能选错方向。并列官方SLU、Intent、strict修复/破坏、分层表现及重复运行不确定性，不用一次小批奖励决定晋升。

## 用干预区分知识构造与信息供给

把每个错误沿链路定位：原始标注/任务定义 → 知识生成 → 存储与检索 → 交付上下文 → 模型决策 → 程序解析与最终答案。当前没有逐样本完成这条链的审计，不能给出各类根因占比。

- **知识构造缺陷**：条目事实或语义不正确、适用条件缺失、槽位规范化与原始定义冲突，或规则依赖运行时不可见的参考答案。先确认原始数据定义，不能直接把单条标注当普遍规律。
- **信息供给缺陷**：正确知识已存在，但未检索到、被截断、引用未展开，或未提供相近意图的区分依据。修复检索、组织或交付；不能据此断言模型不会推理。
- **信息呈现缺陷**：内容存在但对象边界混淆、优先级不清、冲突无解释。e5事件属于这一类的明确风险；尚需对照证明明确命名空间是否改善结果。
- **模型决策问题**：关键证据已核验送达且可理解，在控制信息和知识条件后仍选错；这才是知识消费策略的重要优化对象。仍保留多因素与“证据不足”，不强行单因归责。
- **程序错误**：接口违反约定、错误解析、交付时丢失模型已正确给出的内容。用回归测试修复；模型的错误语义判断本身不算程序bug。

对可疑样本做2×2对照：原知识/修正知识 × 原供给/补全供给。同一音频、感知产物和解码配置内比较。固定知识只补供给能修复，支持供给瓶颈；固定充分供给后改知识才修复，支持知识缺陷；两者共同作用则报告交互，不能简单相减当独立贡献。上述是后继设计，尚未运行。开发诊断可用TRAIN参考转写定位感知问题，但参考转写带来的提升只算诊断上界；上线验证必须仅使用运行时可得信息。

## 模型作决策前应收到什么

构建模型需要：原任务和意图/槽位定义、实际节点输入输出、错误评分差分、可编辑知识及操作范围、证据来源、支持例与相近反例。消费模型需要：用户语音/P产物、相关知识与候选边界、来源及冲突说明、合法槽位及输出要求。开发参考答案与运行输入显式分开。

由程序生成节点证据包，分类、去重、展开相关引用、记录截断和缺项；模型据此提出解释、请求补证并选择干预。去重必须保留来源、例外和冲突。先确保关键证据完整，再按相关性分层；不以减少系统推理tokens为优化目标。信息不足的样本进入补证队列，避免无依据地再反思一次。

## 轨迹分配与算法安排

固定51条难例是起点，保留现有204分支；先登记每条的独立感知次数、共享感知分支、正确节点、奖励差异、信息缺项和重复路径。对全错组，组内相对奖励仍可能区分局部改进，但不能学习出并不存在的完整正确路径。扩到8/16条应由新证据或新干预驱动；停止条件是可行干预已检验、重复路径不再增加信息或达到预设预算，预算用尽仍未修复也必须记录。

TF-GRPO继续作为组内相对反馈基线，审查优势信号是否真的对应任务改进；ACE检验逐步知识更新；Reflexion作为反思记忆参照；GEPA检验基于轨迹反馈的消费策略搜索。四者共用可追溯样本、证据包和评测器，分别记录任务rollout、学习调用及候选验证成本。近期实际新结果集中ACE/GEPA，不能声称其他算法已有同步新轮次。

233条反馈池保持固定，按照原始意图与真实槽位模式组织批次，逐步扩大每候选可见的支持例和反例，不再默认只取前2条。80条选择池与51条构建池重叠14条，联合实验必须标记开发暴露；若需要独立选择，应一次性版本化划分并保留旧名单，不能将重叠数据说成未见数据。16条用于机制验证，312条用于开发回归，TEST13078不参与策略选择。
