# 多模态系统强化学习：两阶段路线与功能交付顺序

状态：依据用户最新业务约束执行。当前处于第一阶段；第二阶段生产LoRA训练暂缓。本文区分功能目标、实际完成度和后续实验，不把规划当成果。

## 第一阶段：系统构建与Training-Free RL轨迹优化

目标是形成可运行、可评价、可迭代的多模态系统。冻结模型参数，通过系统策略、知识构建和知识消费改善轨迹与任务结果，同时稳定采集后续学习需要的数据。

最小业务闭环为：固定真实输入→感知/检索/推理→正式评分→错误归因→有证据的知识更新→候选冻结→配对开发评估→采用或回退→在实际采用版本下采集下一轮轨迹。每个箭头有可追溯输入输出和测试；单轮生成经验或分片完成不等于RSI闭环完成。

现有参考为[Training-Free GRPO](https://arxiv.org/abs/2510.08191)，本地四阶段提示和实现出处见[归属说明](../../reference/tfgrpo/NOTICE.md)：轨迹摘要、语义优势、组更新、批次综合。密集奖励、共享感知及分片综合属于明确的本地适配，不宣称原论文效果已复现。

当前优先补齐以下功能：

| 功能 | 当前事实与下一交付 |
| --- | --- |
| 共享运行入口 | 三片真实FIT、生成和封存完成；生产依赖修复153项回归通过；最终融合123项相关测试和真实prepare通过，生成终态待核验 |
| 证据与融合 | 204条轨迹语义核对完成，72项提议发现至少5项直接反例；融合功能已实现，真实候选语义审查及配对评估待完成 |
| 学习信号 | 174个全错组中51组有部分奖励差异，123组同分；同分组进入诊断，不制造优势或无限重复采样 |
| 固定难例与验证 | 复用625条固定候选及历史证据，完成难度确认；按原标注实际关系覆盖，不能把多样性名单直接称难例集 |
| 版本闭环 | 完成候选配对评估、自动保留/回退和真实跨轮采集；逐轮记录父策略、知识版本、奖励与累计成本 |

首先只改知识构建，固定消费及其他组件。已有错误包括条件丢失、类型混淆和规则冲突；先检验具体修复能否改变任务答案。构建基线锁定后，再独立比较知识key/value描述、检索排序、消费提示及结果筛选，避免多个组件同时变化导致无法归因。

奖励目前为0.5×IntentExact+0.5×ExactSlotF1，用于TRAIN内学习信号；最终仍用官方pooled SLU-F1与Intent验收。相对最高奖励但仍错误的轨迹不当正确示范。感知证据不足、检索未命中、规则错误和消费错误分开诊断；参考答案只供学习归因，不能注入被评估推理端。

H2已多次用于开发选择，继续诚实标注开发用途。既有筛查门槛SLU至少+1pp且Intent不下降保持；通过后还需更大固定开发验证、回归分析和配对不确定性报告。方法冻结后使用完整13,078条test；历史采样报告没有参与调优，不因此判废test。

## 第一阶段的功能基线与质量收敛

先为上述功能的成功、边界及失败行为建立用例，通过共享入口完成真实小规模闭环；再集中验证断点续推、异步持久队列、故障恢复、长期稳定性和有效吞吐。已识别的实验正确性缺陷随功能交付修复，不以全套工程优化完成为算法讨论的无限前置条件。

NPU执行与CPU准备、评分、分析持续异步。三次综合调用本身不足以填满8卡，需要提前准备有独立研究价值、配置兼容的后继工作；没有足够任务时报告空档及原因，不用重复无效实验填充负载。已有明显效率改进时先安全优化，再接续实验。

通用质量要求见[功能基线与非功能质量工程规范](../../../../docs/engineering/development-and-quality-contract-zh.md)。

## 第二阶段：LoRA系统级强化学习

第二阶段依赖第一阶段稳定的系统执行和轨迹采集，将系统目标映射到可训练的模型决策。LoRA是参数高效更新方式，具体RL算法、训练数据接口和奖励分配仍需独立验证；不能将一次回答微调称为系统级RL已完成。

范围为主模型适配器；音频塔、视觉塔和既有投影/对齐参数冻结。复用多模态特征管线，但保留音频的长度、mask和位置语义；冻结模块并不能替代多模态能力回归测试。

第一阶段向第二阶段交付的轨迹契约至少包括：

- 数据/媒体、模型、策略、知识及解码配置身份，episode与各决策的关联。
- 实际模型输入、输出token或可核验原文、动作/工具调用、环境反馈及终止原因。
- 正式评分使用的规范化答案、奖励分量和来源；区分模型输出与后处理。
- 成功、失败、截断和未知状态，以及完整成本、断点、来源和隔离角色。
- 需要策略比率的算法所需行为策略概率信息；未采集时明确缺项，不从旧自由文本伪造。

历史轨迹可用于错误分析、数据筛选和合格的监督初始化。GRPO等在线/近在线方法仍需在对应当前策略下采样；旧TFRL轨迹不能直接充当当前策略rollout。无需每条预先正确，但需要可信奖励、足够有效差异及真实多模态输入；全组同分需识别而非虚构梯度。

进入第二阶段的技术条件：第一阶段闭环和轨迹契约验收通过；关键恢复测试与连续真实运行证明采集可靠；训练环境完成生产模型真实音频单步反向、adapter保存/恢复/回灌和资源测量；固定多模态回归基线可用。这些是技术验收条件，不另造反复人工审批。保留现有verl环境成果，当前不切换NPU到生产训练。

## 当前结果与下一轮验收

最近Dense候选相对lock仅+0.6729pp SLU，Intent下降1.6026pp，未晋升；第一阶段尚无稳定TFRL收益。下一轮优先完成有证据的构建/融合/评估功能闭环，锁定特性测试，再集中完善非功能质量。若候选失败，保留lock、记录失败原因及成本；不以写出更多经验、增加loop或收集更多同分轨迹充当优化成功。
