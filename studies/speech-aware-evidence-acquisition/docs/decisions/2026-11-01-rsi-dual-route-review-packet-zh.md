## 2. 固定数据、难例与评估边界

现有 construction625 来自 SLURP TRAIN，固定分为 H1 313/H2 312。当前 TF-GRPO 学习取 H1 中四轨迹二元奖励有正有负、并落在固定 A0-error439 名单内的32组，共128条轨迹；H1全部 mixed 导出52组。当前 H2312 的用途是完整开发比较，不能把学习32组与开发312条混报为同一进度分母。

这份32组是**可学习对比子集，不是已证明的完整困难分布**：两次共享感知求解不能估计完整系统的高频错误概率，代码也明确记录 `independent_full_system_repeats=0`；mixed 筛选排除了全错组，存在选择偏差。后续固定困难训练集应在 TRAIN 内按原始 utterance 分组，记录独立完整系统重复的正确率及不确定性，再按原始 scenario、intent、slot 类型和实际出现的 intent–slot 关系核查覆盖。通常正确的样本放回归集，不为 TFRL 人为混入固定正确配比；缺少某关系的真实难例须报告空缺，不能用笛卡尔积或合成记录补齐。

沿用固定清单和内容哈希，多实验共享原始数据与缓存。分组校验须覆盖 sample、utterance、音频内容及知识库来源；[本次固定总体审计](../results/2026-11-01-tfgrpo-population-audit-zh.md)确认 H1/H2 在样本、原始语句、固定音频哈希与规范化文本上均无重叠；仍不证明知识库来源与历史方法使用独立。32学习样本仅覆盖22/60个意图、14/55类槽位、26/432种实际意图—槽位关系，H2仅覆盖115/432种关系，不能宣称困难分布已完整覆盖。H2和Fold A有历史分析/方法使用记录，应如实披露；不因它们相对本轮 H1 分离就称“从未接触”。扩展训练名单须独立版本化，不根据 H2 错例把其转入训练。

最终冻结方法后报告完整 **13078条 test**。此前对 test 的采样汇报本身不等于调优或不可使用；当前任务按用户说明没有据 test 调优，继续保留完整 test 评测计划。后续禁止据其结果选择提示、阈值、adapter或停止轮次。

实现证据：`scripts/analysis/tfgrpo_seed_groups.py`、`tfgrpo_learning_job.py`、`tfrl_uncertain_credit.py`、`tfgrpo_h2_read.py`。

## 3. 路线 A：Training-free RL based RSI

### 算法与实际更新对象

参照 [Training-Free GRPO 论文](https://arxiv.org/abs/2510.08191) 和 [Tencent youtu-agent](https://github.com/TencentCloudADP/youtu-agent/tree/training_free_GRPO)。当前引入的是主线提交 `c2caa539f4c95ae1c39ed24dc8a99cb3651e1d5d` 的四阶段提示及流程，不能冒充论文分支逐字节复现或已复现其效果；归属、差异见 `reference/tfgrpo/NOTICE.md`。

执行链为轨迹摘要 → 组内语义优势 → 分组经验操作 → 全批经验合并。冻结模型提出 ADD/UPDATE/DELETE/NONE，确定性程序验证结构、冲突、大小和来源，发布不可变候选。二元奖励为 **Intent exact 且 exact-slot FP=FN=0**；它提供成败对比，不等于官方距离度量 SLU-F1。当前只处理 mixed 组，全对/全错组跳过，不能声称对最困难全错样本已有学习能力。

第一轮只改变 Solver 消费提示中追加的条件经验，保持感知、知识池、检索、排序、答案选择及模型权重固定。更新的是经验知识的构建，效应通过知识消费呈现；并未同时优化基础知识库 key/value。反思输入是原轨迹的文本投影，音频被哈希替代，不得推断未记录的声学事实或把模型补写的解释当作真实推理记录。

策略版本至少绑定：模型、完整提示、经验候选及父版本、知识池/检索/排序、解码参数、输入投影和奖励版本。后续轮次必须用当前经验策略重新采样，不能把空经验历史轨迹重标为新策略数据。失败或未知请求保留成本与状态；已观察阶段可核验复用，最终合并截断不能靠程序补括号假造模型结果。

### 归因、接受与下一次改动

完整 H2312 每条共享一次新感知，分别执行 learned Solver 与 lock Solver，正常936次生成；通过共同输入把当前比较限定为知识消费增量。主门槛为官方 pooled SLU-F1 至少 +1pp 且 Intent 不降，官方计数合并，不平均分组F1。当前分析提供按原始 utterance 聚类、scenario 分层的10000次配对 bootstrap；该区间只表达名单采样不确定性，不覆盖独立解码波动，数字过门槛不等于已接受或稳定收益。

首轮结果前提出的重复次数、停止条件与失败分支见[后续比较协议草案](2026-11-01-rsi-next-evaluation-protocol-zh.md)，需Astra审查后登记。候选通过开发门槛后才启动独立重复/确认；不通过则保留失败结果，定位信息覆盖、经验冲突或上下文开销，不能在同一 H2 上无限改提示追分。下一版只选一个组件：经验生成/压缩、key/value表示、检索排序、消费提示或结果筛选。先保持其他组件固定；若声称构建与消费交互，再登记两因素实验。已有 odd40 证据供给审计只证明内容不同，不能替代其精度实验。

稳定收益验收应同时包含：完整官方分数和区间、修复/破坏条数、原始标签覆盖、至少独立解码复验的方向一致性、每条调用/tokens与墙钟成本；重复次数和停止规则在新结果前固定。代码：`rails/tfgrpo_learning.py`、`tfgrpo_runtime.py`、`tfgrpo_consumption.py`、`scripts/analysis/tfgrpo_h2_read.py`（rails 位于 `src/speech_aware_evidence_acquisition/`）。

## 4. 路线 B：RL based RSI，主模型 LoRA

### 模型、数据与算法选择

沿用现有 Thinker 主模型，首个候选范围为48层注意力 q/k/v/o 共192模块，rank16、alpha32、dropout0，13,369,344可训练参数。音频/视觉塔、已有投影、embedding、lm_head及MoE基座参数冻结；显式完整模块名白名单并核验全部梯度，不能使用会误命中音频塔的宽泛正则。冻结这些参数不保证主模型更新后多模态能力不退化。

先准备真实输入的 response-only SFT 对照，再比较 verl 的 GRPO 路线（算法参照 [DeepSeekMath](https://arxiv.org/abs/2402.03300)，实际配置以固定 verl 源码为准）。SFT只用经官方标签核验的正确回答，历史轨迹可以作为离线数据；RL每一轮必须来自当前 actor/adapter 的真实 rollout。第一轮提案固定四候选组，成败二元奖励沿用路线 A 便于对照；不同时搜索奖励权重。组内优势用 `(r−组均值)/(组标准差+epsilon)`，对同奖励组按固定规则跳过策略梯度，保留数量、资源与全错类别报告。组大小、epsilon、裁剪、KL、学习率和步数均写入一次性 pilot 配置，在真实显存/梯度探针后锁定，**当前没有已准入的数值训练配置**。

正确轨迹不是一般 RL 的逻辑前提，但本方案的二元 GRPO 要有组内奖励差异才产生任务优势；全错组全零无法提供此信号。不能删除全错样本后声称解决了它们，也不能把gold答案补写成“模型成功rollout”。全错处理单独比较：更有效的证据、受预算约束的探索，或来自训练标签的明确 SFT 预热；引入连续槽位奖励或教师示范属于新方法，须分别标注来源和评估。仅正确终答也不能证明中间解释可靠，不训练反思模型编造的思维过程。

### verl 接入与一致性门槛

复用多模态字典、FSDP和损失框架，增加原生音频 Processor、feature mask、占位展开与 Omni RoPE 适配；不能以伪造图像尺寸代替音频位置。先关闭 remove-padding/packing/sequence parallel，真实权重 raw音频与冻结特征输入前向对齐后再逐项优化。视觉含 DeepStack，现有音频边界遇到 image/video 会拒绝；视觉回归须走正确原生路径，不能假定当前缓存支持视觉。

rollout档案必须绑定原始消息、音频/缓存哈希、精确token IDs、终止原因、attention/position/response mask、采样参数、行为adapter版本及对应log-prob。API只留下终答而丢失实际采样的reasoning tokens时，不能重分词终答后宣称恢复了完整on-policy轨迹；需补齐采集，或明确注册新的不含该段的策略。组内所有轨迹来自同一策略，训练开始前核对初始ratio接近1、rollout与trainer逐token log-prob一致，单独解释数值容差和sampling变换。

GRPO保留冻结reference的KL约束、裁剪目标及response mask；经验提示版本在参数更新期间固定。只有保存adapter后，rollout引擎完成所有实例的版本确认，下一组才能使用新策略。禁止新旧adapter混组，禁止沿用旧decoder KV。冻结塔特征可以跨adapter复用，但cache key必须包含音频、预处理、塔/投影权重、代码、dtype、分块和样本顺序；模板/长度/mask仍按每条新轨迹重建。

### 最小工程验收与效果比较

1. 加载真实checkpoint并核验 `thinker.` 前缀；真实音频前向有限，LoRA有有限非零梯度，冻结参数更新前后哈希一致。
2. 单步保存/恢复包含adapter、优化器、scheduler、RNG、数据游标、rollout/策略版本及缓存manifest；中断后不重算已封存组，不漏算历史成本。恢复后的下一步与连续执行在声明容差内一致。
3. vLLM接收adapter并核验实际生效；基座、SFT LoRA、GRPO LoRA使用相同开发名单、输入与解码协议，报告预算差异。先测固定经验条件下参数更新，联合TFRL+LoRA作为后续独立因素。
4. 对主任务采用同一完整 H2 门槛与独立确认要求，同时固定音频/视觉/文本回归名单；具体回归任务、基座分数及非劣界限尚待登记，不能将“塔冻结”替代回归结论。test只用于冻结后的完整报告。

现状和代码见[环境报告](../results/2026-11-01-verl-omni-environment-zh.md)、`scripts/environment/verl_omni/`。上述训练闭环尚未实测，本文不启动参数训练。

## 5. 8卡调度、效率与持久化

当前推理工程配置为2×TP4、每实例128序列、batch tokens2048、context49152。两实例驻留不等于8卡满载。最终合并的单请求依赖点已完成，H2已完成312条并释放，下一有效任务尚未准入；不要为占用卡而重复无信息的样本。CPU异步准备输入/奖励/官方评分，NPU按可执行任务队列接续，采用终态事件或约600秒监测。

RL显存与吞吐尚未测量，不能许诺在两套驻留TP4之外叠加训练。先以独立资源窗口测8卡主模型训练可行性，再比较训练/rollout分时切换与空间分卡的有效样本/卡时；切换须排空已知请求、保存权重版本、释放资源并验证重载。若上下游异步，按版本队列消费，不能以吞吐为由混入过期策略轨迹。

热日志、attempt、checkpoint写本地持久盘并保留fsync，开发机异步归档；唯一共享guard及旧执行器围栏保持。归档水位、文件哈希、权威副本与恢复规则必须明确；活跃快照不是自动可恢复检查点。当前局部恢复验证不能推论任意断电/故障均可恢复。

每轮报告完成数据条数/固定总量、端到端墙钟秒/条、P/检索/FIT/排队/HTTP/解析/持久化耗时、卡数/实例/并发、剩余量及基于已测阶段的ETA。累计阶段区间不能相加为墙钟；新推理、历史复用、失败消耗、tokenizer与CPU评分分账并保留总成本。

## 6. 要求 Astra 主动尝试推翻的检查

| 质疑 | 最小反例或检查 | 修复验收 |
| --- | --- | --- |
| 经验更新只是复述标签 | 检查规则能否反推出学习样本实体；比较条件经验与预登记无信息/错配对照 | 无答案泄漏，收益不能仅由额外上下文或随机性解释 |
| 32组无法代表稳定难例 | 完整系统重复正确率、全错组比例、原始标签覆盖缺口 | 固定困难名单与覆盖报告；不把shared-P重复当全系统重复 |
| 奖励改善而主指标退化 | 二元成功率与官方SLU-F1逐条/分层方向不一致 | 保留官方主指标和停止门槛，奖励改动单独实验 |
| H2被反复选择过拟合 | 汇总所有候选、读取次数和停止决策 | 披露开发使用，冻结方案后独立确认；不隐去失败候选 |
| 语音感知错误被归因于Solver | 保持/替换感知的受控实验，审查反思是否臆测音频 | 明确可观测边界，只对已干预部件作因果结论 |
| LoRA训练的不是采样策略 | adapter版本、完整tokens/mask、逐token log-prob与初始ratio检查 | 无混组、无隐失采样段、可复现实测容差 |
| 冻结塔仍损害多模态能力 | 固定基座对照的音频/视觉/文本回归 | 各回归通过预登记非劣界限才接受adapter |
| 恢复“省成本”实为漏记 | 请求intent/response、祖先成本、归档水位、实际训练游标核对 | 未知不重发，已知不重算，失败成本与恢复来源完整 |
| 所谓持续满载只是驻留 | 逐卡实际活跃、队列空档、有效样本/卡时与GPU/NPU等待 | 优化后质量不降且有效吞吐提高，明确串行依赖开销 |

Astra输出需逐项提供严重程度、精确证据、反例、修复建议和可执行验收；父线程落实阻断问题，再交同一独立审查线程复核。尚未完成的RL参数、数据与回归登记应作为审查对象，不能通过文档措辞认定已解决。
