# TFRL外部长上下文学习模型方案

## 判断与实测依据

建议优先让外部长上下文API承担开发态知识构建、跨轨迹反思和消费策略搜索，保留NPU上冻结的Qwen3-Omni执行感知与任务决策，并验证学习产物的实际收益。当前4条完整GEPA反馈输入66824 tokens，加16384输出预算需83210，超过原生65536。这个数字使用本地tokenizer；候选API须重新计数。128K可作为首批容量候选，256K及以上更利于扩大反馈，但不能仅凭窗口大小承诺覆盖多少样本或效果。

参数冻结的外部教师辅助优化仍可作为training-free系统优化；需单列teacher-assisted分支，与同模型自改进分别汇报。不能把教师自身更高的答题精度当成本地执行系统的收益，也不应将冻结模型选择校验简单删除。

## 代码现状与需要的接口

现有core/model/transport.py将端点限制为本地loopback，绑定真实服务会话，HTTP请求只配置Content-Type；GEPA preparation要求学习模型与seed的model_lock_key相同。因此换base_url不足以完成接入。

按依赖倒置新增外部learner provider，与本地executor分别配置身份、协议、上下文、输出预算及计费。复用算法的证据构造、候选校验和成对评测，不把API伪装成本地vLLM，也不绕过原校验。认证只引用环境变量或私有文件；请求存证去除认证头。根据提供商实际协议处理thinking、JSON schema、usage、缓存和错误返回，不无条件透传vLLM参数。

## 首轮实验

1. 收到API配置后核验实际模型版本、输入/总上下文/最大输出、是否支持音频、结构化输出、限流及定价。文本API可以分析文本轨迹，但不能声称听过原音频。
2. 使用同一固定2条反馈，对照本地与外部学习模型，控制证据、任务及候选评测；隔离教师更换因素。
3. 在外部模型内对照固定2条与完整4条反馈，随后按真实分布扩展8/16条支持例与反例；以实际token计数决定批次，不截断必要证据。2与4比较只代表这组反馈的扩展效应。
4. 所有知识/提示候选交由同一本地executor在固定16条进行成对评测，报告官方SLU、Intent、strict修复/破坏；再进入开发回归。TEST不作为学习输入或选择依据。

同一教师跨不同信息量与同一信息量跨不同教师分别比较。后续TF-GRPO、ACE、Reflexion、GEPA采用显式教师身份、样本暴露和学习预算，避免把更强教师优势归为算法优势。

## 调度、成本和恢复

API学习队列与NPU任务队列异步，通过候选产物及来源hash连接。API反思期间NPU继续固定任务、验证和其他已准备探索。CPU独立准备下一批证据。记录provider/model版本、请求ID、请求/响应摘要、输入输出及可用的缓存/推理tokens、耗时和费用；未知用量不补零。明确每轮费用、并发、TPM/RPM及超时上限。

请求先持久化，响应落盘后推进状态；超时或断链不自动认定请求未执行。优先使用服务商幂等键或可查询任务ID，无此能力时保存unknown并对账，不能承诺绝对避免重复计费。任务通过固定脚本与外部配置运行，断开SSH不中断队列。

## 当前状态

已收到用户指定的glm-5.3-flash Chat Completions配置，凭据通过CUSTOM_API_KEY环境变量读取。最小请求HTTP 200，3.41秒，返回模型名一致，输入17、输出43 tokens，其中reasoning40、cached0。尚未核验模型实际最大上下文、计费单价或长输入有效性；模型名由端点返回，不代表已独立核验其底层模型身份。

新增配置驱动的外部学习请求脚本scripts/environment/configured_external_learner.py及configs/learners/glm-flash-external.example.json。脚本接收固定消息文件及SHA，持久化请求与响应，输出usage和请求ID，禁止自动重发已有/未知请求，拒绝HTTP重定向以保护认证头。HTTP错误/超时保留状态，缺失usage不填零；尚未支持服务商任务查询或自动对账。该脚本是开发态教师请求执行器，尚未接入原生候选来源核验与成对评测的完整流水线。

固定镜像6项测试通过，覆盖成功响应复用、超时不重发、intent后崩溃保护、输入篡改、重定向拒绝和429不重发。第一条真实开发请求复用已封存node4的全部两条system/user消息，4条反馈、150794字符，max_tokens16384、timeout600秒，后台独立运行。它直接使用原始学习消息而非本地native包装，因此不能将本地66824 token计数当作API实际输入量，也不能声称严格隔离了教师更换变量。服务端实际usage与候选验证结果另行记录。

使用方式：设置私有环境变量，填写示例中的消息路径、SHA及唯一输出目录，执行python scripts/environment/configured_external_learner.py --config /private/learner.json。生产调度应通过固定镜像及受控凭据注入配置；本轮开发机后台请求用于验证外部协议，未改运行中的NPU执行树。尚无外部教师系统精度收益。

## 流式执行验证

统一请求执行器现支持配置stream=true，启用stream_options.include_usage；逐行fsync私有SSE日志，分开保留reasoning_content与content，记录响应头请求ID和流内响应身份。必须收到结束标记及finish_reason才形成完整响应；断流保留部分日志并标记unknown，不自动重发。8项固定镜像测试通过（0.08秒），覆盖成功流组装、缺失结束标记和重复调用保护。

真实短流式请求HTTP200、11.23秒，输入17/输出125，其中推理121 tokens，已得到usage；该端点此响应未提供x-request-id，流内ID另存响应。随后已启动真实ACE外部语义评价：完整历史失败上下文及响应，93850字符，max_tokens16384，正在收到SSE数据。此评价用于知识对象边界、证据缺项与最小干预分析，不是新的任务rollout或算法收益。

未重发此前四反馈GEPA未知请求。流式能减少无数据连接等待，但尚不能证明根除了网关302秒断链问题；socket timeout是读操作超时，不是严格的总任务时限。跨提供商完整上下文上限、价格和异步查询仍待核验。
