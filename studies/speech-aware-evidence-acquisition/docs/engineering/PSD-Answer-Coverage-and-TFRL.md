# PSD v2 回答覆盖与 TFRL 优化计划

## 当前优先级

先启动已准备的两路 PSD 实验；启动后第一优先消除工程协议导致的弃答，第二优先在现有 v2 接入配置化 TFRL 优化点。仅修阻止执行或损失有效答案的实际问题，不增加通用框架和额外启动门槛。CPU 分析、评分、教师素材准备与两个 TP4 推理实例异步进行。

当前发布为 `a675a7bd`，两路使用同一 Fold A1080、冻结三库、P thinking off、Decision thinking on，仅 Slot thinking off/on 不同。两路输入准备已完成，注册和准入由同一启动任务继续执行；尚未核实首条模型请求，不能宣称实验已运行或 NPU 已满载。

## 第一优先：有效回答覆盖

目标是全体样本均获得可评分的意图和槽位回答，工程可恢复错误不直接变成终态弃答。回答有效不等于正确：有效回答率、Intent、SLU F1、strict 必须分别报告，分母保持完整名单。不得用默认意图、强填空槽、删除失败行来实现表面上的 100%。100% 是验收目标，尚未达成。

代码核查发现：`rails/intent_slot_pipeline.py::slot_results` 要求所有候选全部返回，漏一个分支会拒绝整份结果；`reproduction/ojw/native_request.py::_answer_only_fallback` 仅覆盖空文本、长度终止且有 thinking 答案预留的情况，并不恢复普通格式或分支缺失错误。v2 已支持候选归组和 Decision 只选 ID 后程序组装，不能沿用旧 v1 的拒绝比例推断 v2 表现。

处理顺序：

1. 无歧义格式问题由程序规范化，原文和转换记录保留；不推测缺失的语义字段。
2. 分支缺失或冲突只修复对应节点/候选，保留已有有效结果。向模型明确提供失败原因、原始音频、候选及锁定知识，不整条重跑。
3. 长度不足、空输出按外部配置分配恢复预算；恢复调用独立计费、写 checkpoint，接续不重复调用已完成分支。预算耗尽保留待恢复状态，不能宣称已有有效答案。
4. 真正的意图判断、槽位抽取错误进入模型优化；样本串线、来源不一致先隔离修复，不把错误来源答案混入结果。

需要验收真实轨迹上的三项：原有有效回答不丢失；可恢复拒绝被转成有效回答且可重放；新增模型调用、耗时与失败样本均可追溯。定点补齐全部候选和仅在已返回候选中决策是不同策略，不能静默互换。仅修改解析器而不更新实际 SDK 节点、交接材料和最终重放校验，不算实现完成。

## 第二优先：v2 的可优化点

|位置|允许优化|冻结边界|现有入口/待补点|
|---|---|---|---|
|知识供给|锁定库筛选、排序、字段投影、上下文预算|知识正文、来源版本与原始领域定义|复用 before/after_model_call 和 candidate_handoff；新增策略须实际接入|
|P|候选识别提示、候选证据组织|原始音频与合法意图清单|NodeWorkload 已有 perception_policy；保持首轮 P off|
|Slot|抽取提示、候选条件信息、定点修复策略|合法类型与冻结知识，原始实体证据|已有 slot_policy；通用分支修复尚缺|
|Decision|选择提示、比较材料与排序|合法候选及对应 Slot 结果，不改写实体|v2 仅选 candidate ID；需核实候选配置入口|
|学习器|轨迹采样、反馈与候选策略提案|冻结基座身份、数据划分、评分规则|每算法独立模板，动态轨迹由脚本拼接|

TF-GRPO、GEPA、ACE、Reflexion 沿用各自算法逻辑，不能共用一个泛化“反思提示”冒充四个算法。既有模板位于 `configs/prompts/learner/tfrl/`，配置位于 `configs/learners/tfrl/`；存在文件不等于已支持 v2 闭环。历史写知识正文的构建入口与当前冻结知识约束冲突，不直接接入。构建侧先研究冻结知识的索引、关联和供给组织，消费侧研究节点提示和决策。

每个候选记录基座/配置/模板身份、目标节点、因果假设、素材来源、改变项、真实运行结果与完整成本。先单节点配对，保留正向调整，再组合；不能把协议恢复的收益算成 TFRL 算法收益。教师从开发机外部 API 调用，运行态任务输入不含金标。

## 任务依赖与交付

两路当前 Fold A 实验独立启动 → 首批轨迹 CPU 分类 → 回答恢复最小实现与针对性测试 → 独立新配置发布及同名单复验 → 完整 Fold A 选型 → Fold B 确认并锁定 PSD 基线 → 四算法配对探索。TFRL 接口核查、模板和素材准备可以现在并行；正式效果对比依赖新基线。

运行树不热改；新旧协议结果不混报。队列中待依赖任务与已注册可执行任务明确区分，不以规划 JSON 冒充 NPU 已有负载。队列补充优先使用可比较的真实任务，不为填满显存重复无关实验。每轮报告完成/总量、整批秒/条与单样本延迟、卡数/实例、剩余时间、恢复覆盖与成本。当前无新增用户决策阻塞。
