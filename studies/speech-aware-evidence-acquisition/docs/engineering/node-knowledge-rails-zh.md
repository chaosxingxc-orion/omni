# 节点前后置 Rails 与锁定知识供给

## 决策与边界

保持一套 openJiuwen 智能体和既有 P→Slot→Decision 图，复用 `before_model_call` / `after_model_call`。本文为已确定的实现契约；实现正在独立分支开发，尚未完成固定镜像验收和真实数据效果验证。

领域知识仅来自版本锁定的知识快照。模型允许根据当前样本提出候选、抽取实体、做选择；模型解释不能升级为知识规则，不能写回知识库。知识正文由程序读取，不能让模型重写后作为权威内容传递。仅校验引用存在不能证明解释受知识支持，因此自由解释不能作为下游规则使用。

## 两个钩子的职责

`after_model_call`：保存原始响应及来源 → 解析实际业务终态 → 校验全部原始条目 → 归并重复候选和证据 → 根据合法候选及已有关系检索锁定知识 → 去重并组装下一节点的结构化材料。工具调用和中间响应不按最终判断处理；终节点输出最终结果，无需再检索下一节点知识。

`before_model_call`：首节点加载配置指定的初始知识；后续节点验证上游材料的样本、分支、调用和快照身份，按节点字段投影、去重和预算渲染，生成实际模型请求。复用已经准备的知识，避免上下游重复执行同一检索。补充查询只能由配置明确触发并留下来源记录。

P 的后置钩子按候选意图关联槽位契约及相关训练示例，供 Slot 使用；Slot 的后置钩子保留各候选槽位结果，并关联决策所需的意图区分证据，供 Decision 使用。所有关联遵循数据集原始定义，不能执行意图与槽位的笛卡尔积。

## 逻辑分库与字段投影

沿用 `intent-boundaries`、`slot-contracts`、`train-exemplars` 三类逻辑库，共用 provider、索引和运行基座；无需新增物理数据库或智能体。节点配置决定库类型、关联条件、投影字段、排序与上下文预算。跨库使用带命名空间的 ID 和版本，不凭裸 ID 混合知识。

现有审计显示：1080 次 P 请求的知识 ID 和完整正文无重复，但有261次重复意图输出；因此输入知识去重与输出候选归并必须分别实施。训练示例库存在5条完全重复正文冗余，可在消费视图合并并保留全部来源，不改历史快照。

## 稳定交接接口

交接材料至少记录：schema版本、样本/分支/节点/调用身份、原响应hash、规范化候选与槽位结果、明确的缺项和冲突、知识快照与条目ID/正文hash、投影和去重策略版本、来源别名映射。知识与样本判断使用不同字段，下一节点不得把样本解释当成库知识。

同意图候选按ID归组；相同证据引用合并，原始来源保留。知识仅在角色、适用条件和规范化内容相同时合并。槽位仅合并同候选内完全重复的语义对象；不同值、位置、否定关系和标注不能被吞掉。跨节点重复使用必要证据不属于应删除冗余。缺项不补空冒充正确，冲突不静默覆盖，非法引用不因去重消失。

## 验收与部署

验证真实SDK钩子顺序、实际HTTP知识输入、检索次数、幂等、并发样本隔离、非法引用、冲突/多值保留、原始响应不变及转换记录可回放。保留既有计费、请求身份和断点来源链；v1回归及v4g组合验证必须通过。

固定镜像+独立只读源码+外部配置发布；不热改绑定中的运行树。随后使用原有Fold A/B口径比较协议通过率、候选召回、Intent、SLU与节点耗时；开发集冻结后再安排完整测试。工程测试通过不代表已获得精度收益。
