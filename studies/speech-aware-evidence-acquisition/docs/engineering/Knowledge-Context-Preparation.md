# 知识消费前的程序化上下文准备

## 功能目标与执行位置

把归类、去重从模型反思中独立出来，作为知识供给到Solver之间的确定性CPU节点。相同知识快照、查询范围和配置必须生成相同消费内容与来源映射，新增模型调用为0。复用现有 KnowledgeProvider → PhaseSupply / SupplyPacket → 消费路径；具体接入代码正在实现，不能把开发态JSON重复折叠当作该节点已经上线。

链路：已固定知识与来源 → 程序归类 → 等价项去重 → 原有检索/排序及预算规则 → 消费请求 → 模型回答 → 官方评分。全库可提前建立分类和等价索引；最终请求组装前再次检查多路供给的重复项。两处共享同一版本规则，避免每个实验重写处理代码。

## 归类规则

只读取已有结构化字段：知识类型、来源库/版本、适用任务、目标节点以及原始数据定义中的意图和槽位关系。缺字段明确进入unknown类，保留原内容，不由模型猜分类。类别是可追踪索引，初版不以预测意图硬过滤其他类别，不重新构造意图×槽位笛卡尔积。

## 去重与证据保全

去重键必须包括内容、类型、适用范围与语义相关版本/有效性。只对按规则可证明等价的项目合并，保留首个位置和稳定顺序；文本相似不等于等价，不依赖LLM选取。首版优先字节或结构化内容等价，不随意小写、删除否定词、重排列表或折叠有语义的空白。

重复正文可以只渲染一次，但每个原始知识ID、来源摘要、检索命中、适用范围、版本和选择记录必须映射回保留项。重复次数不额外提高证据权重；具有冲突动作、不同范围、来源可信度或版本的项保留，交由单独的冲突处理策略。分类与去重不能暗中改变排序、奖励定义或答案。

## 配置、缓存与观测

使用显式策略版本和开关，旧配置默认保持原行为；新实验仅通过配置启用。缓存键绑定知识快照、分类/去重规则和配置；查询依赖部分还须绑定查询与供给输入。只缓存不变的知识内容，不能复用另一条样本的P状态、音频或动态证据。

normal记录输入/输出/去重数量、类别数、规则与产物摘要、CPU耗时及同一tokenizer测得的请求tokens变化。debug补充逐项归类、等价组、保留/合并原因和来源映射。真实token测量未完成时只报告字符/字节量，不能据此声称token节省。

## 测试与实验验收

先锁定确定性、幂等性、无输入突变、同文不同范围不合并、未知字段保留、冲突保留、多源追溯及默认关闭兼容性。随后用固定真实小集合比较原供给与程序化供给，冻结模型、P、解码和评分器，检查最终请求及官方SLU/Intent/strict、repair/break、每环节耗时和全部成本。

功能验收通过后再优化缓存、内存和批处理。上下文变短是工程收益，精度提升仍需成对实测；知识消费指令TFRL与该节点分别消融，避免混合变更导致归因不清。实现owner为知识消费子智能体，主线程审查、集成、配置实验并同步结果。
