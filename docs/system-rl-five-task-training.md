# 节点训练与系统训练：当前重构方案

四个节点训练任务加一个系统训练任务，共用现有 verl、vLLM Ascend、数据采样器、成功更新 Clock、评分器和运行控制器。五个任务不是五次 optimizer step，也不另建训练框架。

建议采用这个五任务结构，先把四个条件优化问题解耦，再训练它们的协同。物理训练并发由资源吞吐决定，不能把逻辑独立等同于当前四路训练已经可运行。每个节点应完成配置中已采样的数据，系统的 1000 难例仅是之后的新训练阶段。

## 为什么先节点、后系统

节点阶段优化 `E[x~D, c_n~frozen_system(x), a~pi_n][R_n(a,c_n,y)]`；系统阶段优化 `E[x~D, trajectory~current_system(x)][R_SLU(trajectory,y)]`。前者把上游固定，方便并行归因；后者让所有中间结果来自当前组合，处理误差传播和节点协同。系统 rollout 仍由节点的模型调用构成；改变的是采样单位和 reward 的归因范围。

冻结上游的代价是分布偏移：独立优化 S2 时看到旧 S1 的输出，组合后看到新 S1 的输出。因此四节点收益不能直接相加。组合后先在 TRAIN 上重新采集并定位接口错误，再用系统阶段校正；DEV 只用于选模与判断收益。每轮缓存绑定上游版本，上游更新后只有受影响的缓存失效。

节点阶段的冻结指输入上下文固定。每个节点仍以当前策略生成新动作，记录动作 token、行为概率、策略版本和 reward。系统阶段按真实 DAG 生成整个轨迹；同一轨迹内 S2 对 S1、D 对候选的实际依赖不能并行越过，能够并行的是不同样本、独立 Fold，以及训练与 CPU 准备。

四路独立不意味着四路共用一个优化器写同一份 LoRA。首轮采用独立分支以便归因；物理上按原八卡训练域排队执行，数据准备、评分和 rollout 异步流水。若后续需要共享 LoRA，则由一个训练器混合四类 minibatch，属于显式实验条件，不能声称与独立训练等价。

## 数据与缓存

训练入口统一解释为 `raw_dataset + frozen_system + sampling_config + task_config`。固定召回在 CPU 准备阶段完成，准入集合为 `E={x∈TRAIN: gold_intent(x)∈retrieval_top_list(x)}`，不以 P 的输出是否正确代替这个条件。全训练集遍历后，在 E 中按配置构建版本；错误/正确比例、真实/合成比例及抽样概率记录在版本里。节点训练出现上游漏供给时保留诊断身份，不把无法完成的目标伪造成目标节点自身错误。

逻辑上的最小训练项为 `(sample_id, audio_ref, gold_ref, task_id, frozen_context_ref, sampling_weight)`。当前实现为兼容原消费者，将原始记录单次写入内容寻址 references，采样清单只保留 `record_ref`、draw 元信息与抽样概率；不是声称已把所有内存对象和模型上下文都改成这六个字段。历史请求、响应、评分和调试文本不逐 epoch 重复传输。

固定数据层保留原始音频引用、官方标签、录音与来源 ID、TRAIN/DEV/TEST、版本。已有系统轨迹作为 references：用于错误采样、冻结上游输入、基线比较和具有正确目标的辅助损失；不把错误历史输出作为监督答案。标签不进入在线推理输入。

采样清单只记录原始采样概率、draw ID 和内容寻址 record_ref；窗口只记录起止位置。历史完整记录只保存一次，消费者只展开当前窗口。首次实现兼容旧清单，保留所有官方标签与历史成本。

阶段上下文缓存与采样成员分开版本化：进入新的节点阶段时，按新的冻结上游重新绑定 online 输入，保留样本身份、顺序、标签、抽样概率和消费进度。后续窗口复用该版本；不因阶段改变重新抽样，也不沿用旧上下文。候选实现已通过 23 项采样/恢复检查和原控制器 4 个场景；19 条真实保留记录通过准备→录音映射→窗口→原消费者接线验证，其中选择器为受限替身，不能作为全 TRAIN 采样验收。

应保持“数据记录精简”和“模型上下文精简”的区别：前者消除重复序列化，不删除知识、音频或标签；后者会改变模型行为，必须作为独立实验。完整 reference 由离线消费者读取，在线模型只得到该节点所需音频、知识和实际上游结果，不能看到 gold 或参考答案。

缓存分三类：

1. 固定系统 references：预先缓存冻结系统的召回、节点输入、输出、知识与评分，键包括数据、系统/知识/检索/rails/模型版本。训练改变的节点输出不能被历史输出替代。
2. 模态预处理：音频、processor、冻结塔、精度和长度/mask/位置语义一致时复用；改变任一依赖则失效。
3. reference policy 概率：本轮动作产生之后，在 optimizer 前计算并缓存 `log pi_ref(action | actual_context)`；新动作与新上下文不能从旧答案的概率替代。当前实现先缓存同一封闭 cohort 的精确请求，支持 GROUP 提交前中断恢复；跨 cohort 语义键复用尚未实现。缓存只含实际前向结果，不产生行为概率。

## 五个训练任务

| 任务 | rollout 的可变部分 | 固定输入与 reference | reward 主项 |
|---|---|---|---|
| P | 候选排序 topK→top3 | 音频、实际召回候选与知识 | gold 的 top3 覆盖，合法索引与输出遵从 |
| S1 | 每个 Fold 的槽位存在性判定 | 音频、槽位类型卡、Fold；不依赖意图 | 类型召回/F1、混淆多标惩罚、无值类型覆盖 |
| S2 | 提供槽位的值填充，允许空值 | 音频、冻结 S1 的真实供给、槽位知识 | 原始官方定义下的值 F1、正确空值、错误填充惩罚 |
| D | 最终意图、槽位和值的选择与组合 | 音频、冻结 P/S1/S2 的真实候选，关系知识 | 官方 SLU、联合准确率、有效回答 |
| system | 当前 P/S1/S2/D 的实际系统 DAG | 固定数据、知识、召回；更新后的中间结果重算 | 官方端到端 SLU，辅以渐退的节点 reward |

S2、D 的节点训练不偷换成 gold 上游输入；上游已漏供给的损失要与该节点自身错误分别报告。可另设显式 oracle 诊断，不混入主指标。

对节点 n，采样期间冻结策略 theta_n,t，采样 G 个动作，组内计算优势：

`A_n,g = (R_n,g - mean_g(R_n,g)) / (std_g(R_n,g) + epsilon)`。

同输入 G 次均为同分时，GRPO 的组内优势为零。保留这些组的成本与统计，按当前配置消费而不冒充成功更新；不能只提高 G 或反复抽样就宣称会学习。需要监测零信号组比例、reward 方差和有效更新/小时。P 可采用覆盖与排序分量，S1 采用逐类型的 TP/FP/FN 分量，S2 采用官方值匹配分量，D 采用联合结果分量，缓解单一精确匹配 reward 过稀；指标权重仍需由开发集验证。

统一目标：`L(t) = L_GRPO + beta(t)*KL + sum_k lambda_k(t)*L_aux,k`。
P 的排序、S1 的二元选择、S2 的监督填充、D 的选择辅助项复用现有 task loss；系数按成功 optimizer step annealing，失败与零信号组不推进系数。系统阶段主 reward 为官方 SLU，节点辅助权重逐步减小。硬指标须同时报告，不能只看加权总 reward。

## 并行与组合约束

独立训练的成本应按 `C_n = G·C_rollout,n + C_ref,n + C_update,n` 计算；全系统成本为 `C_system = G·(C_P + F·C_S1 + M(x)·C_S2 + C_D) + C_ref + C_update`，其中 F 为 Fold 数、M(x) 为实际 S2 请求数。节点拆分省掉了目标节点以外的重复生成；它不必然省掉训练反向计算，也不意味着缓存命中时可以不核验策略和输入版本。按相近长度组批、Fold 请求并行和 reference 前向批处理是同一工程下一步的效率调节项，须用实际有效更新/小时衡量。

四分支同时写同一共享 adapter 会破坏单节点归因。选择独立 adapter 时，系统阶段要按节点路由并保持整组 rollout 的策略向量不变；选择共享 adapter 时，应由唯一训练器混合四种任务，随后系统训练，不执行未经验证的 LoRA 参数相加。当前优先把单分支真实更新跑通；独立分支的 CPU 编译通过不代表四 adapter 组合已经可运行。

四节点可独立制作数据、缓存和评测。四路真正独立训练必须分别拥有 adapter、optimizer、Clock、消费账本；共享一个 LoRA 时应以单一训练器混合节点 minibatch，不能四路并发写同一权重。

当前原生训练实现仅接受 shared/default LoRA；per_node 仅在上层契约/CPU场景中出现，不等于实际后端已支持。需要扩展既有 worker 的节点路由、分路 checkpoint/恢复、vLLM 加载发布，并验证同输入训推一致；禁止直接删除 shared 断言后宣称支持。组合方式是按节点选用 adapter，不是把四个 LoRA delta 相加。

181 八卡仍为一个已授权 FSDP 训练资源域；175 四卡用于 rollout。CPU 可并发准备四路，NPU 按实际资源预算执行。只有证明基座共享/显存峰值和吞吐后，才提高物理训练并发；不启动四份未经测量的 30B 模型常驻。

## 系统难例阶段

在四节点组合并冻结后，使用该组合在官方 TRAIN 全域重新挖掘错误。建议首轮 1000 条困难样本加 250 条成功样本，沿用 80/20；“1000”是起始实验规模，不是保证收敛的定额。保留真实/合成配比与意图/槽位错误类型覆盖，按录音 ID 去重，并记录来源平衡。仍只纳入 gold 在初始实际召回候选中的训练样本。

难例收益、成功保持集退化和完整 DEV 同时观测，决定是否扩容；DEV 8690 选模，冻结后 TEST 13078 评估三组：直接模型、TFRL 系统、系统 RL。TEST 不用于挖难例或定权重。

1000 难例不能只挑最低分样本，应按根因、意图、槽位类型、真实/合成来源分层，兼顾可纠正错误与系统协同错误；可明确确诊的数据缺陷另外登记，不通过修改评测分母提升主指标。1250 条是首轮建议，既有已采样训练集仍按原配置跑完，不用这个建议替换用户的全量完成要求。

## 验收与效率

reward 分量均按对应样本人口统计。S1 至少报告 `recall=TP/(TP+FN)`、`precision=TP/(TP+FP)`、类型集合完全一致率、空值类型召回；数量一致只作辅助，因为“数量相同但类型全错”不能得高奖励。S2 把空值与非空值分层，防止全输出空值取得虚高分；D 与系统最终使用官方 SLU，同时保留意图准确率和槽位指标。若重采样难例优化的是困难分布，就如实说明；若声明优化原始总体期望，应显式使用目标分布与采样分布之比作权重，而非默认把 80/20 当成原始分布。

系统阶段的候选目标为 `R_t=(1-λ_t)R_SLU + λ_t Σ_n w_nR_n`，`Σ_n w_n=1`，`λ_t→0`；沿用成功 optimizer step 的配置化退火。各项归一化和权重需要 DEV 验证，公式不构成收益证明。每个 rollout 组使用同一策略版本，更新成功后下一组再切换版本；异步处理不允许悄悄混入过期策略动作。

缓存正确性与原消费者的输出一致性先用 CPU 验证。NPU 报告有效样本/秒、有效更新/小时、生成 tokens/秒、reference 命中率、各阶段墙钟与峰值显存；AI Core 高占用不能代替有效吞吐。没有实际同负载测量，不称“效率最优”。

已实现候选：精简采样清单/窗口、按需展开、同动作 reference 概率缓存、节点清单单次提交恢复修复；跨主机仅展开当前窗口引用；runtime_construction.node_training_task 选择四个独立分支，复用单 default LoRA worker，分别维护原运行/Clock。配置片段在 rl-ready-window-configuration/config-fragments/node-{P,S1,S2,D}.json，需合入同一宏解析后的运行配置，每个分支使用独立输出根与原资源调度。原 Clock 与本地 annealing 的六项 CPU 检查通过，实际四路训练/组合发布尚未验收。未完成：独立四 adapter 后端、组合发布与系统难例自动采样接线、真实更新/DEV 收益、生产吞吐测量。已有运行未被热修改。

## 正式节点启动修复

原正式启动路径调用仅接受 P/G4 的有限诊断准备接口，导致独立 S1/S2/D 在进入模型前就被拒绝。v200 在同一接口中显式区分正式启动材料与有限 P 训练：正式启动保留目标节点 mask、Clock、辅助损失和历史成本，诊断另行派生全部节点的不可训练证据。全 TRAIN screen 完成前，此启动输入不能进入普通训练 capture；完成后原 screen 绑定器将启动身份转存到 lineage。原有限训练仍只接受 P，未放宽到任意训练任务。

runtime 构建已经准备的 SOURCES.json 现在由后续阶段引用，不再重复展开 19 条音频并写入第二份 PCM。该复用绑定来源配置与不可变录音映射，不把有限启动材料宣称为全量训练集。

四个真实保留输入分支通过原准备、Clock 和诊断绑定器共 19 项检查；正式 screen 转换 7 项、原节点 Clock 6 项、原控制器 4 个场景通过。检查没有模型调用，未验证四 adapter 后端、全 TRAIN、实际训练内存或训练吞吐。两次测试入口问题（旧消费者源命名空间、物理路径替代原逻辑配置身份）的失败保留，修正测试接线后在原路径通过。

## 节点采样与组合的下一步要求

共同准入集合 E 可以复用，四路困难度不能全由最终系统对错定义。应分别从冻结轨迹评分得到 e_P、e_S1、e_S2、e_D：例如系统虽错但 P 已正确的样本，不应算作 P 的困难样本。每路抽样概率、失败类型、真实/合成来源和录音分组均保留。现有 80/20 采样仍按系统历史对错，节点特定困难度采样尚待接线，不能将设计写成已实现能力。

独立训练后的组合采用向量 (adapter_P, adapter_S1, adapter_S2, adapter_D)，每个 rollout 组冻结这个向量；系统任务才在真实 DAG 上重新生成上游结果。系统困难样本来自组合后的 TRAIN 结果，不能直接沿用训练前的困难度排序。P 和 S1 没有意图依赖，S2 依赖 S1，D 依赖 P/S1/S2；节点阶段缓存可以打断训练依赖，系统阶段必须恢复这些真实依赖。

启动预算还需覆盖真实系统调用：v194 的 32 个业务请求之外，原 owner 会为新服务执行 1 个端点验证。漏计导致最后一个业务请求在发送前失败。v201 在原 stage_budget 中统一计入端点开销，原 SQLite 记账器复现及修复回归通过；没有删除预算守卫，也没有重发已经完成的请求。该修复待 NPU 原路径验收。
