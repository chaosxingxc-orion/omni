# 子智能体模型路由

仓库通过 [`configs/agent-model-routing-v1.json`](../../configs/agent-model-routing-v1.json) 固化子智能体职责与模型分工。当前路由如下：

- 工程开发、固定脚本和配置、测试实现以及文档生成：`gpt-6.1-sol`。原目标模型为 `gpt-6.1-terra`，但 Terra 当前没有形成可核验的任务回执和报告，因此暂时切换到已确认可访问的 Sol。
- 样本分析、统计结果和 bad case 根因分析：`gpt-6.1-sol`。
- 任务规划、结果评价和重新规划：Astra（`gpt-6-astra`）。

这次切换是显式、可追溯的临时路由，不是静默替换。只有 Terra 通过独立探针提交匹配任务哈希的回执、报告、文件哈希和测试证据后，才允许切回 Terra。当前工程任务沿用 Sol，报告中必须记录实际模型身份。

模型路由是准入条件。调用前必须记录请求模型、实际模型身份、任务哈希和交付目录；实际模型不可用时阻塞该职责并记录原因，不能把“完成”消息当成交付。每项工作仍需落盘 `REPORT.md`、结构化 `result.json`、文件哈希和测试证据，主线程核验后才能合入或调整实验队列。

该配置只约束 ChatGPT/子智能体协作，不改变 NPU 推理模型、实验预算或业务评分口径。NPU 实验、CPU 分析和外部教师调用继续按现有队列与断点协议异步运行。
