# 停止准入与实验切换

## 配置与行为

普通 OJW 调度器在既有 admission-control 配置中支持 `"stop_policy": "cancel_unstarted"`。收到有效停止请求后，尚未首次提交模型调用的已准入样本在派发边界取消；已提交样本继续下游并排空。工具调用不算模型已提交。省略该字段保持 `drain_admitted` 兼容行为。

此策略解决 queue_depth 大于执行槽时，停止后仍让所有预准入样本跑完整轨迹的等待。它不会抢占已运行工具、取消未知模型请求或立即强制释放槽。node_batch 和 node_pipeline 当前明确拒绝新策略。

## 轨迹与恢复

实际观察停止时持久记录观察时间、请求与配置摘要。取消样本不写伪完成 checkpoint；其已有部分轨迹（包括已记录工具成本）先持久保存，再生成排空收据。收据包含准入、取消、已提交与完成样本集合；无模型自然完成样本也正常计入完成。

排空收据不代表租约释放。资源交接仍须精确进程终态、逐请求结算和服务静默验证。已有停止观察文件的同 attempt 不再启动；恢复使用新 attempt 和原有恢复校验。不要删除观察文件、guard 或历史费用来绕过检查。

## 验证与使用边界

配置贯通 flight→rails→真实 OJW 调度→checkpoint/receipt 的 CPU 回归通过。框架包装异常曾使取消失效；随后审查又发现 cleanup 错误可能被宽泛因果链匹配吞掉，两个负例在旧代码复现。最终只接受已验证的显式透明包装，其他错误继续失败，禁止成功排空收据。

最终修复的相关回归57项通过；此前版本较宽范围132项及4个子测试通过，两者不混称最终字节全量验证。没有实际NPU压力测试。功能已合main，当前冻结实验未热更新；后续普通调度任务通过新版基座与外部配置启用。

配置切换的可复用要求：取消以模型提交为边界；保存取消前成本；区分停止观察、样本排空与租约释放；清理失败不得被包装异常掩盖；CPU评分与NPU后继异步调度。
