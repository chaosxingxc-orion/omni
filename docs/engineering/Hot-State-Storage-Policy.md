# 热状态本地持久化与共享归档规约

## 当前生效的存储规则（覆盖下方历史约束）

在尚未修复的175/181上，禁止应用向Ceph写热状态并调用文件或目录fsync。热状态改为本地持久盘写入，保留文件及目录fsync，再由受控归档流程同步到共享存储。本条替代此前“所有项目文件写Ceph”和“Python禁止fsync”的要求，不全局删除或禁用fsync。

热状态包括请求journal、队列、锁和租约、运行回执、日志、增量结果、checkpoint及运行临时文件。配置分开声明本地热写根和共享归档根，检查真实路径与挂载；经软链接或bind落到Ceph仍属共享写入。只读模型、数据和冻结源码可以从共享盘读取。归档处理已关闭文件或一致性快照，独立限流复制、校验；归档客户端不对Ceph目标文件或目录调用fsync，也不使用其他显式同步调用绕过限制。复制校验不等于介质持久性保证，活动恢复证据保留在本地。

清理优先处理/var下本项目非活动历史资产，排除活动热目录、运行锁、唯一恢复副本。已有Ceph热写配置暂停启动；运行中代码不热改，停止新增请求、保留已知/未知状态并核验终态后显式交接，不创建两个可同时执行的guard、不盲重发。共享故障保留本地状态和待归档记录；空间不足停止新增任务。恢复Ceph热写须有修复验证和明确策略变更，不能自动切回。


实施状态：规约已生效，旧Ceph热写配置不得启动；本地热写部署仍待适配验证。存储变化不改变Instruct/OFF、冻结数据和S2评分标准。D继续暂停，S2优先。

## 服务入口

服务启动复用 `scripts/experiments/service_from_config.py validate|start|status --config <配置>`。配置含固定镜像、已停止的前驱CID、原生Docker参数数组、本地目录和回执根。启动验证真实本地文件系统、只读Ceph挂载、模型参数与卡号不变；START意图先在本地持久化，重复启动拒绝并要求核实原回执。脚本启动不代表模型健康，必须另核models端点和业务响应。该入口不替代实验generation lease与原生断点规则。
