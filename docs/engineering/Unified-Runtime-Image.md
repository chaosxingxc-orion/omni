# 统一 Docker 工程基座

## 当前交付边界

当前实现采用固定依赖镜像、完整只读源码发布包、外置配置和通用启动器，符合外部挂载运行脚本的约定。依赖镜像固定为`sha256:7e60208fb45e8af3f1ab777cf24df7a7a415d8d84e2972ee76def4daf5c0f026`；最新已验证源码为`3b267014`，已补齐外置experiment manifest恢复层，固定镜像209项测试通过。下文v7/v8等为历史验收，不能当作当前完整基座的验收结果。当前两TP4引擎保持运行，生成worker已自行退出，无新科学实验；完整断点继承及稳态吞吐尚未通过。

## 发布目标

工程基座收敛为一套版本化运行镜像，内含已验收的业务源码、通用执行脚本和依赖。同一镜像通过外部配置支撑不同实验；发布后修改实验无需复制执行树、修改源码或重新安装环境。一个镜像可以启动多个服务、队列和分析容器，维持两个四卡实例及CPU异步处理。

通用[发布运行手册](https://github.com/chaosxingxc-orion/omni/blob/main/docker/saea-base/release/README.md)和[8份配置模板](https://github.com/chaosxingxc-orion/omni/tree/main/docker/saea-base/release/examples)已入仓，覆盖构建、预检、stage/prepare/register和队列；模板含明确占位项，填写真实来源pin后使用，不能直接执行。

## 配置边界

|固定在发布镜像内|运行时外部输入|
|---|---|
|NPU/vLLM依赖、隔离的实验Python环境|模型、数据集、知识资产的只读挂载|
|节点执行器、TFRL实现、评分器|算法、节点图、thinking、预算、种子和模板配置|
|通用启动、预检、队列、观察与恢复代码|卡组、端口、并发、任务依赖和优先级|
|源码清单、依赖清单、版本信息|本地持久化状态、输出目录及正常/debug观测配置|

教师凭据从运行环境注入，不进入镜像或公开配置。开发态可显式挂载源码；正式发布态使用镜像内源码。算法新增能力通过有测试的新版本发布，实验参数通过配置变更。已有薄启动脚本可以外部挂载，其版本和摘要必须可追溯。

## 当前差距

仓库已有`docker/saea-base/Dockerfile`和`configured_job_launch.py`，尚不能视为完成统一发布。旧构建依赖人工准备的上下文及部分浮动依赖，当前运行还需外挂冻结源码树，启动器也核验主机Git工作树。需要统一镜像内源码身份与原生封存契约、构建上下文、挂载接口和配置验证。

实施先复用已验证的父镜像摘要构建运行发布层，不重装或升级推理栈。必须记录父镜像的可获取来源；只有现存镜像而缺少完整上游构建材料时，不宣称整个依赖链可从源码重建。构建材料采用白名单，不打包历史运行、原始轨迹和私有资产。

## 验收与迁移

先锁功能测试，再优化非功能性能。验收要求镜像内真实导入路径及源码摘要正确，禁止字节码污染冻结源码；只读代码与可写状态分离。相同镜像仅修改配置，至少通过两类实验的真实零模型预检，并验证队列、评分和观察入口。帮助命令或容器启动成功不足以证明业务可用。

重复启动不能重发未知请求；SSH断开后任务持续运行；断点、租约、历史成本和fsync保留。观察默认600秒或终态事件。版本、配置和来源摘要写入结果，跨语义配置不得复用旧响应。

当前两臂继续使用原冻结版本。新镜像独立构建与回归，验收后由后继任务使用。效率修订候选已从main `f7de3231`重新构建：181本地镜像为`sha256:506c770134924a083eb783ba0bdc246cfe211f2b47fdc58aeff567c885398cfc`，source-manifest SHA为`b3c502885c9df7c3d01db9b3b32d59d03207f2c260280408476b6bae0957d84e`。双解释器导入、manifest核验、滚动预加载缓存上限 smoke、真实 NPU ACL/vLLM 导入和两路 TP4 `/health`/`/v1/models` 均通过；两个新服务已替换旧服务，尚未开始科学请求或真实断点接续，因此仍不把该镜像称为科学实验已验证基座。

镜像ID是本机内容身份，尚无镜像仓库分发地址；父镜像依赖现有产物，不宣称完整供应链可从公开源码重建。新候选将音频预加载改为有界rolling submission window，Future只保留失败/完成状态，避免全量Future造成额外内存驻留；运行中campaign的预热线程上限为8，并拒绝外部配置覆盖科学`request_pipeline`或`audio_cache`。发布 Dockerfile 保留父镜像 Ascend Python 搜索路径，并将硬件动态库检查移到真实 NPU 挂载 smoke；这次修复解决了首轮镜像启动时 `ModuleNotFoundError: acl`。这些是工程基座修复，尚不等同于端到端NPU吞吐提升。

当前实验继续，新增大规模实验暂缓。完成最终镜像内三段流水功能验证、科学请求一致性和旧断点兼容预检后，只交接首个实例：停止其旧版准入、排空请求、结算检查点、更换worker版本并接续。真实效率用正式接续负载观测，另一实例继续；确认后再推广。两实例占用期间不借旧租约试跑，不把尚无资源执行的真实效率验证设为首臂交接前置。未知请求不重发。
