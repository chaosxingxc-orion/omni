# 统一 Docker 工程基座

## 发布目标

工程基座收敛为一套版本化运行镜像，内含已验收的业务源码、通用执行脚本和依赖。同一镜像通过外部配置支撑不同实验；发布后修改实验无需复制执行树、修改源码或重新安装环境。一个镜像可以启动多个服务、队列和分析容器，维持两个四卡实例及CPU异步处理。

## 配置边界

|固定在发布镜像内|运行时外部输入|
|---|---|
|NPU/vLLM依赖、隔离的实验Python环境|模型、数据集、知识资产的只读挂载|
|节点执行器、TFRL实现、评分器|算法、节点图、thinking、预算、种子和模板配置|
|通用启动、预检、队列、观察与恢复代码|卡组、端口、并发、任务依赖和优先级|
|源码清单、依赖清单、版本信息|本地持久化状态、输出目录及正常/debug观测配置|

教师凭据从运行环境注入，不进入镜像或公开配置。开发态可显式挂载源码；正式发布态使用镜像内源码。算法新增能力通过有测试的新版本发布，实验参数通过配置变更。已有薄启动脚本可以外部挂载，其版本和摘要必须可追溯。

## 当前差距

仓库已有`docker/saea-base/Dockerfile`和`configured_job_launch.py`，尚不能视为完成统一发布。旧构建依赖人工准备的上下文及部分浮动依赖，当前运行还需外挂冻结源码树，启动器也核验主机Git工作树。需要统一镜像内源码身份与原生封存契约、构建上下文、挂载接口和配置验证。

实施先复用已验证的父镜像摘要构建运行发布层，不重装或升级推理栈。必须记录父镜像的可获取来源；只有现存镜像而缺少完整上游构建材料时，不宣称整个依赖链可从源码重建。构建材料采用白名单，不打包历史运行、原始轨迹和私有资产。

## 验收与迁移

先锁功能测试，再优化非功能性能。验收要求镜像内真实导入路径及源码摘要正确，禁止字节码污染冻结源码；只读代码与可写状态分离。相同镜像仅修改配置，至少通过两类实验的真实零模型预检，并验证队列、评分和观察入口。帮助命令或容器启动成功不足以证明业务可用。

重复启动不能重发未知请求；SSH断开后任务持续运行；断点、租约、历史成本和fsync保留。观察默认600秒或终态事件。版本、配置和来源摘要写入结果，跨语义配置不得复用旧响应。

当前两臂继续使用原冻结版本。新镜像独立构建与回归，验收后由后继任务使用。首个候选镜像已构建成功，并通过无业务源码挂载、只读容器中的源码清单与入口检查；最终候选两类业务预检通过，准备/注册成功，配置缺陷已修复，效率与迁移验收尚未完成，因此仍未发布为可用基座。
