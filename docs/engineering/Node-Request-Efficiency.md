## 已修复的问题及复用规则

1. **外部资产解析**：E0/runtime/D1凭证统一通过带哈希的外部资产解析器读取；编译提前检查输入闭包。保留模型、评分源码和历史凭证完整性校验。
2. **环境身份一致**：编译、准入和执行使用同一数据根环境；知识输入按原哈希预先搬到本地，原文件权限和内容不改。
3. **只读源码与日志分离**：框架默认相对日志路径导致只读错误。使用 `framework_runtime.log_directory` 指向外部可写目录，由公共API配置；不在源码下增加可写挂载。
4. **入口语义保持**：包装入口保留原argv及脚本同目录导入路径；真实子进程测试覆盖同目录模块和字面参数。
5. **验证输出与生产输出隔离**：离线render曾继承worker计时路径，先创建文件，导致正式进程O_EXCL失败。启动器现在检查计时文件和配置快照；验证任务移除正式计时环境，`runtime-check`自动不传正式计时路径。不删旧文件、不原地重提。

6. **环境资产哈希前置核验**：除了required_inputs，还核对容器实际使用的manifest环境路径与SHA；按挂载映射读取，在launch-intent之前拒绝过期或缺失的pin。
7. **跨版本时间戳兼容**：Docker的0–9位小数时间戳先规范为微秒；同时在固定镜像和实际主机解释器验证。监控失败不当作worker失败，不触发重提。
8. **调度能力与保护包装兼容**：仅检查已知包装内的单vLLM能力，实际发送仍走原租约/资源检查链。测试必须同时覆盖能力识别和生产发送链，不能只测试裸transport。

失败记录：`generation-preload-v1` 在E0路径检查失败；`generation-gate-v1` 在框架日志初始化失败、attempt ABORTED且calls=0；`generation-framework-v1` 在计时文件创建失败，未创建生成/FIT账本及journal。`generation-telemetry-v1` 在单vLLM能力判断失败、ABORTED且calls=0，已完成音频预热但新增终态0。旧状态均保留，不能作为推理性能数据。gate失败lease已核验归档，guard未变。
