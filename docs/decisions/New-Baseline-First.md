# 新基座先锁定，再开展 TFRL

## 当前决定

后续实验统一基于已约定的 `Top-K意图P → 候选条件化Slot → Decision`。先完成新图功能、真实小规模基线与配置冻结，再启动任何 TFRL。旧 joint 的 ACE/Reflexion/GEPA 分数只作为历史参考，不作为新图的基线或学习轨迹。当前状态是 **基线待验证，尚未锁定**。

## 实验基线内容

首版采用 batched Slot、最多3个唯一候选；空槽合法，保留原始音频及知识来源。按既有实现首版关闭候选外恢复，明确与旧 joint 的能力差异；不在本次偷偷增加恢复算法。P、Slot、Decision 模板分别冻结；Decision选定候选的完整槽结果，禁止静默改槽。模型权重冻结，无TFRL附加规则。

基线登记必须同时绑定：源码提交、固定镜像、模型/处理器、节点图与输出协议、P/Slot/Decision模板、知识快照及视图、检索与排序、程序去重、normalizer、官方scorer、推理配置、稳定数据名单/顺序/音频身份以及运行与恢复合同。单个分数或配置文件名不能替代这些来源。

先使用现有第二个四卡实例和原固定DEV80名单，不重新抽样、不使用selection/TEST调基座。模板预算初定沿既有3072思考+1024回答，各节点实际序列化参数必须核验；正式配置变动登记新版本。当前不同实例的上下文设置不能混为同一比较条件，后续对照必须对齐影响语义的配置。

## 执行和验收

1. 修复首次 Slot→Decision 供给重复ID的程序错误：同ID同内容去重，异内容冲突拒绝，保留facet/rank/source证据。使用真实失败路径验证，保留历史失败成本。
2. 对齐增强joint与split的P语义输入和evidence inventory，记录图结构变化及权限差异。先跑新图80条；匹配控制随后接续。不能用旧两卡分数冒充新四卡配对。
3. 全部80条必须有可追溯终态，报告完整三节点轨迹数量、程序拒绝和模型失败；seal_refusal不能计作业务完成。不能只靠单条成功或单元测试锁基线。
4. 汇报Intent、实体TP/FP/FN与F1、官方SLU、strict、修复/破坏、节点耗时/tokens/FIT、墙钟秒/条、资源和ETA；真实请求与最终投影均须可审计。
5. 验证已知响应恢复、未知请求不重发、持久队列和CPU分析异步；正式来源凭据完整后签出一个baseline digest。锁定表示配置与实测可复现，不表示已优于旧基座。
6. 锁定后，每个TFRL实验引用同一baseline digest，并声明只改知识构建、P、Slot或Decision中的哪一项；同题对照和非目标回退一并报告。新图轨迹才能用于新图策略学习，旧joint K4不自动迁移。

新基座锁定后，按既有约定重新做完整TEST13078最终汇报；与TFRL开发可分实例异步执行，测试集不进入教师和调优。若新图出现明显功能/精度问题，先修复或明确版本差异，不能通过降低验收口径宣布锁定。
