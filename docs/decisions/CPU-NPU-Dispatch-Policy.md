# CPU 与 NPU 异步调度约定

用户最新指示优先于旧任务中人为添加的选型/验收前置。当前运行不热改、不因报告中断。

## CPU 队列

在NPU任务驱动前完成数据供给、固定知识/向量加载、配置拼装、目录与权限准备、需要的准入、静态检查。固定数据集、知识快照、镜像、release与prepared supply按已有身份复用；未变的输入不重做stage/prepare、不反复全量hash或运行全仓测试。评分、轨迹归因、教师调用、报告与发布在独立CPU工作项中异步处理，不占NPU租约、不挡无关推理。

## NPU 队列

只有输入完整、已准备的任务进入READY；等待准备的任务留在CPU队列，不持有NPU资源。任务派发只检查当前实例/进程身份、资源空闲和未结算请求等运行状态，不能在拿到卡后再做全量数据/源码/模型文件复核。生成sealed并释放租约即触发下一推理；不能等待容器内CPU评分结束。现有generation-released事件与queue依赖已经支持此边界，优先直接配置复用。

## 依赖

不设置CPU报告完成、所有算法就绪、主线程例行验收等通用屏障。只保留该实验确实需要的输入（教师候选需要轨迹）、科学选择（Fold B确认需要冻结策略）或用户共同决策节点；阻塞仅作用于该分支。E5 OFF/ON k16分别与对应既有k8控制组比较，已有预先定义的干预不需要先挑OFF/ON赢家；可在相应实例释放后运行，评分并行，不将Fold B用于选型。

## 当前实施边界

已核代码：FlightQueue在preflight与preprocess之后才取得generation租约，seal后释放并异步score；run_real_engine_candidate写generation-released事件。但外部launcher仍会全量校验release，worker仍有模型/媒体/runtime身份校验。不得把本约定描述成这些重复工作已经全部消除。先用现有稳定缓存与prepared路径复用；若实际路径仍重复且不可配置，做一个针对该路径的最小改动并验证缓存失效，不新造认证/审批层、不热改v5。
