# S节点播客类型混淆：根因与下一轮实验

## 当前证据

正式探索冻结6682条、独立验证1850条，均为实际P top3命中后的单正确意图分支。当前探索归档4352条；本分析使用已评分3328条，集合exact2293（68.90%）。其余结果异步评分，不能当作完整基线。

已评分play_podcasts共63条，48条类型集合不一致；7条同时漏选podcast_name并选出podcast_descriptor。逐条读取原输入知识卡、实际动态示例及模型输出，不仅统计FP/FN。

## 已识别的机制

1. 名称卡的意图角色说明被历史来源审查暂时撤下，只留下by/of/on等表面线索，语义角色解释不完整。
2. 描述卡同时覆盖集数选择和主题，名称卡也允许主题作为名称，两张卡存在边界重叠。
3. 7条中部分已有名称角色的高相似示例仍错，不能统一归因于样例不足；另有样本只收到描述或空类型示例，属于不同的供给问题。
4. 原对比关系注册表只有日历、烹饪、音乐，未包含播客名称/描述。教师仅在旧关系集合中选择，无法针对这一类别改善角色区分供给。
5. 原TRAIN中有193条播客样本，56条含名称、67条含描述，并有两类型共存的正向标注。只能将经过质量、独立来源及查询/dev同源过滤的记录用作知识，不按单条待评答案造卡。

以上是可检验的机制假设，不是已证明因果或收益。部分主题/节目名仍可能有业务定义或标注歧义，不据此自动删除样本。

## 并行实施

知识子进程准备独立版本的播客角色关系及合法来源，恢复有依据的角色说明，保留当前在途基线。候选编译器已接提示词、示例选择和有源卡片投影；接口回放不能代替模型收益验证。

分析子进程已交付评分、独立ACE/TFGRPO模板及22项边界测试，在固定CPU镜像内通过。原进程完成退出后，以同职责Codex子进程接续新根因工作，仍最多三个工人。教师输入必须展开可用配置、关系和必要来源摘要，本机路径不能代替内容；只消费探索错例，正确query与dev逐例留在本地。

NPU由原执行器继续冻结基线和dev队列。CPU先准备后继策略；完整探索基线后审查并调用教师，再做同集合配对实验。分别检验知识构建、知识消费与提示词作用，不以7条错例通过作为晋级条件。报告修复/退化、全6682回归、1850独立验证和成本。

## 当前限制

未产生新教师调用或候选实测收益；类型合法清单缺口和标注冲突独立分析。S继续仅输出类型，槽位值由D处理，系统级目标尚未完成。
