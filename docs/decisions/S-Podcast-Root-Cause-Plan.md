# S节点播客类型混淆：根因与下一轮实验

## 当前证据

正式探索冻结6682条、独立验证1850条，均为实际P top3命中后的单正确意图分支。完整基线已归档并复算：探索集合exact4596/6682（68.78%），独立验证1298/1850（70.16%）。以下7例机制分析来自较早的3328条切片，不代表全量类别计数。

已评分play_podcasts共63条，48条类型集合不一致；7条同时漏选podcast_name并选出podcast_descriptor。逐条读取原输入知识卡、实际动态示例及模型输出，不仅统计FP/FN。

## 已识别的机制

1. 名称卡的意图角色说明被历史来源审查暂时撤下，只留下by/of/on等表面线索，语义角色解释不完整。
2. 描述卡同时覆盖集数选择和主题，名称卡也允许主题作为名称，两张卡存在边界重叠。
3. 7条中部分已有名称角色的高相似示例仍错，不能统一归因于样例不足；另有样本只收到描述或空类型示例，属于不同的供给问题。
4. 原对比关系注册表只有日历、烹饪、音乐，未包含播客名称/描述。教师仅在旧关系集合中选择，无法针对这一类别改善角色区分供给。
5. 原TRAIN中有193条播客样本，56条含名称、67条含描述，并有两类型共存的正向标注。只能将经过质量、独立来源及查询/dev同源过滤的记录用作知识，不按单条待评答案造卡。

以上是可检验的机制假设，不是已证明因果或收益。部分主题/节目名仍可能有业务定义或标注歧义，不据此自动删除样本。

## 并行实施

知识子进程准备独立版本的播客角色关系及合法来源，恢复有依据的角色说明，保留当前在途基线。候选编译器已接提示词、示例选择和有源卡片投影；接口回放不能代替模型收益验证。

分析子进程已交付评分、独立ACE/TFGRPO模板及22项边界测试，在固定CPU镜像内通过。原进程完成退出后，以同职责Codex子进程接续新根因工作，仍最多三个工人。教师输入必须展开可用配置、关系和必要来源摘要，本机路径不能代替内容；只消费探索错例，正确query与dev逐例留在本地。

全部基线已完成。播客消费候选8532条输入已闭合并通过固定镜像检查，主线程逐行比较确认：探索88条、dev20条实际输入变化，全部限定在play_podcasts；P证据、音频、正确意图分支、槽位允许清单均保持。执行子进程正在接入现有三路队列；尚无新候选NPU启动回执。教师策略准备与候选运行并行。分别检验知识构建、知识消费与提示词作用，不以7条错例通过作为晋级条件。报告修复/退化、全6682回归、1850独立验证和成本。

## 当前限制

未产生新教师调用或候选实测收益；类型合法清单缺口和标注冲突独立分析。S继续仅输出类型，槽位值由D处理，系统级目标尚未完成。

## 下一候选与评估规则

播客名称/描述关系候选已独立核128条合法TRAIN来源：名称53、描述67、共存14；其中现有向量索引可访问的共存来源只有3条。新关系保持原selector参数及其他意图关系不变，是知识消费消融；知识卡角色补全另作候选，不混入同次变更。

候选进入可保留清单的预声明条件：完整6682探索净修复至少1、1850独立验证净变化不负、无新增协议失败、预声明目标类别有正净收益。所有原正确退化与FP/FN、空/非空、意图切片仍须报告，不自动晋级。只有dev配对来源组95%区间下界大于0，才称有统计支持的稳定泛化收益；否则点估计改善仍是暂定候选。

首轮教师采样已退回原职责Codex子进程修正，现有8项测试并未覆盖这项采样要求：旧12代表因字母排序集中在闹钟/音量，随后24代表又过度集中播客。改为机制与意图覆盖、按发生量分配并限制单意图占比；原错误边界、正确query/dev不外发的要求保持。当前未调用这份偏斜教师输入，没有候选实测收益。

## 当前运行阻碍

候选上传时发现计算主机的根分区及日志分区已满；另一块本地数据分区尚有约110GB。执行器正在将新任务准备和持久日志配置到可用分区，保留基线、模型和共享依赖，不把热日志迁至共享文件系统。当前不能声称NPU持续满载；候选收益和完成时间待真实运行后报告。
