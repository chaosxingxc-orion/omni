# 推理引擎布局与两条 TFRL 系统优化线

状态：下一阶段以两条系统优化线组织任务，两个 TP4 为待验证目标布局；尚未切换服务。

## 任务决定布局

A0 已完成 13,078 条完整测试及官方评分，不再需要长期独占第三条运行通道。此前“只缺 CPU 评分”的判断混用了生成释放时的历史标志，现以完整评分结果更正，见 A0-Full-Test-Baseline。外部教师在开发机运行，NPU 主要承担真实轨迹采集和候选对照评测。

当前部署为一个 TP4/49152/max-num-seqs128，两个 TP2/65536/max-num-seqs48。最近观测三端点 running/waiting 均为零；没有三种 TFRL 算法正在并行推理。服务布局不等于科研并行度。

## 两条系统线与算法安排

|系统线|冻结部分与优化目标|参考方法|下一项有效工作|
|---|---|---|---|
|知识构建|固定消费基座；优化知识条件、适用范围、冲突与反例|TF-GRPO、ACE、Reflexion|先检验已有 ACE 来源约束候选；复用教师结果，记录其实际改变的是知识还是消费提示，不能因算法名就算构建改进|
|知识消费|固定知识快照；优化意图候选、槽位条件供给、决策和排序|GEPA 为主，Reflexion 消费策略作为对照|其他负责人完成节点程序修复后，验收旧结构/增强联合结构/分节点结构；补全已有 Reflexion learned 与 lock 独立评分|

算法是队列中的实验方法，不各占一个常驻实例。当前实现含离线迁移适配，不等同于完整复现原算法；每项实验必须注明学习对象、奖励、更新算子、反馈来源。先分别验证两线，再做原系统/构建改进/消费改进/组合的四臂实验。未证明稳定收益的候选不自动晋升。

## 两个 TP4 的价值与限制

建议目标为卡 0–3、4–7 各一个 TP4，两条逻辑队列允许在兼容空闲实例间调度。减少模型副本可能增加 KV 空间；更宽 TP 也增加通信开销，所以总吞吐不能按卡数倍增推算。64K 不是 TP2 专属能力，TP4/64K 需要验证，但不能以尚未验证断言 TP4 不适合长上下文。

先用固定真实开发任务做一次有界验证：相同镜像、输入名单、节点、输出预算和 64K 上下文，比较同四卡上的一个 TP4 与两个 TP2 的聚合完成样本/小时和 NPU 卡时/完整轨迹；同时记录 p95、失败率、前处理/FIT/排队/推理耗时。当前 TP4 客户端常用16、TP2常用32，历史秒/条含这些差异，不支持布局因果结论。max-num-seqs 是服务上限，不是实际客户端并发。

复用固定名单，先用80条判断是否达到稳定负载；不足时使用已有真实500名单一次验证，不重新制作数据或重复无收益扫描。TP4 必须与两个 TP2 的合计产出比较；若有效吞吐或实际候选周转没有收益，就保留物理 4+2+2，而逻辑上仍只维护两条系统线。

先准备可执行候选再切服务：每线保持一个执行任务和至少两个可运行后继，依赖用 DAG 表达；评分、根因分析与教师提案不阻塞独立 NPU 后继。复用稳定数据与可合法共享的冻结阶段结果，不共享被干预节点的输出。完成样本、调用和部分轨迹分别记账，程序失败从有效断点恢复。
