# P 节点八卡训练与双 TP4 推理

两套 TP4 已在独立推理主机部署并启用 KV 和 prefix cache，每个 rank 读回 384 个严格首步 LoRA 张量。两实例对同一条真实录音各完成一次请求，共 20 个实际动作。训练主机从同一 checkpoint 恢复，8/8 rank 正常结束；训练和评估前向的最大单 token 和整段 logprob 差均为 0，top-1 无翻转。两条诊断耗时 105.58 / 107.66 秒，含适配器装载和全词表观测。训练仍为 1/3，尚未测量常规 rollout 吞吐。 [跨机复核回执](partner-handoff/cross-host-active-parity.json)。

严格确定性 P 首步的同一份八卡 checkpoint 已完成同机更新态校准。四卡/八卡的 384 个 LoRA 张量、梯度及 Adam 更新逐值一致。两套 TP4 在旧版请求排空后切到新权重，清除旧缓存；两条录音共 6 个新权重请求、70 个动作，HF train/eval 与 vLLM 的单 token 差、整段差和 argmax 翻转均为 0。本次未执行连续训练或 DEV 评测。 [验收回执](partner-handoff/updated-lora-parity.json)。 [配置与运行入口](../../tools/system_rl/instruct_activation/README.md)。

**当时的接手点：** 原八卡首步更新后的权重在一条真实语音、两次 TP4 自然解码上，与恢复后的 FSDP8 训练及评估前向逐值一致。独立的严格确定性首步中，四卡与八卡的全部 LoRA 梯度、Adam 状态和更新量也逐值一致。原双机服务已经释放。尚无连续训练及 DEV 收益。 [合作交接](partner-handoff/README.md)。

以下为此前的实验记录。

训练主机的八卡 FSDP 完成一个可恢复的 P 节点更新。推理主机的两套 TP4 基础服务通过各一次真实 P 音频请求，均正常返回 10 个 token。两实例随后在常驻基础模型中装入第 1 步 LoRA，并完成缓存失效。跨机更新态概率验收尚未通过。

| 证据 | 实际结果 |
|---|---|
| FSDP8 首步 | 2 组、8 条轨迹、86 个动作 token；全局 loss 0.6874986887，梯度范数 8.51530647，更新前同动作最大 token 和整段 logprob 差均为 0；8/8 rank 正常退出 |
| 新进程恢复 | 8/8 rank 恢复 FP32 LoRA、Adam、scheduler、Clock 和 RNG，确认两组已消费、步号 1；恢复阶段没有执行更新 |
| TP4 实例 A / B | 物理卡 0–3 / 4–7；均为 Instruct、thinking OFF、KV/prefix cache 开启；单次实际音频请求 5.56 / 5.23 秒 |

八卡从冻结基座建立独立谱系。同一批次和四卡交接首步的 loss 相同，两个实验不累计为连续更新。八卡首个进程因任务适配器导入早于原 verl worker 初始化而退出；恢复原导入顺序后，实际八卡更新、写盘、独立进程恢复均通过。保留原始失败及闭合结果。

固定入口仍是 `stage_bounded_actor_step.py`。在已验收四卡字段包和参考运行的基础上，配置 `recoverable: true`、`devices: [0,1,2,3,4,5,6,7]`、独立的 `lineage` 和 `run`，并设置 `storage_budget_bytes`、`timeout_seconds`。恢复使用同一谱系和源，配置新 `run` 及 `restore_run` 指向正常退出的八卡首步。恢复过程只读挂载 checkpoint；它验证恢复，不执行第 2 步。

两套 TP4 的四个 rank 各自核对了第 1 步适配器的 384 张量和实际设备缓冲，并确认 KV/prefix cache 开启、旧缓存已失效。两套服务对同一原始录音得到相同的 10 个动作和概率。FSDP8 复算的最大单 token 差为 0.102120，整段差为 0.156538，零 top-1 翻转；两项仍超出 0.01 门槛。第 2、3 步尚未执行。

在同一恢复进程中，用 FP32 master 和实际发布的 BF16 文件分别前向，观察到的动作概率与层边界逐值一致，排除了导出舍入是这次差异的原因。两套 TP4 的八个 rank 上，4,656 个提示位置的解码器输入、输入归一化及第 0 层 K/V 投影一致，首次可见差异在第 0 层 Q 投影出口。历史实测表明，相同输入和权重下，GEMM 行数可以改变 BF16 结果。本轮直接观察了 Q 投影：输入、base 权重、LoRA A/B 权重及两阶段输出一致。推理按 2,048 / 2,048 / 560 行处理提示，只有最后一块的 base GEMM 有差异。用原操作数在训练主机重放 560 行，二维和三维调用都逐值复现推理的 131 处差异（最大 0.000244140625）；原整段计算改二维无差。补行至 1,024、2,048 或 4,666，或复用 K/V 校准的分组 GEMM，均消除这 131 处差异。

只替换第 0 层推理侧 Q 的 base GEMM 后，两套 TP4 对原录音均返回相同的 10 个动作，Q 和注意力输出在 4,656 个提示位置逐值对齐。最大单 token / 整段 logprob 差降到 0.025441 / 0.022942，零 top-1 翻转，仍未过门槛。首差移到第 0 层 O 投影；继续拆分其全宽 base 与 LoRA。

第 0 层 O 的输入与权重一致。相同操作数以 560 行重放，逐值复现基础投影的 148 处差异；两个 2,048 行块的 LoRA A 分别复现 5 和 2 处差异。固定实际 B 操作数时，整段与三个分块的 B 输出逐值相等；跨机 B 差异均落在 A 已有差异的块内。分组 A 在整段与分块间相等，但有别于原训练侧整段计算。

仅将第 0 层 O 的基础投影改成分组 GEMM 后，两套服务在全部已观察的第 0 层边界逐值一致，输入和 10 个实际动作不变。提示的首差移到第 1 层，动作预测位置的首差移到第 2 层。最大 token / 整段差为 0.108583 / 0.079442，零 top-1 翻转；较小的整模误差不能替代按依赖定位首差。第 2、3 步仍等待更新态精度验收。

已验证常驻基础模型中首次装入 LoRA。已有适配器切到下一版仍需验收引擎卸载、加载、逐 rank 读回和缓存失效。

## 历史基础服务数值证据

训练主机 的 0–7 卡用于 LoRA/FSDP 训练并承担 HF/verl 精度参考；推理主机 的 0–3 和 4–7 各运行一个 vLLM TP4 实例。旧训练主机退出调度。训练、数据准备和推理沿用同一配置化工程，部署配置绑定实际主机、地址、设备和本地热目录；模型、数据和源码只读挂载。

推理主机 已导入锁定镜像，两实例均通过健康检查和一次真实 P 音频请求，确认 thinking OFF、BF16、KV 与 prefix cache 开启。卡组 B 第一次启动因宿主物理卡号被用作容器逻辑卡号失败；固定启动器现分开绑定 Docker 物理卡和 CANN 容器逻辑卡，复验四张卡均有实际 worker。训练主机 最新检查八张卡均无 NPU 进程。

真实 P 样本的原始请求前缀为 4,656 个 token。两实例、历史轨迹的输入 token 一致。固定第 8 个动作的输入前缀（4,663 个 token）后，两实例均把原动作排在首位，但同动作的 log-prob 仍不同。用隔离 cache salt 排除跨请求 prefix reuse，两个实例对原动作的 log-prob 各为 −0.298903 和 −0.314125；正常 prefix hit 下分别为 −0.241321 和 −0.271510。每实例在正常路线上均观察到 4,608 个缓存命中 token，隔离请求新增命中为 0。此对照证明打分受实际缓存路径影响；尚未定位首个不同算子。

1. 复用正式 RL 的镜像、算子精度配置和 named RPC 采集入口。将原控制器的训练与推理逻辑角色绑定到新物理主机，保留既有账本和 guard。处理旧入口对训练主机必须有两份可恢复 TP4 服务记录的假设：训练主机 应使用已排空设备及既有 guard 的验证，不能伪造旧主机的服务记录；推理主机 两实例独立登记，逐批固定 endpoint 与 adapter 版本。两实例的 LoRA 装载与缓存失效都要有独立回执。
2. 使用 训练主机 实际训练路径和 推理主机 两实例，在同一原始录音、权重、输入、前缀和动作上核对真实音频、prefill、缓存解码。优先验证已定位的第 8 个动作：程序读取实际 Q、逻辑 K/V 和注意力输出；上游表示有偏差时先验证音频与输入，随后才归因到注意力算子。复用已封闭证据，仅针对新拓扑缺口。两条推理路径分别满足最大 token log-prob 差与整段差均 ≤0.01，且全词表 argmax 不翻转；再验更新态。
3. 精度门槛通过后，训练主机 启动 P 训练，推理主机 负责 fresh rollout，CPU 并行准备数据和冻结 references。P 奖励为正确意图第 1/2/3 位 1/0.75/0.5，未进入输出 0；训练前置准入仍按动态召回是否含 gold。优先取得同一 optimizer 连续三步真实 loss，按完整 DEV 观察 reward 与 P@3，之后锁定发布镜像并转 S1。三步不是已采样训练集完成，也不是 DEV 收益。
