# P 节点训练与双 TP4 推理迁移

训练主机 的 0–7 卡用于 LoRA/FSDP 训练并承担 HF/verl 精度参考；推理主机 的 0–3 和 4–7 各运行一个 vLLM TP4 实例。旧训练主机退出调度。训练、数据准备和推理沿用同一配置化工程，部署配置绑定实际主机、地址、设备和本地热目录；模型、数据和源码只读挂载。

推理主机 已导入锁定镜像，两实例均通过健康检查和一次真实 P 音频请求，确认 thinking OFF、BF16、KV 与 prefix cache 开启。卡组 B 第一次启动因宿主物理卡号被用作容器逻辑卡号失败；固定启动器现分开绑定 Docker 物理卡和 CANN 容器逻辑卡，复验四张卡均有实际 worker。训练主机 最新检查八张卡均无 NPU 进程。

真实 P 样本的原始请求前缀为 4,656 个 token。两实例、历史轨迹的输入 token 一致。固定第 8 个动作的输入前缀（4,663 个 token）后，两实例均把原动作排在首位，但同动作的 log-prob 仍不同。用隔离 cache salt 排除跨请求 prefix reuse，两个实例对原动作的 log-prob 各为 −0.298903 和 −0.314125；正常 prefix hit 下分别为 −0.241321 和 −0.271510。每实例在正常路线上均观察到 4,608 个缓存命中 token，隔离请求新增命中为 0。此对照证明打分受实际缓存路径影响；尚未定位首个不同算子。

1. 复用正式 RL 的镜像、算子精度配置和 named RPC 采集入口。将原控制器的训练与推理逻辑角色绑定到新物理主机，保留既有账本和 guard。处理旧入口对训练主机必须有两份可恢复 TP4 服务记录的假设：训练主机 应使用已排空设备及既有 guard 的验证，不能伪造旧主机的服务记录；推理主机 两实例独立登记，逐批固定 endpoint 与 adapter 版本。两实例的 LoRA 装载与缓存失效都要有独立回执。
2. 使用 训练主机 实际训练路径和 推理主机 两实例，在同一原始录音、权重、输入、前缀和动作上核对真实音频、prefill、缓存解码。优先验证已定位的第 8 个动作：程序读取实际 Q、逻辑 K/V 和注意力输出；上游表示有偏差时先验证音频与输入，随后才归因到注意力算子。复用已封闭证据，仅针对新拓扑缺口。两条推理路径分别满足最大 token log-prob 差与整段差均 ≤0.01，且全词表 argmax 不翻转；再验更新态。
3. 精度门槛通过后，训练主机 启动 P 训练，推理主机 负责 fresh rollout，CPU 并行准备数据和冻结 references。P 奖励为正确意图第 1/2/3 位 1/0.75/0.5，未进入输出 0；训练前置准入仍按动态召回是否含 gold。优先取得同一 optimizer 连续三步真实 loss，按完整 DEV 观察 reward 与 P@3，之后锁定发布镜像并转 S1。三步不是已采样训练集完成，也不是 DEV 收益。
