These modules go in the existing collection-dispatch integration pipeline alongside dataset_encoder and p_screen_inputs. The screen runner reads the deployment's per-port bindings and group admission mode, checks each adapter activation after its first batch, and carries each observation's engine and policy into export. The reconciliation entry accepts only a complete wave matching the configured runtime, row boundary, count, and explicit pre-generation boot refusal. It archives each original attempt under the screen guard before reopening those recordings.

For a reserved multi-host collection window set `required_lanes_by_host` in the screen config, e.g. `{"train":2,"rollout":2}`. The runner compares the configured host set and lane counts with this allocation before touching the screen ledger or submitting requests.
