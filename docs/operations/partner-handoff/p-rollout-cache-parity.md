# P 节点实际 rollout 的缓存路径和发布状态

同一严格 step 1 checkpoint 下，原两段音频共 8 个请求、98 个动作。用 FSDP8 对 HTTP 返回的实际动作逐项评分，训练前向和评估前向结论相同。A 路 4 个请求全部超出 0.01，B 路 4 个逐值一致。首个失败请求的第 6 个动作，推理和训练的 logprob 分别为 −0.398272276 和 −0.440951318。原 HTTP 没有记录全词表 top-1。

同机双 TP4 在不同请求历史下重新自然采样后，FSDP8 验证 A 路 4/4 逐值一致，B 路 0/4 通过，8 个请求的 top-1 均无翻转。原训练检查点恢复成功，各 rank 报告零次更新。对照的分母是各自实际采出的动作。

将另一段录音放在原失败录音之前，并为这两个请求使用同一个新缓存命名空间，服务分别记录了 0/4656 和 2176/5531 个前缀 token 命中。目标请求的 11 个动作和 11 个行为 logprob 精确复现。命中范围在音频之前。仅改变 HF 全层 Q/O 基座分组算术的配对试验，原轨迹的差异不变。缓存历史可在同机触发该故障，底层首个数值分歧仍需算子轨迹。

历史发布 d9259501d、47b2c5aba、4bb653196 分别保留首步与确定性梯度、更新态切换和跨机校准证据。更新态窗口为 6 个请求、70 个动作。对 a5e00146d 与实际部署的 8 项关键文件进行 SHA-256 比对，5 项一致。续训驱动及其训练入口使用较新的实现，TP 侧 attention 文件版本也不同。后者的代码差异局限于 HF 反向分支。此审计只涵盖清单列出的组件。

## 发布复核

在拥有 Git 仓和已部署文件的控制端运行下列命令。roots JSON 将 training、rollout 分别映射到封闭的训练包和推理 bundle 的本地根目录。固定 Git 提交提供预期字节，部署目录提供观察值。缺件和摘要不一致会导致非零退出。版本相同的后续节点复用回执。

```sh
python tools/system_rl/runtime_repairs/verify_runtime_sources.py \
  --repo . --lock docs/operations/partner-handoff/p-rollout-source-lock.json \
  --roots "$DEPLOYMENT_ROOTS"
```

正式基线以同一个发布版本绑定镜像、训练与推理源码、模型及 LoRA、精度配置和可复现的场景。此次发布的是原版本的核验清单和失败记录。数值验收要求在冷启动、同录音重复、跨录音部分命中及实际更新态上，对生成动作做同权重评分，每个请求的最大单 token 和整段 logprob 差均 ≤0.01，全词表 top-1 零翻转。缓存路径须有请求级命中回执。两项差在任一路超线即保留失败状态。正式 Clock 仍为 step 1。

**按实际算子定位。** 在同机的双 TP4 上，先用另一段录音预热，再与独立实例的冷目标按绝对位置配对。四个 rank 的共享前缀在每个已采位置的摘要相等；目标剩余部分在第 30 层（零起算）Q/K/V 及进入 O 投影的输入相等，但 O 输出四个 rank 均不同。较粗的 norm 轨迹到第 31 层 post 才可见偏差。此结论只覆盖观测到的边界；前面所有层并未逐个采 O，不能断言第 30 层一定是整模全局首差。详见同目录 p-rollout-window-comparison.json。第三轮在实际 O row 函数内采集：四个 rank 共享前缀均相同；后缀完整输入、基座投影结果和 adapter 索引相同，LoRA A 的 BF16 linear 输出首先不同，LoRA B 及 O 输出随之不同。见同目录 p-rollout-o-operands.json。已锁定该分支；是否由有效行数改变了 NPU GEMM 选路或累加方式，仍需相同权重与操作数的定点复验。采样序列本身不要求冷、热相同；验收是对每条路径实际产生的动作做同策略评分。

**统一封存。** 正式准备入口要求 runtime_release 对象，release_commit 指向含锁清单的完整不可变 Git 提交，repo、roots.training 和 roots.rollout 从部署配置解析，均指向实际的只读部署副本。启动前从提交本身读取清单，分别核对清单源版本和发布提交的源码；任一偏差即退出。RUNTIME-SOURCES.json 是源码核验回执，不构成数值验收。现场 3 项差异的精确源码差分保存在 reproduction/，只供还原失败，未替换已验收实现。同一镜像、两端源码、模型、adapter、精度、拓扑、缓存配置及输入范围共同界定可复用的验收；变化时只重跑受影响范围。冷、同录音重复、跨录音部分命中、真实更新态各自需要实际回执。首步继续保留；没有合格第二步。


固定行数的复验补上了跨录音部分命中的反例。同一更新态在 48 层 O 的 LoRA A 上按 4096 行分块计算。热请求命中 2176/5531 个前缀 token，11 个实际动作的最大单 token 差为 0.042679，整段差为 0.041136。冷请求的 12 个动作用同一 checkpoint 复算，两项差均为 0。FSDP8 的 train 与 eval 结论一致，两条路径的全词表 top-1 翻转均为 0，优化器更新数为 0。第 30 层 A/B 中间值仍然不同，这次该层 O 的最终输出摘要相同。固定 4096 行的候选未通过，见 [配对回执](p-rollout-row-geometry-control.json)。

此前的发布锁清单覆盖 8 项源码，遗漏了实际执行 LoRA A/B 的投影文件。本版将它作为第 9 项加入同一清单，来源是原现场与本地实现逐字节相同的版本。训练和推理采用同一个 release_commit 并复用正式准备入口，部署核验成功后按已验收的数值场景范围使用。正式训练仍为 step 1。

第 30 层 O 的乘法现场已复核。两套 TP4、48 层的 Q/K/V/O 共 3072 个 A/B 分片与 checkpoint 全部相符。Q/K/V 在每个 rank 复制 A，沿输出通道切 B。O 沿输入通道切 A，复制 B。现场 O 在相同顺序下拼回完整输入与 A。跨录音命中 2176 个前缀 token 后，冷、热共有的 3355 行输入逐值相同，26840 个 BF16 中间结果中有 9 个不同。单卡原生 linear 精确复现两个窗口。同一 2048 行矩阵循环移动 128 行再还原，3 个元素改变，原位重复为 0 个。由此可将该算子的部分舍入差异定位到批内行位置。单卡 grouped matmul 的冷、热差为 0，与整段原生 linear 比较仍分别差 16 和 11 个元素。整模充分性与更新后训练验收另计。见[算子复验回执](p-rollout-o-row-replay.json)。

对 48 层 O LoRA A 同时在推理和训练评分侧使用 grouped BF16 乘法后，第 30 层 O 的所有已测冷、热中间值均相同。第 31 层 post 仍有差异。首次 HF 诊断对 PEFT 输入的 dtype 假设错误，修复 BF16 autocast 边界后，8 个 rank 完成复算，独立算子输入和 FP32 主参数的梯度对照均逐值相同。冷请求 12 个动作两项概率差均为 0，热请求 11 个动作的最大单 token 和整段差分别为 0.042679、0.041136，与原失败结果相同。两请求均无 top-1 翻转。此次候选未通过，训练 Clock 为 1。见[整模对照回执](p-rollout-o-grouped-control.json)。

**Q/K/V/O LoRA A 配对修复。** 第 31 层的两路残差、归一化输入和 Q/K/V 基座一致，四个 rank 最先观测到的局部分歧均是 Q/K/V LoRA A。只有 rank 3 的最终 Q 出现差异；O 汇聚四卡的 attention 输出，故在其他卡同样可见。两套服务的适配器切片已按各自的切分方向逐值验证。保留这些布局，将 48 层 Q/K/V/O 的 LoRA A 在两端统一为分组 BF16 矩阵乘。对同一录音分别命中 2176/5531 和 0/5531 个前缀 token 后，各 rank 的 148 个已观测边界在共同前缀及后缀全相等。train 和 eval 对各自实际采样动作复算：热 11、冷 12 个动作的最大单 token 差和整段差均为 0，两个宽度的输入和可训练主参数梯度在独立 VJP 对照中相等。冷、热各自采样的 token 可以不同。此验收没有 optimizer 更新。
