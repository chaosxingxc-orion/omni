同一严格 step 1 checkpoint 下，原两段音频共 8 个请求、98 个动作。用 FSDP8 对 HTTP 返回的实际动作逐项评分，训练前向和评估前向结论相同。A 路 4 个请求全部超出 0.01，B 路 4 个逐值一致。首个失败请求的第 6 个动作，推理和训练的 logprob 分别为 −0.398272276 和 −0.440951318。原 HTTP 没有记录全词表 top-1。

同机双 TP4 在不同请求历史下重新自然采样后，FSDP8 验证 A 路 4/4 逐值一致，B 路 0/4 通过，8 个请求的 top-1 均无翻转。原训练检查点恢复成功，各 rank 报告零次更新。对照的分母是各自实际采出的动作。

## 发布复核

在拥有 Git 仓和已部署文件的控制端运行下列命令。roots JSON 将 training、rollout 分别映射到封闭的训练包和推理 bundle 的本地根目录。固定 Git 提交提供预期字节，部署目录提供观察值。缺件和摘要不一致会导致非零退出。版本相同的后续节点复用回执。

```sh
python tools/system_rl/runtime_repairs/verify_runtime_sources.py \
  --repo . --lock docs/operations/partner-handoff/p-rollout-source-lock.json \
  --roots "$DEPLOYMENT_ROOTS"
```

正式基线以同一个发布版本绑定镜像、训练与推理源码、模型及 LoRA、精度配置和可复现的场景。此次发布的是原版本的核验清单和失败记录。数值验收要求在冷启动、同录音重复、跨录音部分命中及实际更新态上，对生成动作做同权重评分，每个请求的最大单 token 和整段 logprob 差均 ≤0.01，全词表 top-1 零翻转。缓存路径须有请求级命中回执。两项差在任一路超线即保留失败状态。正式 Clock 仍为 step 1。
