# P 训练：生产者按录音供给，消费者按轨迹更新

正式基线按 128 条 TRAIN 录音准备一页，每条保留自己的录音引用、标注与召回材料。每个完整策略步只取 32 条录音；同一策略对每条采 4 次，得到 128 条轨迹。8 个 rank 每轮各消费 8 条，累积两轮，最后统一做一次 Adam 更新。下一步可以提前准备静态材料，但动作、行为概率必须等下一版策略；reference 对实际采出的动作评分。页的边界不是策略或优化器的边界。

目前生产路径依次经过：读取静态页 → 新策略采样 → 冻结 reference 批量评分 → 各 rank 封组 → rank 0 发布并验收整批 → 各 rank 读取 → 两轮微批前向/反向 → Adam 和 checkpoint。第 61 步命令到 reference 就绪 100.228 秒，至所有组封闭再用 2.984 秒，至整批发布再用 26.288 秒。更新开始至 loss 259.684 秒。前 100.228 秒含命令准备及 reference 评分，不能全算 CPU 准备，更不能计为此改造可以省掉的时间。

候选实现按真实生成结果及已登记的长度分卡算法先定顺序。在同一录音的完整 4 个回复上计算组优势；保留整步分母、全局 padding 与原来的逐卡次序。读取某一轮实际需要的 GROUP（包括已登记的真实 reference 概率），用原消费者的字段打包代码构造微批。消费一轮时最多预取一轮。收到第二轮与完整验收回执后再允许 Adam；准备或对账失败均清梯度，不重发 rollout。

公开复现入口：固定镜像中使用训练源码、已封闭的 GROUP 与原 actor packet，运行 check_recording_wave_producer.py（--acceptance 或 --native），几何参数从封闭的 TRAIN.local.json 读取，--source 与 --sha256 指向登记的 consumer；check_native_wave_abort.py 验证失败边界。运行时将候选 source、测试脚本加入 PYTHONPATH；CPU 容器只读挂载原输入，无需 NPU。

**微批提前前向尚未切入正式作业。** 已部署的 finalize_and_run 仍等待整批，再由 PreparedBatch 与 task.prepare 建立 loss 输入和 Clock。候选已验证微批字段和原生循环，未验证把正式整批发布移到后台后，真实 FSDP8 的梯度、Adam、checkpoint 恢复及下一步接续。在已有正式作业上直接开启会越过这项验收。热步基线为 680.314 秒（第 56–60 步，首派到首派），不能把 1.845 秒当作训练步耗时，也不能宣称已有整步加速。

第 66 步补充：正式作业的 2,949 条录音已分成 24 页，前 23 页各 128 条，末页 5 条。第 66 步在同一 actor 主机上，命令到 reference 就绪 96.572 秒，封组 3.040 秒，随后整批发布 26.588 秒，开始更新至 loss 253.124 秒。CPU 提前准备不能消除 reference 前向或梯度计算。

候选现已接入正式入口的可选配置 `first_wave_forward: overlap_publish_v1`。在同一轮 GROUP 已就绪后，rank 0 启动独立的 CPU 发布进程，各 rank 可准备本卡的首轮输入并保留其前向计算图；完整包验收、首轮字段与顺序对账后，原 verl 循环消费这张图并反向，再正常消费下一轮。第 61 步固定训练镜像、rank 0 的 CPU 回放，以启动发布为零点：首轮字段就绪 1.095 秒，进入测试头前向 2.857 秒，等待发布结束的同步点 22.848 秒，实际消费计算图 24.521 秒。完整训练字段一致；含 dropout 的测试头输出、梯度及 RNG 状态与常规路径逐值相同。不同于实际八卡整模前向；不能将两时间戳的差作为正式整步收益。正式作业仍用已验证的 actor。

控制器回传另有独立瓶颈：缓存清单随步数增长，从 1,795 项增至 1,823 项，原 SSH 单参数在第 66 步超过系统限制。修复将清单走标准输入，保持对象验收与原子归档；修后实际读回第 66 步的封闭结果。旧 worker 因等待下一条命令 1,200 秒退出。接续前同时核对旧容器已退出、下一条命令在远端从未创建、没有结果目录、上一条命令的 checkpoint 与封闭回执相符、本步采样已排空。拒绝把未能确认结果的请求重新提交。

第 68 步的正式消费已与静态页逐条对账：第 17 页的最后 32 条录音（全局零基区间 [2144,2176)），128 次真实采样、未知 0；每卡 8+8，loss 0.05866504。report_recording_macro_update.py 将页顺序、录音、生成回执、各卡实际行数与已提交的 checkpoint 关联；尾页按实际行数统计，集合通信中的零权重补位不计样本。剩余 773 条录音，按当前窗口是 24 个满窗加 1 个 5 条的尾窗。

表中的子段不能再与首派到首派相加。readback 现在只检查本次封闭命令引用的对象。第 67 步同源重放：全库存 1,880 项、25.846 秒，定向检查 30 项、0.451 秒；两次生成的 471,541,760 字节传输包内容摘要一致。切换 CPU 控制器后，第 68 步实际检查 30 个引用、0.053 秒，2 个对象命中本地缓存，完整回执入账。不能把 CPU 对照的差值当作整步节时。

推理派发还有一道单独的等待：两路各 64 个请求，均在本路输入全部就绪后开启发送。第 68 批两路从首份到末份供给为 5.140/4.632 秒，第 69 批为 45.952/46.188 秒。源码 dispatch_draws 在启动线程池前串行调用各录音的 prepare，并逐项核对既有请求。两批足以定位等待发生在向推理服务首派之前，不能据此断言是某个存储调用或推理引擎变慢。进一步优化应分别计量公共静态材料、逐录音准备、逐次采样的身份绑定和落盘；可复用的是已封闭的逐录音内容，实际请求、资源登记、种子、行为策略和概率各有自己的身份。

本轮没有替换 FSDP8 worker。正式循环只接受当前策略的更新和结束，不支持在同一活动进程中回卷旧 checkpoint 试跑。以第 68 步 30.992 秒发布段作满窗的乐观估算，25 个窗口约 775 秒，且最后一窗非满批。新建并恢复 worker 第 67 步实测 206.992 秒；旧路径未保存逐元素梯度，用同一数据做基线与候选两次完整隔离更新，光按第 68 步更新意图到 loss 估算即约 512 秒，尚未计入 reference、产物封闭和正式接续。没有足够的本轮净收益依据。可选的首轮提前前向保留在候选配置，正式值仍关闭；以后做八卡对照须固定输入、上一 checkpoint、各卡 RNG、分卡顺序，在隔离输出比较逐元素梯度、Adam、参数、loss 和 Clock，数值最大绝对差不超过 1e-8 后才考虑切换。

第 71 批上线：生产者按录音复用 screened_packet 的路径原已存在。本次改变的是反复启动 findmnt 的存储检查。在每路绑定同一真实本地挂载后，用目录句柄核对挂载身份，每次仍检查剩余空间和 inode；其它挂载走原校验器。固定控制镜像回放第 69 批 128 个真实请求的 384 个文件，内容逐字节一致，原 1,024 次挂载查询降为 1 次，保留 1,024 次实时检查，回放 5.480→1.348 秒。空间不足、inode 耗尽、跨到非本地存储、不可变文件内容冲突均被拒绝。回放覆盖请求文件发布段，不含模型推理或整个步。

在第 70 步训练签收后仅交接 CPU 控制器。第 70 步正常提交（2,240/2,949 条，loss 0.11455397）。第 71 批两路各收回 64 个不同请求，未知 0，原 worker 继续更新。目标挂载每路鉴定一次，各做 899/898 次实时检查，各有 1 次不同挂载交回原校验器。首份供给至首派 2.980 秒；切换前四个正常窗口 4.476–4.752 秒，一次长尾 46.936 秒。第 71 批的两路备料跨度分别为 2.892/4.248 秒；checkpoint 返回至首派总计 110.772 秒，其中更新标记发布与激活 38.932+57.444 秒，不能把长尾差值外推为每步节时。配置和回放入口见 START-EXPERIMENT.md；已启用本地站点默认配置，训练 worker 及 LoRA 数值路径未切换。

第 72 步后从原作业发布新 LoRA 使用原始字节传输，原控制器接续、训练进程和两个 TP4 保留。CPU 生产者每页 128 条不同录音，只提前准备不随策略改变的材料，包括逐录音召回的知识和指令；动作、token 和行为概率保持新策略采样。满步取连续 32 条录音，各采 4 条。消费端按 8 卡、每卡两轮各 8 条轨迹完成一次更新。第 72 步训练实录：录音偏移 [2272,2304)，128 条真实轨迹，loss 0.07210167。签收到 reference 就绪 96.460 秒；封组到整批输入发布 24.244 秒；更新开始到全卡 loss 255.488 秒。当前仍等待整批输入发布后才开始前向；跨批提前消费候选没有在线上开启。

服务端策略切换还会分别校验新、旧、新、新四份发布引用。固定镜像独立 CPU 进程以同一实际前后继运行四次校验，用单线程、保留 Clock、模型及资产核对。原实现合计 50.085 秒；限定同一进程、同一切换、同一文件完整字节摘要和几何形状，复用张量分析的实验对照为 28.725 秒；旧策略身份替代新策略的负例被拒绝。两路 TP4 并行，这个差值不能乘二，也不是设备热加载实测节时。容器从启动至首次实际设备激活曾分别用 381、351 秒；至两路正式启动验收约 482 秒。以尚余 20 次策略转换、每次约 21.36 秒估算，总机会约 427 秒，且未计候选上线与同策略服务接续验收。此轮不为该候选中断服务。跨轮评估时可在新服务首次部署前预置并验收，逐卡实际读回仍必需。
