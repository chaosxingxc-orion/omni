# P 训练：生产者按录音供给，消费者按轨迹更新

正式基线按 128 条 TRAIN 录音准备一页，每条保留自己的录音引用、标注与召回材料。每个完整策略步只取 32 条录音；同一策略对每条采 4 次，得到 128 条轨迹。8 个 rank 每轮各消费 8 条，累积两轮，最后统一做一次 Adam 更新。下一步可以提前准备静态材料，但动作、行为概率必须等下一版策略；reference 对实际采出的动作评分。页的边界不是策略或优化器的边界。

目前生产路径依次经过：读取静态页 → 新策略采样 → 冻结 reference 批量评分 → 各 rank 封组 → rank 0 发布并验收整批 → 各 rank 读取 → 两轮微批前向/反向 → Adam 和 checkpoint。第 61 步命令到 reference 就绪 100.228 秒，至所有组封闭再用 2.984 秒，至整批发布再用 26.288 秒。更新开始至 loss 259.684 秒。前 100.228 秒含命令准备及 reference 评分，不能全算 CPU 准备，更不能计为此改造可以省掉的时间。

候选实现按真实生成结果及已登记的长度分卡算法先定顺序。在同一录音的完整 4 个回复上计算组优势；保留整步分母、全局 padding 与原来的逐卡次序。读取某一轮实际需要的 GROUP（包括已登记的真实 reference 概率），用原消费者的字段打包代码构造微批。消费一轮时最多预取一轮。收到第二轮与完整验收回执后再允许 Adam；准备或对账失败均清梯度，不重发 rollout。

公开复现入口：固定镜像中使用训练源码、已封闭的 GROUP 与原 actor packet，运行 check_recording_wave_producer.py（--acceptance 或 --native），几何参数从封闭的 TRAIN.local.json 读取，--source 与 --sha256 指向登记的 consumer；check_native_wave_abort.py 验证失败边界。运行时将候选 source、测试脚本加入 PYTHONPATH；CPU 容器只读挂载原输入，无需 NPU。

**微批提前前向尚未切入正式作业。** 已部署的 finalize_and_run 仍等待整批，再由 PreparedBatch 与 task.prepare 建立 loss 输入和 Clock。候选已验证微批字段和原生循环，未验证把正式整批发布移到后台后，真实 FSDP8 的梯度、Adam、checkpoint 恢复及下一步接续。在已有正式作业上直接开启会越过这项验收。热步基线为 680.314 秒（第 56–60 步，首派到首派），不能把 1.845 秒当作训练步耗时，也不能宣称已有整步加速。

第 66 步补充：正式作业的 2,949 条录音已分成 24 页，前 23 页各 128 条，末页 5 条。第 66 步在同一 actor 主机上，命令到 reference 就绪 96.572 秒，封组 3.040 秒，随后整批发布 26.588 秒，开始更新至 loss 253.124 秒。CPU 提前准备不能消除 reference 前向或梯度计算。

候选现已接入正式入口的可选配置 `first_wave_forward: overlap_publish_v1`。在同一轮 GROUP 已就绪后，rank 0 启动独立的 CPU 发布进程，各 rank 可准备本卡的首轮输入并保留其前向计算图；完整包验收、首轮字段与顺序对账后，原 verl 循环消费这张图并反向，再正常消费下一轮。第 61 步固定训练镜像、rank 0 的 CPU 回放，以启动发布为零点：首轮字段就绪 1.095 秒，进入测试头前向 2.857 秒，等待发布结束的同步点 22.848 秒，实际消费计算图 24.521 秒。完整训练字段一致；含 dropout 的测试头输出、梯度及 RNG 状态与常规路径逐值相同。不同于实际八卡整模前向；不能将两时间戳的差作为正式整步收益。正式作业仍用已验证的 actor。

控制器回传另有独立瓶颈：缓存清单随步数增长，从 1,795 项增至 1,823 项，原 SSH 单参数在第 66 步超过系统限制。修复将清单走标准输入，保持对象验收与原子归档；修后实际读回第 66 步的封闭结果。旧 worker 因等待下一条命令 1,200 秒退出。接续前同时核对旧容器已退出、下一条命令在远端从未创建、没有结果目录、上一条命令的 checkpoint 与封闭回执相符、本步采样已排空。拒绝把未能确认结果的请求重新提交。
