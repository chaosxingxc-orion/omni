# S 节点意图内槽位区分知识：设计依据与实施方向

## 决策纠正

将“同意图槽位区分知识”确定为 S 知识体系的长期组成部分。历史局部实验评估的是特定卡片、提示方式和数据口径，不能据其短期得失否定这条结构设计。此前将未晋级结果直接用于暂缓整个方向，混淆了方案与实现两个层级。

保持当前运行基线，是为了结果可比较；不意味着放弃该结构。已有设计、来源、对照示例、冲突和实验轨迹继续复用。实验发现退化后要定位知识组织或消费环节，不重新回到是否需要区分知识的讨论。

## 从任务本身推导需要什么

S 接收语音 A、候选意图 I、该意图允许的槽位集合 T(I)，输出出现的类型集合 Y，且 Y 是 T(I) 的子集。意图限定了可选范围，但并不能确定每个类型是否出现，也不能消除同一意图内相邻类型的歧义。

单卡定义描述“这个类型是什么”，共同区分知识描述“同一表达在什么角色下对应哪种类型”。词面相同可以承担不同角色；一句话也能同时表达多个角色，因此不能简单做互斥分类或关键词匹配。任务应表达为意图条件下的多标签存在性判断。

形式上可将决策依据写成：

`score(Y | A,I,K) = Σ[t∈Y] evidence(t,A,I,K) + Σ[(t,u)∈E(I)] compatibility(t,u,A,I,K)`

第一项对应各槽位的语义证据；第二项对应真正易混槽位之间的区分与共存关系。它是设计分解，不要求模型输出分数，也不引入手工加权解码器。E(I) 按原业务定义和实际混淆关系构建，不做全部槽位的笛卡尔积。

若知识提供原输入没有明确表达的业务判别规则，就能减少与任务相关的不确定性；如果只是重复已有定义，则不必然增加信息。规则错误、互相矛盾、位置不当或模型未使用时，收益也不会自动实现。因此“结构有充分依据”和“当前版本已获得收益”需要分别记录。

## 稳定知识结构

|层次|应供给的信息|约束|
|---|---|---|
|意图内槽位索引|允许类型及其业务角色|允许出现不等于本句存在|
|单类型定义|语义范围、存在证据、无具体值情形|不要求槽值才能确认类型|
|共同区分卡|相邻类型的差异依据、同词不同角色、共存条件、不能依赖的线索|双方共用一份定义，不分别写互相冲突的绝对规则|
|来源示例|真实同意图锚点、角色对照、共存、未表达情形|TRAIN 来源；未标注不直接当可靠负例|
|冲突记录|标注争议、缺少依据和适用边界|供分析审查；不把整份冲突日志塞入推理提示词|

共同区分卡必须绑定锁定知识来源，不允许模型凭空补业务事实。教师负责归纳策略、指出冲突、建议组织方式；程序从合法来源编译供给。P 的相似问也要区分召回覆盖价值与 few-shot 判别价值，两者不必由同一批样本承担。

## 当前实现步骤

1. 完成正在准备的清洗基线和同供给策略对照，不等待所有知识设计工作结束。
2. 复用既有对照知识，为每个意图建立易混类型关系表。优先处理已有类型定义相互矛盾、角色依赖明显的关系，逐步覆盖，不只挑几个容易成功的样本。
3. 采用配置化的共同区分卡结构，把类型定义、共同边界、示例与冲突审计分开；before_model_call 按意图装配，after_model_call 保持结构和合法性检查，不靠关键词覆盖模型答案。
4. 知识正确性检查关注共同定义是否一致、是否有合法来源、是否保留共存和无值类型。类型任务投影去除槽值格式要求时，保留角色区分语义。
5. 在固定开发集上按问题类别、意图和角色组合评价。诊断前后信息是否真正进入请求、模型是否使用，再分析多提、漏提、共存与无值类型的变化。
6. 用足够覆盖和必要的重复推理判断收益稳定性。局部错例用于解释机制，完整开发集用于选择实现版本，锁定后再测试。测试收益不反向用来挑知识。

## TFRL 的优化对象

固定槽位定义和来源边界，优化共同区分知识的表达、排列、精简方式以及示例选择。给教师的反馈是按错误机制分组的统计、代表轨迹、来源冲突和前后变化，不要求逐样本编答案。多策略候选先查知识一致性，再并行实测；对失败候选解释其具体失效机制，保留设计方向和可复用证据。指标同时保护漏提、混淆提取、共存和无值类型，不能仅凭总体 exact 上升即推广。
