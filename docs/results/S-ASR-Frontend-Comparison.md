# S节点模型直接替换对照

更新：2026-11-10。用户明确要求直接使用Qwen3-ASR替换S节点的Omni模型。此前“ASR转写→Omni文本抽取”是任务理解错误，已停止推进，不作为用户要求的模型对比。

## 统一任务与输入输出

两个模型接收同一份语音、冻结P候选意图、知识卡、few-shot、任务指令与相同输入顺序，直接输出同一槽位JSON。复用545条、1635分支，476学习/69来源隔离和原评分；不能先转写再调用第二模型、不能使用参考文本补槽或更换评测任务。

统一当前工程基座、数据供给、before/after rails、解析、失败统计与评测。模型权重/tokenizer/必要音频处理与不支持的模型专属参数属于必须记录的接口差异，不能声称不同模型拥有相同token序列。总输出预算、并发和资源按可比较方案固定；原生上下文若不兼容，明确记录限制，不截断知识卡假装输入相同。

## 执行顺序

1. 复用现有权重与固定镜像，验证底层vLLM生成接口和真实模板能保留任务、知识及音频。不能只用强制转写的接口来判断模型能力。
2. 在冻结学习集预先确定的小批量上，直接检查任务遵循、有效槽位输出和准确率；保留原始输出，无效响应计入分母。
3. 可执行后运行完整545，与当前基线新跑的Omni结果对照。若接口或模型不能完成同一任务，报告直接替换不适配的实测证据，不改成串联系统。
4. Omni ON/OFF本身也必须新跑当前相同基线双臂，历史ON不得作为正式控制组。

## 状态与指标

直接替换的CPU实现任务已启动，尚无Qwen3-ASR直接槽位推理结果。旧转写链路CPU包仅保留权重hash、原始音频等可复用材料；旧实验不准入NPU。

主要比较全槽正确率、typed/strict/official、漏提误提、有效回答率，以及同任务全部耗时、tokens和资源。WER不作为本次模型替换的主指标。实例部署须在现有任务交接窗口完成，已释放D不重启。

## 实际输入检查
固定镜像真实processor CPU检查通过：默认模板会丢掉多块文本中的知识内容，外部模板按原输入顺序保留system、文本与音频，未强制language/asr_text前缀。代表输入的音频特征和文本均可处理；这只是输入检查，不是权重加载或槽位任务通过。B实例当前验证任务结束后已预留模型部署窗口，未中断当前任务，未释放或启动D。
