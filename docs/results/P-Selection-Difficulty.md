# P消费的筛选难度与收益

## 为什么整体保留率还需分层

P的当前合同是输入1–5个合法候选，输出恰好min(3,候选数)个索引。因此输入不超过3类时，合法输出必须保留全部候选，集合覆盖来自供给与协议，不证明模型能正确区分候选。主线程按真实封存1080行重新分层，不改变样本集、gold或原指标。

|分层|B双向路线|C LCO路线|
|---|---:|---:|
|全部样本：供给内保留|1001/1016（98.52%）|996/1010（98.61%）|
|输入≤3：样本数|772|758|
|输入≤3：供给命中 / 输出命中|756 / 756|742 / 742|
|输入4–5：样本数|308|322|
|输入4–5：供给命中 / 输出命中|260 / 245|268 / 254|
|输入4–5：供给内保留率|94.23%|94.78%|
|输入4–5：直接取前三 / P输出命中|232 / 245|238 / 254|

B的15条消费丢失全部来自需要筛选的308条；其中输入4类丢2条，输入5类丢13条。P相对直接取前三仍有真实净收益：修20退7，净增加13条。不是整体98.52%都来自选择能力，也不能反过来说P没有收益。

## 如何指导下一轮

对P提示/上下文策略，同时报告全1080和输入4–5的子层，定位操作/对象未被保留、竞争域干扰、知识边界冲突等机制。筛选子层来自固定输入合同，不新建开发集、不只评价失败样本。召回策略改变候选数时，两路子层可能不是同一批样本，不能仅比较子层百分比就宣称提升；仍需全量配对修退。

B的308条中，134条输出集合与原始前三相同，99条顺序也相同。父排序本就经常正确，这些数字本身不能证明P忽略音频。对明确动作却选中竞争语义簇的错例，需要结合真实候选、卡和输入证据检验假设。

输入≤3时程序直通有潜在成本价值，但P仍可能改变顺序，后续S是否受影响尚未验证。当前不据此跳过节点，也不把该工程探索变成新前置依赖。优先修复有证据的召回与筛选错误，冻结P后再验证下游行为。

本页为开发集诊断，未新增模型调用、向量编码或TEST分析。所有例外仍须逐条确认；目前确认例外0。
