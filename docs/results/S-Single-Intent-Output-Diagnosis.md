# S 单意图输出失败：机制与配对证据

在冻结的已完成轨迹中，无示例C共364个分支，动态few-shot D共385个分支。逐行核对原始响应、实际请求与来源后发现：129个长度截断均已写完entities数组，随后连续输出空白，尚未开始evidence_refs和unresolved_fields；不能统一解释成“思考用完预算”。

358对的音频、知识卡、schema、提示词、解码参数一致；345对只增加两条合法TRAIN示例，另外13对没有可用示例，实际模型输入完全一致。删除示例块后358对wire均一致。请求身份、运行实例和时段各自不同，按“两边均完成”取交集仍有选择偏差。

345个带示例分支修复128、退化0；13个相同输入分支也有修复2、退化1。因此示例改善稳定性的信号很强，但不能把所有变化机械归因于示例，仍需完整配对与语义评分。

## 两种失败机制

1. **结构间空白循环。** 129个截断中有33个thinking不足1536 tokens；最少238 tokens。实体数组之后连续915–4960个空白字符。优先单独验证紧凑完整JSON提示，保持原schema与预算。
2. **把允许的槽类型当作必须填写的清单。** 空槽值输出中，模型有时已判断没有对应语音片段，仍逐类型输出空字符串。单独验证“缺失mention不创建实体对象，完全没有适用mention则entities为空”的提示，不能将全部非正确候选机械清空。

无效响应与成本保留，不补括号制造成功，不删除失败样本。两个机制候选已交队列，效果尚待完整实验。

## 推理引擎与教师反馈

固定镜像源码存在引擎级disable_any_whitespace，需显式xgrammar或guidance；request同名字段虽能被协议接受，所检查后端并未读取它，不能靠extra_body声称修复。当前没有修改在线引擎，也没有证明后端bug。若提示无效，可独立对照同一backend下的空白约束。

教师曾把历史batched版545整样本中的5个截断，与当前single版分支统计混为一谈，从而错误得出修复上限。主审拒绝该结论。后续证据显式携带架构、父版本、实验臂、统计单位、完整/部分状态和分母。

原诊断749个独立分支已固定镜像CPU复算；358配对为本机CPU增量核验，两者范围分开记录。没有新增模型或教师调用来完成这份诊断。
