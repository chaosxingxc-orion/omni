# 持续队列存储故障与恢复

## 当前队列断链接续修复

已部署新的最小补丁并重启CPU队列进程，模型服务保持运行。A/B默认恢复基座原先缺少语义父manifest，已改为验证过的现存完整输入基座。这个缺依赖错误与磁盘满是两个问题，不能把恢复失败全部归因于磁盘。

观察SSH与补充读取同时失败时，旧实现会把任务永久记为ERROR。新实现区分派发前与派发后：持久化派发意图之前可安全重试配置准备；意图存在后只能追踪原任务，不重复发送。远端明确错误、服务身份或guard变化仍显式阻断。只有完整终态、1635完成及unknown/absent为0，并通过身份核验后才释放后继；评分异步进行。

固定镜像CPU故障注入复现4项旧错误，44项候选测试通过。已核验新本机队列进程和两主机helper字节一致。实际B任务中已中断本机SSH等待客户端，队列继续读取同一任务并归档344条响应，派发与启动记录未变；B原任务随后完整完成1635有效、未知0；因恢复后轮询有延迟，主重启同代码CPU队列验证持久事件恢复，B同事件评分、C同launch继续，派发SHA均不变。这个演练不覆盖服务器重启或持续网络分区，不能据此声称全部断链场景已完成。

随后将“成功observe后重新挂接同容器docker wait”的最小修正实际部署到新CPU队列，消除连接恢复后固定600秒的额外等待；wait仅作唤醒，仍需真实终态和身份核验。旧44项回归、12项新路径测试及5项安装测试通过，另4项复现旧延迟。模型服务和远端helper不变；新重挂路径已在天气A实际运行期间演练：仅断开本机等待连接，同一CPU队列自动只读核验后创建新的同容器等待连接，派发和启动SHA保持，无人工队列重启。该次已由同一队列自动完成1635有效终态、unknown/absent0与评分，无人工重启介入；不覆盖主机重启或持续网络分区。[增量补丁](../operations/TFRL-Exploration-Queue/wait-reattach.patch)与[部署证据](../operations/TFRL-Exploration-Queue/wait-reattach-evidence.json)保留。

[实际部署补丁](../operations/TFRL-Exploration-Queue/disconnect-recovery.patch)与[聚合校验记录](../operations/TFRL-Exploration-Queue/disconnect-recovery-evidence.json)已归档。补丁需匹配对应旧源码，不是独立队列发行包。当前实验结果和新任务状态以[教师策略反馈](../decisions/S-Teacher-Strategy-Feedback.md)为准，以下为历史存储事件记录。

本轮已解除一项会阻断四路队列的实际故障：其中一台推理主机的Docker分区空间耗尽，新监测容器无法创建；正在运行的两路推理仍继续响应。

## 根因与修复结果

旧归档脚本的终态事件一直处于置位状态，600秒条件被旁路，导致反复打包；打包内容写到标准输出，Docker默认日志驱动又持久化这些二进制归档。三个旧CPU归档进程持续重复工作，共留下2430个已经成功退出、只读挂载原实验目录的重复归档容器。

已停止三个旧归档进程，保存容器身份及检查记录，逐批重新确认退出成功后回收这2430个容器。原始轨迹、失败成本、实验目录、镜像和当前模型服务未删除。Docker分区可用空间由0恢复到约570GB；新监测容器创建及读取成功。两路进度确认分别为1188/1635分支（390/545整样本）和893/2802分支（287/934整样本），未重启推理。

旧脚本最小修复：终态信号仅消费一次；归档失败和缺少终态结果均按600秒重试；归档容器自动回收，禁用二进制标准输出的Docker日志留存。针对实际调度代码的测试覆盖成功和失败重试路径。旧归档进程保持停用，当前滚动实验使用独立的评分与归档流程。
