# 持续队列存储故障与恢复

本轮已解除一项会阻断四路队列的实际故障：其中一台推理主机的Docker分区空间耗尽，新监测容器无法创建；正在运行的两路推理仍继续响应。

## 根因与修复结果

旧归档脚本的终态事件一直处于置位状态，600秒条件被旁路，导致反复打包；打包内容写到标准输出，Docker默认日志驱动又持久化这些二进制归档。三个旧CPU归档进程持续重复工作，共留下2430个已经成功退出、只读挂载原实验目录的重复归档容器。

已停止三个旧归档进程，保存容器身份及检查记录，逐批重新确认退出成功后回收这2430个容器。原始轨迹、失败成本、实验目录、镜像和当前模型服务未删除。Docker分区可用空间由0恢复到约570GB；新监测容器创建及读取成功。两路进度确认分别为1188/1635分支（390/545整样本）和893/2802分支（287/934整样本），未重启推理。

旧脚本最小修复：终态信号仅消费一次；归档失败和缺少终态结果均按600秒重试；归档容器自动回收，禁用二进制标准输出的Docker日志留存。针对实际调度代码的测试覆盖成功和失败重试路径。旧归档进程保持停用，当前滚动实验使用独立的评分与归档流程。
