# P节点知识供给候选：CPU验证

更新：2026-11-07 22:08（北京时间）。这是知识召回供给的离线结果，不是P精度或TFRL收益。复用原生召回/排序/融合、锁定60张知识卡和封存向量，没有调用NPU、教师或重新计算embedding。

## 实验目的与设置

比较父配置每条供给8张卡、候选12/16张卡，以及tau从0提高到0.1。P输出候选意图仍最多3个；知识供给条数和输出候选数是两个参数。其余配置固定，先完成原生选择再关联原始标签。

使用原Fold A1080与原construction625内既有80条反馈，两者样本不重叠。80条原向量和音频摘要全部匹配；不创建新的开发集。固定CPU镜像、3个CPU worker、无网络/音频读取，4种配置×1160条=4640组，供给阶段36.79秒，续接后处理27.82秒，含失败尝试累计72.71秒（另有勘查验证开销）；不是NPU吞吐。24个首中尾锚点与原生供给函数逐项匹配，60卡正文匹配。

## 结果

12/16均没有移除父配置已供给的正确卡，但是否会增加模型混淆需真实P验证。tau0.1在两个名单上连供给顺序都未改变：父配置已入选最小得分分别0.286与0.336，均超过0.1。因此跳过本轮tau候选的NPU实验，保留其CPU零变化结果。

## 如何进入P轮次

优先12张，16张作为独立候选；分别与相同父版本和相同输入的实际P控制比较。供给变更必须生成对应新供给文件，复用其余不变资产。历史80供给集合仅31/80与本次父供给相同，不能把旧P回答直接当新控制。其历史15条失败中，本次8张供给覆盖11条，12和16张都覆盖12条；因此不能把16较12的全部覆盖增量解释成已知错例修复。

知识正文tokens由实际tokenizer测量，未含完整多模态请求、协议与音频，不能据此直接计算总时长或总费用。Fold A用于开发诊断，记录本次结果暴露；不称未见评估。TEST未参与。

下一步仍是P原父控制与声明单轴候选的真实推理，报告合法覆盖、候选集合召回、排序质量、改对/改错和成本。只有多轮重复收益成立才冻结P及真实输出，进入S。
