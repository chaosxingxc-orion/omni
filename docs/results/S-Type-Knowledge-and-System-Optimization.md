# S 节点槽位类型：知识保留核查与系统优化方案

## 结论与任务边界

当前只优化原音频输入下 Omni Instruct 的槽位类型识别。固定 P 候选，每个意图独立进入 S；不恢复 ASR＋文本模型填值级联。历史基线为 545 条样本、1635 个候选分支，其中学习区 476 条、隔离报告区 69 条。准确率以正确意图分支评测，不能把其他候选的结果当作有金标数据。

“值等于类型标签”“有类型但值缺失”“没有该类型”“模型不确定”是四种不同情况。字符串相等不是删除依据，值缺失也不能导致合法类型消失；有限词表之外的值不应使开放类型被裁掉。类型集合识别不能评价同类型出现次数，若将来关心实体数量，应另设实体级任务。

## 值等于标签名的核查结果

已核查真实 TRAIN 的 11,514 条语句及合成 TRAIN 的 19,711 条语句；合成部分没有相等命中。真实部分：精确相等命中 1 条，大小写、下划线与空白归一匹配没有新增命中。该原始记录仍在优化 mask、检索 bank 和合法示例候选中，也已进入另一条 TRAIN 数据线的学习分区。因此目前没有证据证明该记录曾因相等而删除。

但当前 1635 个请求实际选择的 3182 次示例未选中它，知识卡构建所选来源示例也未覆盖它。这里是“来源存在，但模型没有看到该类示范”，不能称为“已删后恢复”。已生成保留原始实体的知识支持记录、类型示例和配置 overlay，可用于 53 个同意图且无独立隔离冲突的候选分支。六项本地 CPU 回归测试通过，覆盖等值保留、null 区分、原标注与隔离保留、补充幂等和意图范围；尚未部署到运行实验，也未证明带来收益。原始标注、合法类型和独立质量/隔离限制保留，不以字符串相等判无效，不为了补示例改变固定评价集。

## 当前输入的实际薄弱点

对固定 476 条学习样本的真实输入逐条核验 packet 哈希，结果如下；脚本为 `audit_knowledge_supply.py`，汇总为 `KNOWLEDGE-SUPPLY-SYSTEM-AUDIT.json`。

| 检查项 | 结果 | 意义 |
|---|---:|---|
| 正确类型不在 allowed_types | 0 | 此学习区没有发现白名单直接阻断正确类型 |
| 每条平均允许类型 | 8.83 | 这是允许范围，不是实际应提取数量 |
| 每条示例 | 2 | 全部学习样本均已供给示例 |
| 正确类型未被示例全部覆盖 | 98/476 | 有知识卡不等于有合适的示范 |
| 漏提类型 | 87 | 52 个无对应类型示例，35 个有示例仍漏提 |
| 无类型样本缺少无类型示例 | 19/135 | 缺省与存在边界也需要示范 |
| 缺少类型示范的非空样本 exact | 35/98 | 关联统计，不是示例不足的因果证明 |
| 类型示范完整的非空样本 exact | 174/243 | 即使示范完整，也不是全部识别正确 |

当前动态检索确实存在：同意图内，以完整音频 query 对完整 TRAIN 句子的缓存向量相似度选择两例，去除同源重复。源码 `delivery/s-single-intent-fewshot-v1/code/retrieval.py` 中类型覆盖与边界覆盖仅在相似度完全相等时影响排序。因此第二条可能重复第一条的类型模式，而非补足判决边界。没有将全局 query 与短槽位标签直接做相似度匹配。

## 按系统部件拆解优化点

| 部件 | 当前问题或待验证假设 | 最小调整 | 验收重点 |
|---|---|---|---|
| TRAIN 来源及知识支持 | 合法泛指表达可能被误当无槽位；少见合法样本未进入模型视野 | 保留原实体与来源；值等标签不得过滤；为相关意图补充来源支持 | 是否保留合法类型，是否误加其他类型 |
| 意图—类型绑定 | 当前范围未漏金标，但允许不等于必填；有限示例不能变成值域约束 | 保留合法全集，分清可出现、实际出现、未确定；禁止根据本轮预测裁掉合法类型 | 类型覆盖不下降、空样本不被补齐 |
| 类型知识卡 | 数值格式、填值要求可能干扰类型判决；卡与例可能冲突 | 为类型任务投影“语义角色、出现条件、易混角色边界、来源正反例”；省略非必需填值格式，保原卡审计 | date/time/timeofday、person/place/news_topic 等混淆是否减少 |
| 相似问选择 | 相似度第一的两例不保证互补 | 保留一条相关锚点，从同意图相关候选池选一条边界或类型覆盖互补例；保持两例预算先验证 | 少示范组 FN 是否下降，完整示范组与空样本是否回退 |
| 示例标注组织 | 大量 filler、原句标注、类型答案同时出现，可能诱导背值或复制示例类型 | 模型视图突出 query→类型集合与必要角色证据；完整标注留在审计侧 | 原音频事实是否压过示例；类型复制 FP 是否下降 |
| before_model_call | 业务信息和来源追踪字段混杂 | 给模型稳定的意图范围、类型卡、示例、音频；审计标识保留在模型外；A 路已单独验证此投影 | 相同语义下精度、输入 token 和耗时，不能预设精度上升 |
| Instruct 判决 | 有示例仍漏提，说明供给不是全部原因 | 教师按错误类别提供角色识别、可选项存在性、完整性检查策略；保留非 thinking 基线 | 类型 exact、非空完整覆盖、逐类型 FN/FP |
| after_model_call | 去重或值校验可能误伤类型；未决不等于缺失 | 类型别名规范化、同类型去重、按原意图校验；不因无值/值等标签而删除类型；错误显式记录 | 原始输出与后处理差异、合法类型保留率 |
| 可选的两阶段类型判决 | 单次同时找类型和区分近邻可能困难，尚无证据证明拆分更好 | 仅在整类错误持续且知识/示例已修正时，试“候选类型→角色校验”；只用运行时证据路由 | 新增调用能否换来净收益，防止扩大串行成本 |

知识卡应先解决真实冲突，而不是添加更强硬的泛化业务约束。例如 TRAIN 的具体类型标注和卡的解释冲突时，要记录冲突来源并核实规则；不能仅凭模型答错就删除样本或认定标注错误。教师提出策略，不获得修改测试标签或凭空生成权威知识的权限。

## 相似问的可实现选择方案

候选仍从同意图 TRAIN 库按原音频相似度召回，禁止读当前 query 金标和离线转写来选例。第一例保持最高相关性；第二例在相关候选池中优化：

`J(e|E,q) = α·sim(q,e) + β·新增类型覆盖 + γ·边界模式覆盖 − δ·重复度`

新增类型覆盖来自候选自身 TRAIN 标注和已经选中的示例；边界模式来自合法 TRAIN 中的空/非空、角色近邻、泛指但有类型等模式。不能用当前样本的真实类型定义“缺哪个补哪个”。权重和候选池大小在固定学习区调节，隔离区仅报告。初轮保持两例，不把增加 token 当成默认答案；不足时再用一组有明确错误假设的增量实验。

## TFRL 学习对象与验收

冻结模型权重，分别优化知识卡投影、示例选择策略、类型判决指令；一次实验对应一项根因假设。ACE维护有来源的规则与冲突记忆；training-free GRPO采用同策略多次真实采样，分析哪些错误可由更好判决策略解决，不把不同实验臂当成同策略 rollout。

设金标类型集合为 T、预测为 T̂：集合 exact 为 `1[T̂=T]`，数量一致为 `1[|T̂|=|T|]`，另报“数量一致但类型错误”。报告 micro P/R/F1、宏平均类型表现、非空样本完整覆盖、无类型样本误提。不能让少输出、清空未决或多数空样本优势掩盖真实类型召回下降。

有类型无值的集合 Z 必须来自明确的原始标注或独立确认。未知值状态不能伪造为 null，也不能把所有类型都判为无值；当前只输出类型的实验可测 Z 中类型是否被供给，但不能宣称已经识别了无值状态。

优先顺序：合法数据保留核查与来源补充 → 同预算互补示例 → 冲突类型卡的局部修正 → 教师的角色判决策略 → 证据支持后才考虑额外模型节点。评价保留历史固定分母；若确实恢复数据，另列新版本及前后分母，不覆盖旧结果。
