# S节点槽位覆盖与多类型槽值审查

## 结论

测试集53种槽位类型在训练集55种类型中全部出现；没有需要靠扩充训练集补齐的全新类型。存在意图—类型组合覆盖不足、局部漏标、同词不同角色和明确误标，必须分别处理。当前知识定义/卡片缺music_album，但原训练集5056已有该类型，属于知识库存遗漏，不是缺训练数据。

## 统计口径

原始TRAIN为11,514句/50,628份录音，TEST为2,974句/13,078份录音。主统计按独立slurp_id；实体出现次数与录音数分开，不把重复录音当独立语义证据。当前清洗版本clean-v6训练11,462句/50,391录音，测试2,950句/12,994录音。

意图统一为scenario + action。原始intent有训练162行、测试37行与此不一致，多数仅写action。此前27个训练未见意图—类型组合更正为26个：email_addcontact::list_name实际在TRAIN16621出现，旧统计漏计。测试7353的intent和scenario/action还存在实质冲突，已在历史清单删除。

槽值按token ID读取entity span，NFKC、casefold、空白归一化；保留标点，不把相关词自动视为同义。原数据、代码及SHA均留存。此轮是文本标注审查，没有音频听审和新模型调用。

## 根因与S节点设计含义

1. **合理的角色变化**：pink可为歌手、颜色或人物；chicken在cooking_recipe中可指待烹饪食物或配料。同意图也未必唯一确定角色。知识卡应给角色判据和对照例，而不是一个词唯一映射一个类型。
2. **边界定义冲突**：weekly在weather_query中分别标date/general_frequency；every monday在calendar_set中也跨两类。需明确单次日期与重复频率的判据，再审查各完整句子；不通过扩大候选数消解标注冲突。
3. **明确误标**：clear标time、disco在音乐喜好句中标place_name，不能当模型能力问题训练。
4. **覆盖不足**：如cooking_recipe中device_type、timeofday等训练未见组合，不等于非法组合。先审任务语义，再使用独立训练来源补上下文覆盖，禁止直接复制测试句作few-shot。
5. **知识库存遗漏**：music_album原训练1例却未进54类型卡片，需要修库存，不需要制造新类型。

建议顺序：先清理确认误标和知识库存遗漏；再审607句漏标候选中的强证据子类及48个同意图多类型值；随后补充确实缺少的角色对照训练例。S应判断“该表达在此句承担何种角色”，意图提供上下文先验；训练未见组合不能直接当负例或硬屏蔽。
