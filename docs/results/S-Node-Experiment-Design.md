# P冻结与S节点实验方案

## 执行次序

P独立子进程负责教师策略与实验反馈循环；CPU准备和NPU执行异步。S不等待P最终冻结才准备，现有P版本可用于明确标记的摸底。只有最终P验收锁定后，才能生成正式S优化清单。不同P或数据版本之间不直接将差值归因于S。

## 数据锁定

沿用原TRAIN、R01C-fit、Fold A、Fold B、TEST身份。P版本绑定模型、知识库、召回配置、prompt、thinking、输出TopK和rails。先应用确认质量排除，再筛P最终Top3正确的样本，验证正确意图合法卡能够传递到S。P错误移出S优化，保留在端到端评估。所有候选保序、保内容，不使用gold缩减或重排候选。

分母分区：原始N＝质量排除Q＋其余；其余＝P错误/无有效响应F＋P正确但handoff未验证H＋S可用E，各部分互斥。待采集P响应独立标为pending，不伪称P失败。样本槽位gold单独存评分文件，不进入runtime。质量清理前后计数及算法变化分开报告。

## 知识卡锁定

复用现存意图槽位关系、槽位定义、值规范化与合法TRAIN例句，逐来源绑定hash；共同槽位可去重但不得丢失意图归属。只提供候选允许的信息，不能用gold slots选择卡片。知识缺失或映射不明是供给问题，记录修复，不能删除样本掩盖。

## S基线与验收

固定P输出与原音频、知识卡版本、S thinking ON配置。先确认现有runner可直接运行，输入准备和预算在占用NPU前完成。记录每条response、slot原值与规范化值、候选归属、协议状态、tokens和HTTP耗时。初始运行不同时改提示、召回、schema。

slot评分明确多值、重复、空值、大小写及时间规范化规则，使用原数据集指标实现；报告micro/macro precision、recall、F1、整条槽位完全正确率和合法输出率。条件指标以固定S清单为分母，另报原始端到端完整分母。对错例逐条区分听辨、漏提、多提、槽位归属、值规范化、时间/否定关系、知识供给与程序协议错误。

## 学习与验证

TRAIN内优先S失败或不稳定样本，保留按原slot类型/意图覆盖的回归样本，不造笛卡尔组合。教师收到聚合根因与代表轨迹，要求可执行策略和反证。一次验证一个机制，开发验证锁定收益后再固定TEST评估；TEST不反向调优。没有真实TRAIN P轨迹时先排采集任务，不把开发集改名成训练集。

## 首轮结果怎样使用

1. 首轮只改执行阶段，不同时改知识卡、P结果、S提示词和thinking。先得到545条真实结果与每条耗时/tokens，再谈S精度。
2. 输出合法率、响应覆盖率、精确type+filler micro/macro F1、全槽正确率，以及原官方SLU指标。精确匹配诊断不能冒充官方SLU。保留协议失败和知识供给缺口。
3. 逐错例核对原音频/参考文本、全部P候选、卡片供给、原响应、rails解析结果和gold，区分知识缺口、听辨、候选归属、漏提/多提、值表达、时间/否定、程序错误；不能只看总分。
4. 教师仅基于fit/合法TRAIN提出根因策略，每轮锁定P和卡版本，只改变一个有证据的机制。FoldA/B作冻结回归，不反馈教师或据此反复调参；若发现需学习的新信息，另从TRAIN建立证据。
5. 候选与基线用同一清单配对，报告修复数/回退数及低频槽位，S条件收益与P筛选造成的分母变化分开。最终P改变时重建正式S清单，旧provisional结果保留但不混算。
