# S节点：槽位类型识别与槽值填充分离
当前方向：用户已停止ASR＋文本模型槽值级联，三个实例统一探索Omni槽位类型。参见 [S-Type-Three-Instance-Plan](S-Type-Three-Instance-Plan)。下文保留分析与阶段记录；旧文本执行计划不再生效。


当前方向将S拆成两个可独立评测的任务。类型识别采用Qwen3-Omni Instruct：输入原音频、冻结P的单个候选意图及锁定知识，输出当前语音实际表达的槽位类型，不填值、不依赖ASR或槽值工具。槽值填充采用用户指定Qwen3.8-27B：输入真实ASR文本、候选意图、类型及知识。ASR是并行证据支路，不是类型节点前置，也不是权威标注。

## 数据与评测

复用原545样本、1635候选分支；476开发、69隔离。旧Instruct结果先投影为类型集合，形成历史参照；新类型任务报告类型P/R/F1、集合exact、完整类型覆盖率、空槽误报与协议有效率。只有正确意图分支有相应gold，不把竞争候选当已标注负样本。

槽值填充分两步：真实类型条件的诊断实验，明确标记oracle；预测类型条件的实际级联实验，保留上游漏类型造成的损失。两者均使用真实ASR缓存，不用参考转写或gold值替代证据。重复同类型实体由填值节点处理。类型集合正确不等于槽值正确。

## 当前执行状态

三个Codex CLI子进程分别准备并执行类型专用实验、文本填值诊断，以及后继类型TFRL模板与反馈。历史分解已完成，详见 [S-Type-Value-Error-Decomposition](S-Type-Value-Error-Decomposition)。权重目录已只读确认存在；官方Qwen3.8-27B也使用Qwen3_5ForConditionalGeneration架构名，本地服务兼容性尚待验证。官方部署说明见 https://docs.vllm.ai/projects/ascend/en/latest/tutorials/models/Qwen3.8-27B.html 。

旧整槽位指令候选已在发请求前停止准入，新增请求0。新类型及填值实验尚无结果，不能宣称NPU满载或收益成立。先保留可用Omni服务准备类型实验，文本部署不阻塞类型实验。旧教师请求尚未派发，后继教师目标改为类型混淆或填值根因分别优化。

## 已有证据与边界

完整545上，纯音频Instruct槽位F1为51.84%、exact247；直接追加ASR后F1为52.96%、exact235。追加文本改善部分召回，也增加误提，不能自动晋级。文本模型是否更适合填值仍需实证；ASR漏词与同音歧义也不会因换模型自然消失。D继续负责最终意图及跨候选裁决，不把类型列表伪装成完整槽位答案。
