# S单意图条件提取与示例增强对照

## 目的与证据

用户提出：多意图共用槽位知识可能引起相似类型混淆，S应每次只处理一个意图及其槽位，分别产生假说供D选择。当前代码确实把P三个候选关联知识合并，使用全局槽位类型枚举；卡片正文还可能携带其他意图绑定。这支持进行意图作用域隔离，但尚不能证明全部重复、误提由此造成。已有15条排除大小写后的分支不对称只能提示问题，不能直接搬运预测修复。

## 固定对照

原多意图S基线保持：545条、118条全槽正确、严格F1 29.16%、官方条件槽位F1 56.89%。不使用已否决的nonempty候选作为新起点。

|方案|输入和作用域|验证目的|

## 示例选择与知识消费

示例使用真实训练完整句及其原始槽位标注，展示类型、边界和上下文角色。每候选意图最多两条，优先覆盖容易混淆的类型、跨度、否定、重复提及或无槽位边界。知识事实来自锁定库，模型不得临时生成知识。排除已有质量清单、开发/测试及当前样本同源录音与别名；不使用评估query标准转写或gold挑例子。

相似问增强采用完整query对完整例句的可用表示，复用既有向量与索引，不用全局query直接匹配孤立槽位值。如果缺少可用检索表示，只能明确报告为意图内固定代表例证，不能冒称动态相似问增强。缺合法示例时保留缺口，不合成填充。

few-shot可能帮助辨别，也可能诱发复制示例值、补出未提及槽位。模型必须从当前音频提取实体；示例只示范方法，不能作为当前样本事实。实验分别检查误提、漏提、类型混淆和合法重复提及，不预设示例必然增益。
