# S 节点的信息顺序、槽位知识供给与意图边界

## 核心结论

当前请求已经是“一个候选意图＋该意图的允许槽位类型”，并非把三个意图的槽位合并给模型。硬边界能够防止通过校验的输出落入其他意图的独有槽位；它不能保证模型只选择本句实际表达的类型。主要问题是意图内的存在性、语义角色与类型边界判决。知识正文的意图局部化仍不完整。

## 当前真实输入与顺序

对冻结1635请求逐个核packet hash：system为类型任务指令；user为音频→该意图槽位卡→同意图TRAIN示例→重复任务指令及pipeline上下文。1591分支有示例，44分支无合法示例；全部1635尾部重复system指令。输出schema绑定唯一candidate_id和该意图allowed_types。

顺序可能影响多模态融合、近期信息权重、示例复制及输出约束的保持，但这些是待证机制。不能只凭“先给知识再听音频更自然”决定顺序，更不能同时移动音频、改知识、删指令后将变化全归顺序。模板会将多模态占位符展开；API数组顺序检查还需真实模板/token位置验证。

历史P顺序实验有实际反证，同轮622样本/臂：

|user顺序|Top3正确|相对音频先|
|---|---:|---:|
|音频→知识→指令|542/622（87.14%）|基准|
|知识→音频→指令|526/622（84.57%）|−16|
|知识→指令→音频|508/622（81.67%）|−34|

该实验不是当前Instruct S类型任务，不能外推S最优顺序。S现已有元数据投影退化和完全同wire输出波动，说明内容布局/推理随机性均不可忽略；也不能据此认定某个哈希本身有语义价值。

已给A子进程一个纯顺序任务：原type-only父，仅把user音频块移至最后；其他块内容、相对次序、system、重复指令、卡、示例、schema和推理配置不变。先反向排列恢复原wire和固定模板位置验证，再在固定545/1635上真实回归。此任务目前是已授权准备，不是已完成结果；不继承A退化的时间卡。

## 是否还需要槽位类型知识库和召回

已经有知识库：54类槽位、60意图、402个有合格TRAIN支持的意图—槽位关系。当前每次按意图键取出全部绑定类型卡，而非全局语音query对短槽位名做向量topK。每意图1–16种类型；476学习样本加权平均8.83种。现545正确意图分支金标类型均在其允许范围内。

应优化已有知识库的组织和消费，暂不增加会裁掉合法类型的全局向量检索阶段：

1. 以(intent_id, slot_type)为键，供给当前意图下的角色定义、存在条件、相邻类型对照和原TRAIN支持。全局类型说明可以复用，但不得把别的意图角色当作当前指令。
2. 对一个意图的全部类型先提供简明索引。更详细的来源例子可按相关性和角色互补选择；召回决定详细信息多少或顺序，不直接决定类型是否合法。
3. 示例召回继续“完整音频query→同意图完整TRAIN语句”，按源标注提取类型证据。不能将全局query直接与person/time等短标签相似度比较后硬截断。
4. 如果以后真实预算或类型规模要求类型预筛选，先独立评价真实类型集合覆盖率、平均候选量、漏类型样本和最终S净收益；当前1–16类型不值得未经证据增加一道硬召回漏失风险。

知识库应有来源、版本、意图角色、正例/相邻反例、可选/缺省含义和争议标记。不能把未标注一律当明确负例，也不能为纠正开发错例制造知识。来源隔离后的402关系是观察支持关系，不等于官方穷尽本体。

## 为什么单意图输入仍会误提

设当前候选意图为i，允许类型集合L(i)，本句真实类型集合T(x,i)，预测为T̂(x,i)。系统能约束：

`T̂(x,i) ⊆ L(i)`

真正业务目标是：

`T̂(x,i) = T(x,i)`

前一个约束不能推出后一个。audio_volume_down允许change_amount，但“turn down the volume”未必表达数量，不能因为意图允许就补数量。同一类型person、date可以合法属于多个意图，但角色不同。当前类型任务不输出槽值，所以更准确地说是误提类型，尚不是值填错。

原父545中543个有效结果的201个FP，全在当前意图允许集合内，accepted越界为0；2个协议失败单列，没有当作无越界有效输出。A、B的有效结果也未越界（各204、203个FP均在允许范围）。1635输入异意图卡ID、显式绑定、示例、示例类型越界均为0。

但是卡正文仅裁剪intent_bindings，其他段落仍全局。例如cooking_recipe的food_type卡仍写菜系修饰restaurant、restaurant归business_type；而cooking_recipe允许集合没有business_type。这种正文不一致可能干扰判决，即使输出枚举能阻止越界。402卡中203卡含当前意图范围外类型词，程序扫描只能提示人工语义审查：其中有些是合理的排除对照，不能直接删掉全部词句。

还有P候选错误的情况：三个候选分别进入S，各自只在自身范围内解释音频；错误候选也可能产生合法但不适用的类型。必须保留candidate_id关联，D选择意图后消费该分支，不能把三分支槽位取并集。当前准确率只在正确意图分支评估，未把其他候选结果伪造成有金标错误。
