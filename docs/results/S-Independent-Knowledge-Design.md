# S节点：独立于意图的知识构建与知识消费

## 已确定的责任边界

用户明确：S独立于意图，负责语音中的槽位类型标注与候选值填充。S不接收P意图排名，不通过意图过滤槽位卡、示例或输出。P和S可在逻辑上并行，D负责结合意图与槽位之间的关系作最终采纳和组装。D可以尝试自行补充，但净收益需在相同P/S输入条件下对比验证，包含纠错收益和新增错误。当前全部实验暂停，后台开发、派发及分析子进程已退出，不自动重启。

## 知识构建建议（待讨论，不视为实施批准）

建立以全局槽位类型为主键的知识卡。每张卡包含：原任务定义、语音中支持该类型的证据、容易混淆的类型及区分条件、候选值填充规范、未知值处理。区分封闭词表、开放实体、数值时间等知识，但暂不引入ASR级联或新工具。

将跨类型对比知识独立组织：相同词面在不同句内语义角色下的差别，以及语音本身无法消歧时应保留的候选。不能以历史意图共现频率替代任务定义；句内上下文仍是必要证据。不存在信息时不强行唯一归类，也不输出所有可能类型。

示例来自清洗且冻结的训练数据，保留完整语境及标注出处，以槽位类型、语义角色、混淆关系组织。包括同词异类、同类异词、多提及、无槽位、有类型无值。检索示例只是参考，不是值复制来源；测试数据不进入知识库。多类型值本身不能判为标注错误。

## 知识消费建议

before_model_call固定提供完整但简短的槽位类型目录与基本规则，详细卡和few-shot可按语义证据增补。召回未命中不等于该槽位不允许输出。先把全目录方案作为可解释参照，若上下文过长才引入动态供给，并独立测知识供给覆盖率。

全句语音与槽位片段卡不可直接假定向量相似度可比。若使用检索，应以完整训练问句作为入口，再关联槽位卡和对比示例；去重、类别集中度约束及示例覆盖由程序完成，不依据P输出过滤。

模型输出候选类型与值，保留多提及；类型有证据而值无法确认时用null。歧义候选可共享同一提及身份，具体字段待接口讨论；不得要求未经过对齐的精确语音时间戳。

after_model_call负责解析、类型别名映射、约定的值归一化及确切重复清理；不能删除真实重复提及，不按意图筛选，不把歧义裁成单解，不把格式可修复错误变成弃答。

## 后续验证边界

S单独报告类型覆盖、类型候选负担、值准确率与候选覆盖、无槽位误报、有类型无值保留情况、各类型及混淆对表现。允许歧义不代表扩大输出就算提高能力，覆盖必须与候选负担同时观察。

旧P@3成功筛选集可用于历史可比分析，但不能代表新独立S的总体表现；将来应使用冻结且清洗的原始划分评测，单列P成功/失败分层。当前不重新制作或运行数据集。
