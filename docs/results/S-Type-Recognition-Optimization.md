# S Instruct槽位类型优化

主线程聚焦类型识别；文本槽值模型由独立Codex CLI推进。类型识别输入为原音频、单个P候选意图及锁定知识，输出实际表达的类型集合，不承担槽值拼写、数字归一化或转写。

## 已核证据

历史完整抽取任务投影到类型后，学习476中291条类型集合正确、185条错误：114条只漏类型，44条只多报，27条兼有漏报和多报。这是历史参照，不是新类型专用任务的结果。主检查了实际供给的知识卡、示例与离线参考文本，未据此宣称已听清原音频。

- 知识已齐仍漏：日历表达this year、媒介audiobooks都有相应定义和近似训练示例。优先检验类型存在判断是否仍被精确填值要求干扰，不直接追加更多知识。
- 定义/标注边界冲突：天气时间跨度在参考与实际训练示例中分别标作date和time。应审计训练来源与角色定义，不能按数字差异硬编码标签或为提高分数删样本。
- 同词不同角色：新闻主题中的国家名和事件发生地点不能共享固定词到类型映射。示例需要展示关系，不能仅按词相似度决定类型。
- 事件与容器角色覆盖：提醒目的行为短语、列表名称需按意图中的语义角色判断，不能只认典型名词或固定词形。

## 优化顺序

先完整跑类型专用基线。后续优先验证一项任务级策略：允许“类型已知、值暂不确定”，检查所有实际表达的合法类型；缺省不是未决，意图允许不是实际存在。然后按错例证据做类型知识视图：保留角色定义、正反边界和合法示例，把拼写、大小写、数字格式与span限制移交槽值阶段。知识内容改动另列候选，不把编写新业务规则与消费策略混为一谈。few-shot按角色边界与槽型组合选择，先从合法TRAIN检索，不使用开发答案构造知识。

评测同时报告类型P/R/F1、完整类型覆盖率、集合exact、空槽误报与未决比例；集合正确和无未决的集合正确分开。不用“返回全部合法类型”换取召回，也不把协议失败当空槽。

## 当前类型实验

原545样本、1635候选分支、476学习/69隔离不变。A实例TP4、并发64、输出512，Instruct官方模板，无ASR与Tools。首尝试因引擎不支持uniqueItems在生成前HTTP400；已保留记录，移除不兼容约束、保留程序唯一性检查后接续。新尝试容器实际running，首个真实类型JSON通过，完整指标未出。

首响应正确确认time_zone，但把其他允许类型全部放入unresolved，提示“未出现”与“无法确定”可能混淆。单例不能判定普遍性；现有基线保持不变，完整统计此模式后再设计后继策略。协议成功不能冒充类型判断成功。
