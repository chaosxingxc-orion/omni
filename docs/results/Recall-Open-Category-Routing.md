# 开放域事实问答、闲聊与业务others的区分

原始TRAIN标注核验：8条至少一条正确路线cosine<0.01的样本全部为qa_factoid，包含人物参演时长、人物身高、最长河流、国家地理意义、美国首任总统。不是general_quirky或audio_volume_other；不能为了简化路由更改原标签。只有1条所有正确供给路径<0.01，其余有较强相似问路线。

## 三种不同语义

|类型|当前标签示例|应判断的信息|
|---|---|---|
|开放域事实问答|qa_factoid|请求确定事实，人物/地点/事物/事件主题可很分散|
|开放对话|general_quirky|聊天、意见、感想等，仍需按原业务边界核验|
|域内剩余类别|audio_volume_other|先确认音量业务，再判断请求未落入明确升/降/静音等动作|

当前60类库中只有audio_volume_other名称含other，并无一个可直接把所有低分样本装进去的全局others标签。上述自然语言边界来自当前锁定的TRAIN派生知识卡，是解释材料，不冒称已查到官方穷尽定义；原始样本gold已独立核。

## 系统性问题

向量相似问通常同时反映话题、实体和请求形式。某演员参演时长与城市海拔的主题不同，仍可同属事实问答。以具体话题近邻作为类别供给的必要条件，对qa_factoid这类广泛主题类别可能低效；“类别内必须所有问题语义高内聚”的要求也不适用于其原始定义。域内others还具有排除其他子类后的逻辑边界，并非一个天然的单一向量中心。

当前采用P常设卡：模型基于锁定业务定义判断请求类型、比较相邻意图，不以话题近邻命中作为这两类的准入条件。但不能用“所有近邻低分”直接推出others/闲聊，因为低分也可能来自语音表征、缺少知识代表或数据错误。原语义明确样本仍属于系统需处理的有效任务，不能按主题开放而清理掉。

## 数据集验证范围

先验证动态召回池移除两类、P常设卡供给及小规模P识别效果，不同时引入阈值或D恢复实验。P需判断原任务意图，不需要回答事实问题本身，也不需要生成新的意图定义。

两张卡由配置引用冻结内容，在P调用前固定注入；不按query相似度决定是否注入，也不为这两张卡逐query召回相似问例句。其他动态类别仍使用既有召回与few-shot规则。P继续输出候选索引，后处理rails映射回锁定标签和知识卡，供后续节点使用。两类不是低置信样本的默认归宿。

## 召回供给的信息差异

实际P输入中，动态类别除锁定知识卡外还有每类一条query相关、来源合法的TRAIN例句，以及候选集合和展示顺序。数值cosine、来源ID、逐例槽位标注并未直接送入P。固定两卡版保留了相同定义，却删除两类的例句，其他类别仍有fs1，形成判别证据不对称。
