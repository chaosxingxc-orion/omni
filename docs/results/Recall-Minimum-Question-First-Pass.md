## 当前决策：先最小种子，再增量回补

4451、724、143均是历史候选，不是不可删除的核心，也不是已证明的最小集。当前143条来自731条的删减和一次真实TRAIN回补，仍保护已有开发命中，因此不能回答“先删到最小，再根据错误增长”的问题。后继已由Codex工程子进程实际执行；种子已缩至59条，首轮回补至65条，后继已排队。

1. **最小种子阶段**：仅保留有真实TRAIN支持的类别及来源隔离后的必要可用性，不硬保全部槽型签名或当前命中集合。逐步删除到条件约束下不可继续单点删除，给出每个剩余代表的必要性证据；有可证明下界时报告下界。局部不可删不等于全局最小。
2. **增量回补阶段**：冻结种子，以既有开发集错例从真实TRAIN支持池提出少量候选。按修复、回退和类别竞争逐条评价；加入后再检查被替代的旧代表是否可删。保留所有中间版本与接受/拒绝原因。
3. **评价与停止**：沿用固定Q15/Q50及描述D5，报告逐例修退、每类覆盖和去重标签数量。小库下Top50接近遍历不能当作排序达标；Q50饱和后优先处理Q15错误。不靠增大K宣布成功，预算停止不等于最优。

候选全部来自真实训练数据；开发样本及同源别名不得入库，不合成问题。三个既有开发分组都参与适应性选择，TEST未用。删库期间的召回损失公开记录，最终回补候选与原8554、4451、143比较；知识供给覆盖不是P最终Top3指标。
