## 主线程负责多轮对抗分析与基线集成

每个子进程交完整报告、配置差异、来源证据、类别修复/回退、成本、组合约束和回滚配置。报告不完整退回原进程补齐，不由主线程默默代做。当前三路科学父保持一致，运行中输入不可变。

主线程按四轮分析推进：

1. **证据有效性**：分母、金标分支、模型配置和父版本可比；失败不能伪装为空；无查询答案/隔离数据泄漏。
2. **根因与反证**：按类别检查修复是否支持原假设，在哪些反例退化；区分知识不足、知识冲突和判决错误，避免只看总分。
3. **跨路组合审查**：检查新卡、示例和提示词是否互相矛盾，接口和预算是否兼容。只合并有证据且兼容的改动，不要求三路全部保留，不按排列组合穷举。
4. **组合实测**：新方案在固定545/1635上真实回归，与父和单路结果配对；476学习区选策略，69仅报告。类型exact、非空覆盖、空样本误提和逐类型回退一起判断，不能用省tokens抵消精度损失。

组合收益不会从各路分数相加推断。若两项单独有效但组合退化，先分析交互、回退冲突项；如需运行时条件路由，只用输入可观测信息，禁止用样本ID或真实标签挑赢家。

组合方案通过后发布版本化基线清单，锁定模型、镜像/引擎、数据、知识卡、检索、提示词、schema、rails、评分器、证据及回滚入口。随后把新版本、已接受/否决策略及原因、剩余错误类别、下一轮独立假设和实例分配发给各子进程。三路下一轮必须绑定同一新基线，历史输入和结果保持可追溯。

这一集成过程由主线程负责；三路CPU准备和NPU执行异步继续。当前没有新组合基线被晋级，也没有凭子进程启动就宣称NPU满载。
