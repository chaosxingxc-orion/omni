当前用户决定停止ASR＋文本模型槽值级联探索，三个实例统一用于Omni Instruct槽位类型提取。文本子进程已停止，文本模型尚未部署、没有新增槽值推理。现有准备文件和历史结果保留，不继续投入该路线。

|实例|实验目的|配置/状态|
|---|---|---|
|A|类型专用基线|Omni Instruct，TP4，并发64，输出512；已完成545条、1635分支；评分完成|
|B|区分类型存在、缺省与未决；不因无法精确填值漏掉类型|保留现有Instruct服务；已实际启动，首个真实schema通过|
|C|检验槽值格式约束是否干扰类型识别|Instruct服务已ready；实验已实际启动，首个真实类型schema通过|

三路共享原545样本、1635候选分支与476学习/69隔离划分。B只追加任务指令；C只对锁定知识卡生成类型视图，去除明确的槽值格式章节，保留可能影响类型判别的语义例外。原知识库不重写，不把缺省类型补成存在，不输出槽值。A结果无需重跑，最终配对评分等其终态；B/C准备与A异步执行。

原部分类型结果1034个分支中，892个把所有未选合法类型都放入未决；学习正确意图297个观测中268个出现此模式。它提示输出语义可能混淆，尚非完整精度结论。后继同时评价类型P/R/F1、非空样本完整类型覆盖、集合exact、无未决exact、空槽误报、协议有效率、原正确回退及成本。减少未决本身不等于精度提升。

CPU继续准备类型任务的ACE与TFGRPO反馈，教师研究对象限定类型判别。真实GRPO组需要同样本、同策略多rollout；有gold的正确意图分支可作节点学习条件，其余候选保留在完整回归中，不为没有可靠奖励的分支盲目增加采样。
