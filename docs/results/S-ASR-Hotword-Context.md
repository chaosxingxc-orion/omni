# Qwen3-ASR槽位热词上下文实验

## 判断与依据

现有官方SDK的`_build_messages(context, audio)`将context放入system、音频放入user；本地官方源码448–452行已核。可以用业务热词做上下文偏置，但不等于硬词表约束，也不保证提高槽位准确率。

热词应是可能听到的词/短语/实体别名，例如业务设备、动作、单位和知识库内真实名称，而非person/date等抽象槽位ID。May自身作为热词不能解决人名/月名/作品多义；意图与句子上下文仍需下游判定。普通数字不应凭预期值强化，真实数值仍须来自音频。

## 首轮单项候选

从每样本锁定P top3关联的合法知识来源提取热词，按来源和重复规则合并，供该音频一次ASR；不按三个候选分别转写，以免错误意图驱动出互相矛盾的文本。若P遗漏正确意图，应统计偏置失配影响，不能用金标替换P。

固定context格式由配置给出，当前候选为 `Hotwords: {phrases}`，动态热词由脚本插入；ASR仍只负责转写。先设置最多32个短语、256个上下文文本tokens作为有限实验预算，不宣称最优；实际有多少合法有用词就供多少。不放整张知识卡、few-shot全文或S槽位JSON任务。每词保留训练/知识来源，排序去重确定化。

严禁使用当前query参考文本、金标槽值或测试错例答案生成热词。真实开放实体别名可作偏置，但未被知识库收录的名字仍可正常转写，不能强制映射至已知项。数值时间与短语语义的处理仍由后继S和工具完成。

## 配对验证

沿用原545音频和476学习/69隔离，无热词545真实转写缓存已经完成，作为对照；新热词臂只改变system context，ASR权重、模板、音频、语言模式和解码不变。新缓存身份包含实际context及生成策略版本，不能覆盖无热词缓存。

先看分组WER和关键实体保真、遗漏/替换、热词无依据插入；WER须披露数字写法差异。判断是否锁定最终以同一Omni OFF系统的槽位F1/exact/修退为准，不以热词命中率或单例转写看似正确为准。隔离69仅汇报，不用于词表或预算选择。

## 关键反证与验收

热词偏置可能把原本正确的声音误识别成词表中的词，因此必须统计修复与回退，特别关注未被词表覆盖的开放实体。初版按训练支持频率选词，可能漏掉罕见专名；英文且无数字的词形过滤也可能漏掉产品型号。这些是首轮候选的限制，尚未证明应该采用更复杂策略。

区分原S、无热词ASR辅助S、热词ASR辅助S；后两者才能隔离热词收益。除转写指标外，最终汇报S的precision、recall、F1与exact，避免将减少过提但增加漏提误报成全面提升。

## 执行顺序

CPU热词生成与来源核查独立进行。B先运行已经准备的无热词ASR辅助S对照；不为了新增候选反复切换模型而打断当前实验。热词输入准备好后再安排ASR批次，与后续S消费形成可复现对照。当前仅确认接口可用，未取得热词收益结果。
